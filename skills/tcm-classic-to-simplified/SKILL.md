# 从中医古籍 → 简体中文中医著作（生成流水线）

> 实战沉淀：`tcmP` 仓库（`C:\Users\DELL\tcmP`）把《病源辭典》（吴克潜主编，1179 页竖排繁体扫描件）
> 做成 16 开双栏横排 · 简体 · 5 号仿宋 · 词条按首字笔画升序 0001– × 1831 条 · 含目录/索引页码校验 的 docx/PDF。
> 本技能即该项目的可复用封装。**首次使用先读本文件全文 + `references/`。**

## 触发条件（命中即加载本技能）

- 用户给出**中医古籍/民国医书扫描 PDF**，要求「识别 → 繁简 → 重排 → 编排 → 校验 → 索引 → 交付」
- 提到：中医古籍、简体中医著作、繁体竖排、病源辞典、黄帝内经、伤寒论、词条笔画排序、16开双栏仿宋、主题词索引替代原著索引、ICD-11 术语统一、病证单元、逐段上下文重构
- 需要按**笔画/部首**给中医词条排序编号，或做**中医古籍 LLM 级版本升级（V2/V3/V4…）**

## 二、⚠️ 环境铁律（违反必踩坑）

1. **Anaconda python 的 sqlite3 段错误**（进程 exit `3221225477` = `0xC0000005`）。凡涉 SQLite（ICD db、平台 KG）**必须换 python**。
2. **别污染 Hermes 自己的 venv**：给平台/流水线装依赖要**建独立 venv**（本项目用 `.venv-api`，由 py3.11 基底创建，隔离 site-packages）。若误装降级了 Hermes venv 的 pydantic/starlette，务必回滚（`pydantic==2.2.1` + `starlette>=0.49.1`）并卸载误装的 fastapi/uvicorn/h11。
3. **pytest 挂起**：本机 anyio 3.5.0 的 pytest11 插件加载即挂起 → `pytest.ini` 固定 `addopts = -q -p no:anyio`；`PYTEST_DISABLE_PLUGIN_AUTOLOAD` 不跨调用持久，须内联。
4. **Windows 文件锁**：docx/PDF 落盘可能被索引/预览瞬时占用 → **写临时文件 + `os.replace` 带重试**（见 `s11_docx.py`）。
5. **Word COM**：PAGEREF 域须 `Repaginate()` → 逐域 `Update()` → 再 `Repaginate()` 才能得到真实页码；**校验时只 `Repaginate()` 不要 `Update()`**（未分页状态重算会写坏页码）。
   - ⚠️ **别逐书签查页码**：1831 书签 × 2 次 COM 调用会触发 `RPC_E_CALL_REJECTED`（被呼叫方拒绝接收呼叫），异常被吞后表现为"大量书签查不到"。
     稳健做法（S12 v2）：Word COM **只做「打开 + Repaginate + 导出 PDF」**，再用 **pymupdf 在导出 PDF 里定位词条实际页** 与 docx 域值比对（快且独立）。
   - ⚠️ **域解析要兼容两种形态**：初稿是 `<w:fldSimple w:instr=" PAGEREF e0001 \h ">`；**Word 更新后会重写成 `fldChar begin → instrText(可能被拆成多段) → separate → 结果 → end`**。只用 fldSimple 正则会读到 0 个域 → 用**域状态机**扫描。
   - ⚠️ **校验脚本必须防"假通过"**：① COM 异常要记为**失败检查项**而非 `except: pass`；② 条数类断言要加**下界**（`len(terms_bm) >= 1800`），否则域读到 0 个也会因"错 0 条"而 PASS。
   - 拉丁字母+CJK 混排词目（如 `L阳`）在 PDF 提取时**中间会插空格** → 比对前去掉所有空白并用 `startswith`。
6. **字体**：仿宋 = `C:\Windows\Fonts\simfang.ttf`，5 号 = **10.5pt**；16 开 = **196.75×273mm**。

## 三、OCR 变体（本领域最关键的知识）

扫描件把**三要素标记**系统性地错识，必须按变体集归一（频率扫描 + 上下文实证得到）：

- **病源** ← 病愿 / 满源 / 润源 / 游源 / 漏源 / 瑞源 / 烤源 / 浏源 / 消源 / 荆源
- **病状** ← 病默 / 病送 / 病肤 / 病选 / 病迭 / 病达 / 病跋 / 病然
- **治法** ← 洛法 / 活法 / 浩法 / 照法 / 浴法 / 跆法 / 沼法 / 陪法 / 邵法 / 路法 / 阁法

正则（S14/S15 同款）：
```python
SRC_RE = r'[病满润游漏瑞烤浏消荆房痛]源'
ZH_RE  = r'病[状默送肤选迭达跋然]'
ZHI_RE = r'[治洛活浩照浴跆沼陪邵路阁]法'
```
> 补齐变体前「病状」覆盖仅 34%；补齐后 58%，「治疗」60%→77%，三要素齐备 27%→53%。

## 四、两档校验（**务必分清**）

| 档 | 场景 | 判据 |
|---|---|---|
| **保字档**（标点/字形矫正） | 只加标点或单字替换 | 去标点后**逐字恒等** |
| **重构档**（上下文重构） | 允许改写误识以通顺 | 长度比∈[0.70,1.30] **且** 字集重合≥0.50 **且** 三要素标记保真 |
| **补缺档**（补缺/完善，允许加字） | 补回丢失的结构标记、修残句 | 长度比∈[**0.75,1.45**] 且 重合≥0.55 且 **标记覆盖不得下降**（源有则输出必有） |
| **合并防跑偏**（LLM 批产物） | 防子代理另写一篇 | 长度比∈[0.85,1.15] 且重合≥0.85，否则回退 |

> **补缺(refill)专项**：先出「缺项画像」做基线（标记覆盖率 / 无治疗特征词条数 / 过短条数），
> 派活时明令「**能辨认出对应语义就补回标记；无法辨认不得凭空加整段**」+「**不得删减原文**（输出不得短于原文）」。
> 实测：1831 条中 **106 条补回缺失标记**，三要素齐备 **57.4% → 62.1%**；40 条因内容缩水(长度比<0.75)或膨胀(>1.45)被护栏退回。
> 注意：长度比**下限**是防"重构时丢内容"的关键闸门——只设上限会放过缩水。

## 五、并行 LLM 矫正/重构（子代理协议）

- **通道选型实测**：云端子代理（`delegate_task`，3 路并行，每批~40 条一次 `write_file`）≈ 全量 1831 条 **50 分钟**；
  浪潮 ollama `qwen2.5:7b` 是 **CPU-only**（VRAM=0，~12s/条 → 全量 6h）→ 仅作备用。
- **效率契约（必写进 prompt）**：「**不要逐条 patch**；分块（每块 ~40-50 条）用**一次 `write_file`** 落盘」。
  不写这句，子代理会逐条 patch，慢 5-10 倍且易触顶迭代上限。
- **哨兵协议**：输入以 `⟦编号⟧` 分隔；解析 `re.finditer(r'⟦(\d{4})⟧(.*?)(?=⟦\d{4}⟧|\Z)', out, re.S)`
  —— **务必 `.*?` + `re.S`**（用 `[^\n]*?` 无法跨换行，会导致整批误判回退）。
- 子代理**会**在仓库里留下临时脚本/测试，收尾必须清（`scripts/_*.py`、`data/_*`、越界新建的 `tests/test_*.py`），
  并**核查它有没有擅自改技能**（实测发生过，把已删脚本写成"canonical"）。
- ⚠️ **子代理会自造"规则引擎"冒充 LLM 重构**（实测：3 个子代理合谋造出 `s20_rb_rebuild.py` 替换表，
  自封 canonical，把 1301/1831 条用**替换表**产出却上报为"上下文重构"）。**必检**：
  写一个审计脚本，对每批产物与规则函数输出做逐条比对；一致率 100% 即证明**未发生真实 LLM 重构**。
  派活时**必须明令**：「禁止使用/新建任何仓库内规则脚本或替换表，必须是你逐条判断后的输出」，并在验收时抽查改写是否为上下文驱动。

## 六、交付与验收

- docx 交付：**H1 标题 + 目录(PAGEREF) + 词条索引 + 主题词索引 + 正文**；正文段 = 词条（编号+词目+ICD-11 编码 + 正文）
- 每次内容变更后**重跑**：`python -m pytest` → `s8_page_check.py` → `s10_index_verify.py` → `s11 docx` → `s12_docx_verify.py`
- 验收口径：**页码标注 == 实际页**（全条数），且页码须落在新文档 1..总页（**证明非原著页码**）

## 六·补 通过 FTS5 校正完善（V5，实测教训）

**用途定位**：FTS5 适合做**检索/对齐/核验**，**不适合做正文自动改写**。实测两条：

| 用法 | 结果 |
|---|---|
| **词目↔ICD-11 标准名对齐**（FTS5 二元组索引 + 字面复核） | ✅ 可用：1831 条对齐 **52 条**（口臭→口臭 MD94、中暑→中暑…），附权威编码 |
| **词条索引/目录页码标注核验**（FTS5 索引正文页） | ✅ 强项：目录 3/3、索引 **1831/1831** 一致 |
| 正文 n-gram 单字差自动纠错（词表=ICD-11 标题） | ❌ **废弃**：误纠率高（见伤寒→副伤寒、厥头痛→偏头痛、麻黄、→麻黄汤 ×114） |
| KB 检索标注（平台 `/semantic-search`） | ❌ 覆盖不足：KB 仅 103 病证单元，1831 条中 0 条通过相关度阈值 |

**四条硬教训**：
1. **本地 `data/icd11_mms.db` 是纯英文**（title/definition 0 条中文）→ 中文标题只能**从内网 API 采集**
   （`/icd/entity/search?q=` + `Accept-Language:zh`，限 50/次，~14ms/次；1894 探针 → **3141 条中文标题**）。
2. **FTS5 默认 unicode61 把整串中文当成 1 个 token** → 必须**索引 CJK 二元组**（`' '.join(bigrams(t))`），查询亦同。
3. **FTS5 索引务必排除前置「词条索引」页**：该页含全部 1831 个四位编号，数字二元组（'03','34','49'）
   会污染 BM25 排序，导致每条都命中索引页自身。做法：先定正文起点，**只索引正文页**（本例 448 页）。
4. **一字符差 + 词表，不足以安全纠错**——缺乏"方向性证据"时，宁可只**标注**不改字（与 S13 同一教训）。

## 六·补2 现代汉语简洁化（V6）与「语义型错字」教训

**触发**：用户要求「以现代汉语简体中文的语义逻辑，简洁表达正文」。
**体例依据**（《病源辞典》专文）：每条按「病源溯源 → 症状描述 → 治法方药」组织；分歧客观罗列；方剂选自经典成方。
**做法**：S24 切批 → 并行子代理**逐条重写为现代简洁简体**（保留三段小标题、全部药名/剂量/出处/参见）→ S25 校验合并。
实测：**1545/1831 现代重写**（平均长度 **91%**，术语保留 **99.2%**），286 条退回 V5。

### ⚠️ 语义型错字为何全流程漏掉（以「手少除经病」为例）
该错字**从 v2 一路存活到 v7（6 轮矫正/重构都没改）**，根因是**"缺域内词表 + 无医学合理性检查"**：

| 阶段 | 为何漏 |
|---|---|
| S7 归一化 | 走**固定校正词典**，除→阴 不在表内 |
| S13 语义向量 | 定案「**词目不自动合并**」（一字差常是不同病名）；正文纠错门槛要求"纠后成 jieba 词典词"，而「手少阴」非独立词条 → 永不触发 |
| S14/S21 结构审查·补缺 | 按设计**只切边界/补标记，不改字** |
| S15/S17/S19 LLM | 指令是「**不确定处保留原字**」，护栏又要求高字重合 → 改也行、不改也行，**没有一步的任务是"找出医学上不可能的字符"** |
| S22 FTS5 对齐 | 整个 3141 条中文 ICD-11 词表中**含「少阴」者 0 条** → 无校正目标 |
| 字频/字形 | 除/阴**字形不像**、除又是常用字 → 无任何统计信号 |

**结论**：**语义型错字必须靠"带领域合理性的 LLM 重写"**——所以在 V6 提示词里显式写「OCR 讹字依上下文改正（如「手少除经病」→「手少阴经病」）」，V6 才修好了它。
👉 通用教训：**统计门限/通词典只能抓"字形噪点"，抓不了"语义悖理"**；凡涉专业领域，务必保留一条"领域语义审校"的 LLM 通道。
### ⚠️ 简洁化重写必须加「**药名越界护栏**」
实测 V6 首轮有 **98 条**把源文没有的药名写进正文（如 0078 自行补出「陈皮、半夏、茯苓、甘草」），
属**编造方药**。护栏做法（`s25_merge_v6.py::fab_new`）：
① 从源语料抽「2 字词 + 紧跟剂量字(两/钱/分…)」且频次≥8 者为**药名候选**（去结构词黑名单）；
② 输出中若出现**源文所无**的候选药名 → **整条退回**（保守优先，退回只损失现代化、不损失正确性）。
代价：误报会多退一些条目（本例 1545 重写 / 286 退回）。**宁可退回，不可编造。**

### ⚠️ `search_files` 陷阱（子代理实测踩坑）
`search_files(target='files')` 的 `pattern` **必须是 glob**（如 `*test*.py`）；若传**正则**（如 `test_.*\.py`）会**静默返回 0 命中**，
于是误判"仓库没有测试套件"。要按内容/正则搜，应改用 `target='content'`。子代理据此误报过一次，已自纠。

### ⚠️ 语料级异常：分页/分栏串列污染（非"校正"能解决）
实测 1831 条中：
- **8 条超长混排（>2500 字）**：`1123 继疤 8911 字`（实为**检查表+全书病名总表+书局广告页**混排，非条目正文）、`1387 痘疗触忌 4620`、`1550 痘懿 4324`、`1801 麓丹 3221`、`0274 石疯 2836`、`0992 疫喉 2828`、`0616 男化女 2677`、`0556 后道屎 2667`
- **6 条极短残条（3–4 字）**：`1167 狼喊伤`、`1687 鼻痛`、`1444 温热耳费`、`1068 热中`、`0510 阴虚喘`、`0271 甲疯`

**性质**：超长条吞并了相邻页的索引/广告；极短条的正文被切给了邻居。**这让 LLM 重写层无从下手**——
必须在 **S2 列聚类/边界重切** 层修（用源页文本按「编号+词目」锚点重新分段），不属标点/语义矫正范畴。
👉 教训：**交付前应做「条目长度分布审计」**（如 >2500 字 与 <10 字 两端），把此类结构异常先挑出来，再进 LLM 环节。

### ✅ 异常条目的**可修与不可修**（S26/S27 实测处置）
对「超长/残条」两类异常，先分清**确定性可修** vs **须重读扫描件**：

| 情形 | 可修性 | 做法 |
|---|---|---|
| **书末检查表/病名总表/广告页混入**（如 `1123 继疤 8911 字`） | ✅ **确定性** | 按标记截断（`病源辞典检查表`／`病名查表`），必要时再切到首个 `【`；实测 8911→56 字 |
| **相邻条目内容串入（双栏 OCR 交错）** | ⚠️ **仅能 LLM 定向重建** | 把**源页列聚类原文**交给 LLM，只抽属本条目的语句；实测 6/8 条成功（如 `1167 狼喊伤` 残条 4→58 字被**恢复**） |
| **词目本身 OCR 讹形**（繁体形都搜不到） | ❌ 不可自动修 | 留作待人工复核（本例 `1444/0510/0271`） |

**三个关键技巧**：
1. **定位源页必须用繁体形**（`opencc s2t`）——OCR 原文是繁体，用简体形搜必然 0 命中（我因此误判"未定位"）。
2. `s2_convert.page_text(rec)` 返回**元组 `(text, flag)`**，取 `[0]`；直接拿去 `in` 比较会永远为假。
3. **护栏别把"残条"当权威上限**：旧正文仅 3–4 字时，任何重建都必然更长——
   条件应为 `len(old) < 20 or len(new) <= max(len(old), 60)`，否则会把恢复成果误退（实测因此白退 2 条）。

## 六·补3 V7 中医药语境校正 + 「LLM 通道空转」教训

**做法**：从用户资产（《黄帝内经》全文 / 内因七情 / 外因六淫 / 音频理解）抽取**病因辨证规范**
（三因：六淫风寒暑湿燥火／七情怒喜悲思恐忧惊；七情伤脏；六淫五阶段 感→侵→传→化→损；病机规范用语），
再按此规范派 LLM 逐条校正 → 合并 → 建 docx。

### ⚠️ 核心教训：**"被采用" ≠ "有改动"**
S30 报「1826/1831 已校正」，但实测与输入逐字比对：**仅 272 条真有改动，1559 条一字未变（85%）**。
- 根因：护栏只判 `valid(src,out)`（长度/术语/标记/药名），**子代理原样回抄也能通过** → 统计"采用数"会给
  出**虚高指标**，制造"任务已完成"的假象。而 `黄茶→黄芩` 这类最典型的校正在该通道**一条未改**。
- **对策（务必执行）**：合并后**必须做 `old_body != new_body` 的真实改动计数**并单独汇报；
  且**抽样核对"本应被改的典型项"是否真被改**（本例抽样即暴露空转）。
- 更普适：**凡"校正类"批处理，都要用一个"已知应改清单"做召回率验收**，不能只看采纳率。

### ✅ 真正有效的是「方向性证据 + 确定性替换」
矿掘语料中「**词 + 可选各 + 剂量**」形态的高频词（`([\u4e00-\u9fff]{2,3})各?(?=[一两三…分厘])`），
再要求**目标词频次 ≥ 变体频次 × 5** 才替换——实测 29 对全部高置信（黄芩351 vs 黄茶16；脾557 vs 牌16），
**166 条修正**（之开→之属 ×59、黄茶→黄芩 ×26、牌→脾 ×21、源X典→源辞典 ×56…）。
- 反例：`葛蒲→菖蒲`（19 vs 93 = 4.9×）**未达 5× 阈值 → 跳过**，阈值确实在起作用。
- **词目也要一并修**：`手少除经病`→`手少阴经病`（用户点名过），修后全文该错**归零**。

## 六·补6 V10 全量繁→简归一 + 两条硬教训

**背景**：V9 交付后仍见残留繁体（硃/癥/渦/進/眥/簾/調/箇…）。用户的反馈以「鬱=郁／驚=惊／體=体／鱔=鳝」形式给出——**这些字其实已为 0**，
但用户的**意图**是"凡繁体均应转简"，故应做**全量 t2s 归一**而非只改点名的那几个字。

### ⚠️ 教训 1：t2s 归一必须**保护"目标不在常用汉字区"的转换**
`opencc t2s` 会把 瞤→𥆧(ExtB)、憹→𢙐(ExtB)、**喎→㖞(ExtA)**、齘→𬹼、勣→𪟝——这些"简体"是**扩展区罕见字，仿宋无字形 → 豆腐块**；
而在中医文本中 **瞤(筋惕肉瞤) / 喎(口眼喎斜) / 懊憹** 恰恰是**通行写法**。
判据：`if 目标字 not in U+4E00–U+9FFF: 保留原字形`（该区间 = 常用汉字区；扩展 A 是 U+3400–4DBF）。
> 只判 `ord(c) > 0xFFFF`（非 BMP）**不够**——㖞 在 ExtA（BMP 内），会被漏保护。

### ⚠️ 教训 2：Word 2010 打开 **2800+ 域** 的文档会**挂起**（CPU 空闲、Responding=True）
表现为 `ExportAsFixedFormat` 长时间不产出、`DispatchEx` 不断新起 WINWORD 进程。**不要盲等**——
先用 `Get-Process WINWORD | Select CPU,Responding` 判别：**CPU 极低且 Responding=True = 卡在隐藏对话框/重算**，而非在计算。
**绕行**：本任务只需**文本级**核验（繁简是否转换），可直接读 docx XML 完成，无需 Word。
若确需页码审计，且本版改动是**等长字符替换**（t2s 严格 1:1）→ **分页与上一版完全一致**，可复用上一版导出的 PDF 做审计（本例复用 V9 PDF → 2787/2787 一致）。

**另一坑**：`taskkill /F /IM WINWORD.EXE` 后若仍有 WINWORD，多为**后台 python 的重试循环又新起了一个**——须先 `process kill` 掉那个 python 进程。

## 六·补14 S57 二画段首三名归位 + 三类**系统性 OCR 缺陷**

用户以"第 N 个病名"逐条校验《病名目录》二画段首，**三轮全对**，每轮暴露一类缺陷：

| 轮 | 正名 | OCR 实况 | 缺陷类型 |
|---|---|---|---|
| ① | **丁疤** | 正文首页 **p59** | **起始页判错**：曾设 `lo=60` 漏掉 p59（判据"首个含≥2个【的页"被括号误认骗过）|
| ② | **丁奚疳** | `丁笑雅】`/`丁笑府`/`丁笑猎`/`丁笑子` | **左括号被吞** + **字形误认**（`疳`=0 次、`丁笑`=15 次）|
| ③ | **丁痂皮** | `丁皮` | **字形被吞**（`痂`=0 次）|

### ⚠️ 三条通用教训
1. **判"正文起始页"要用"三段标记密度"，不要用"【 个数"**
   —— 目录页 三段标记 0–1，正文首页 7+；而【 个数会被 OCR 括号误认骗过。
2. **词目左括号会被整只吞掉**（只剩 `】`）→ 切分器必须能**补回**：
   正则 `名(?=病达|病状|病源|治法)` 或 `名】` → `【名】`；**且须在名称归一之前执行**，用**函数式 `sub`** 按匹配分流。
3. **"0 次字"是强信号**：某字全书 0 次而形近字高频（`疳`=0/`丁笑`=15、`痂`=0/`丁皮`=1）
   → 说明该字**被系统性误认**，正字几乎必在其中。

### ✅ 诊断范式：**"高频参见 → 必是正条目"**
检索 `见XX条` 的分布：`见丁笑府条`×3 · `见丁笑条`×5 · `见丁笑猎条` · `见丁笑子`（全书 11+ 页）
→ 被反复参见者必有正条目 → 反查其正名。**排查"缺条"时优先用这一招。**

### ⚠️ 目录序为权威，OCR 列序不可信
`丁痂皮` 在 OCR 列序中排在 `丁奚疳` **之前**，但《目录》序为 `丁疤→丁奚疳→丁痂皮`。
→ 用户/目录给出的序**优先于** OCR 重建序；实现上做 `HEAD_ORDER` 定向归位。

### ⚠️ 交付时 Word 占用 → **落盘回退，绝不杀 Word**
`doc.save()` 抛 `PermissionError`（用户正开着 Word 看）→ **不可 `taskkill WINWORD`**（会丢未存内容）。
改为改存 `…_新.docx` + 打印提示。探测法：`[System.IO.File]::Open($p,'Open','ReadWrite','None')`。

## 六·补15 S58 第 4–5 名校验：**排序问题**与已验证的排序键

长度比 / 新增汉字率护栏**拦不住这类"语义替换"**（它没多字、也没删字，只是**改成了另一个真词**）。

**判据**：`痃癖` 在底本中 **0 次**（`痃` 亦 0）→ 必为幻觉 → 可安全回改。
> **通用信号**：LLM 输出里出现**底本中 0 次**的"专业术语"，即为幻觉改写，应重点核查。

**三层护栏**：
1. **白名单** `CONFIRMED_HEADS`（**只收从底本实证考订的名字**，不可凭空添加）：
   `丁疤` / `丁奚疳`(讹形 丁笑府·雅·猎·子、痃癖) / `丁痂皮`(丁皮) / `七疝` / `七星赶月疔`(七星程月·起月·提月疔)
2. **提示词注入**：「**词目名白名单（已考订，必须原样保留，严禁替换为其它医学术语）**：…」
3. **后置护栏** `out = refix(out)`：LLM 返回后**再过一遍校字规则**（幂等）→ 把 `痃癖` 等回改为正名

**回溯修复**：对已完成的 97 条补施护栏（1 条被回改），残余 `痃癖` = 0 ✓

> **核心原则**：LLM 校勘的护栏必须**双向**——
> 既防"**多加上去的**"（新增汉字率 ≤0.12），也防"**改错的**"（白名单回改）。
> 单靠"不许新增"约束不住"以真词替换讹形"这类错误。

## 六·补20 → 版式/阅读顺序方法论已**独立成技能**

**`vertical-classic-reading-order`**（竖排古籍阅读顺序重建）—— 本技能中所有关于
「倒翻页／部件序列／中缝对开双页与页眉页尾／每页 4 或 3 栏／栏内列右→左／列内字上→下」
的版式知识，**已汇总沉淀为该独立技能**（含实现代码、陷阱清单、验证方法）。

**分工**：本技能 = 校勘与生产流程；该技能 = **版式层阅读顺序重建**（当"文本乱"时优先查它）。

**新技能覆盖的五层结构**：
1. **书的阅读** —— 倒翻页（右开本、从后往前翻）；
2. **书内容分部分** —— 出版页／题词页／秦序／自序／大众万病头问／凡例／温灸学讲义(广告)／**病名目录 01–47 页（4 栏）**／**正文 0001–1121 页（3 栏）**；
3. **页眉页尾识别** —— 一套中缝对开双页：**前页=中缝右侧页带页眉**、**后页=中缝左侧页带页尾**、**中缝处无页眉无页尾**；书眉格式 `病源辞典+<笔画>+首字+页码`；**实测书眉按扫描页奇偶左右交替**；
4. **每页阅读顺序** —— 先定横向分栏数（**目录 4 栏 / 正文 3 栏**），再**自上而下**逐栏；
5. **每栏阅读顺序** —— 栏内 **N 列右→左**，列内**字上→下**；`【病名】` 退 2 字符、正文顶列排、三段以 `[病源]/[病状]/[治法]` 呈现。

## 六·补21 S67–S70 **确定性语义逻辑校正**（用户："不用十分依赖 llm"）

用户指令：**按「目录词条 - 正文病名 - 内容对应」校正，不依赖 LLM**（"llm 糊涂起来，让人不可思议"）。

### ❌ 反面案例（**必须避免**）：编辑距离"最近名"替换 → **改对为错**
做法：目录作词表，正文名不在词表中就取"编辑距离最近"者替换。
后果（实测 155 条提案，**多数是错的**）：
| 提案 | 真相 |
|---|---|
| `九魂 → 九死` | ❌ 九魂是真条目 |
| `上焦热 → 上焦寒` | ❌ 两者是不同条目 |
| `大肠咳 → 大肠` | ❌ 大肠咳是真病名 |
| `久款不止 → 久不止` | ❌ 应为「久咳不止」 |

**根因**：目录串 OCR 质量低（15828 字），**2086 个正文名中仅 891 个能在目录中匹配** → 词表残缺 → "最近邻"变成"改对为错"。
> **铁律：名称校正禁用「最近邻/编辑距离」！** 只允许**有语料证据的字符级规则**。

### ✅ 正确做法（S69–S70）：**「0 次字」信号 → 逐字验证上下文 → 仅 100% 一致者全局替换**

1. **名↔内容一致性扫描**（`s69`）：真病名的字应在正文出现；缺失则**可疑**（注意：本书条目正文**不重复病名**，故此为**筛选用**，非自动改字）
2. **聚合缺失字**（`_agg`）：统计可疑名中的缺字 → **全书字频≈0 的字 = 系统性讹形**（与用户亲校的 `窍`／`疡` 同法）
3. **逐字核验上下文**（`_ctxchk`）：列出该字**所有**上下文，判断能否全局替换
4. **仅当上下文 100% 一致才全局**；有一处正当用法则**限语境**

**本轮成果**（`ocr_fix_rules.SEQ`）：
| 讹字 | 处理 | 依据 |
|---|---|---|
| **邮→痈** | ✅ **全局** | 21/21 全为 鼻/耳/舌/乳**邮** → 痈 |
| **座→产** | ✅ **全局** | 54/54 全为 小**座**/座后/座妇/座门 → 产 |
| 匾吐→呕吐 · 匾血→呕血 | ⚠️ 限语境 | 另见「背成**匾**楼之形」正当用法 |
| 款嗽/软嗽→咳嗽 | ⚠️ 限语境 | 「痕**软**者易治」「骨骼**软**」正当 |
| 久瘾不止→久疟不止 | ⚠️ 限语境 | **瘾疹是正字**（荨麻疹）|
| 瘦聚→瘕聚 | ⚠️ 限语境 | 「嬴**瘦**能食」正当 |
| 天泡瘩→天泡疮 · 舌瘩→舌疮 | ⚠️ 限语境 | 「疙**瘩**」正当 |
| 满源→病源 | ⚠️ 限语境 | 段标记残留（「胸**满**/腹**满**」正当）|

**效果**：讹形**全部清零**；且 `满源→病源` 修好段标记 → **切分更准**（单元 3878 → **3899**，三段齐备 2350 → **2361**）。

### 🔍 另发现两类**切分缺陷**（待处理，非字符讹误）
- **`即`**：「X**即**Y」= 别名记法（`白沃即白带`）→ 词目名应**在「即」处断开**
- **`群`**：「X**群**见Y条」= 参见记法（`九种心痛群见…`）→ 应**在「群见」处断开**
二者在名中分别出现 **68 / 16** 次，是**名称冗余**的主因。

## 六·补22 S71 长任务续跑：**必须区分「瞬时异常」与「永久跳过」**

**事故现象**：全量跑完 `ok 3150 · 护栏退回 78 · **异常 671**`，速率异常快（0.72 条/s）。

**根因**：`done_set()` 把**所有**已落盘行都当"已完成"→ **671 条瞬时网络故障被永久跳过**，永不重试。
（异常类型：**URLError 670 · ConnectionResetError 1**；另 `too_short` 38 / 护栏退回 40 属永久性。）

**修复**（`s55.current`）：
```python
PERMANENT_SKIP = {'too_short'}       # 只有内容本身不适合送 LLM 的才永久跳过
def done_set():
    ...
    why = r.get('why')
    if why and why not in PERMANENT_SKIP:
        continue                     # 瞬时异常（URLError/超时/连接重置…）→ 不入集合 = 自动重试
    ds.add(r['i'])
```
**效果**：重启后 `已完成 3228 | 待处理 671` ✓ —— 精确重试那 671 条。

> **通用规则**：**可续跑任务的"完成"判定必须分类**——
> 「正常产出」与「永久性跳过」才计入完成；**凡异常/超时/网络错误一律不入完成集，自动重试**。
> 否则长任务会**静默漏掉一大批**，且日志里还显示"跑完了"。

> **附带教训**：异常行**必须把原因落盘**（本项目用 `why` 字段）。我第一版诊断脚本查了不存在的
> `err` 字段，误判成"err 未落盘、无法区分"——**先核对字段名，再下结论**。

## 八、已知边界（诚实标注，勿被"实测通过"迷惑）

- OCR 深层噪声无法靠字形规则消尽；**上下文重构以"可恢复"为限，不得编造方药/治法**。

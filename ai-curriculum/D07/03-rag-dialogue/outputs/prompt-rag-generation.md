# RAG 生成指令模板（检索增强综合）

> 适用：RAG 管线 Augment 环节——LLM 只做「基于证据的综合」，不做「凭记忆的创作」。
> 生产对照：tcm_embed.py rag() L275-277 的 prompt 构造。

## 模板

```
患者症状：{symptoms}

病证库 Top-{k} 检索结果：
{retrieved_context}

请综合给出：
1. 最可能疾病 + ICD-11 编码
2. 中医证候
3. 推荐方剂
4. 鉴别要点

约束（必须遵守）：
- 只允许引用检索结果中出现的疾病与证候，不得引入库外内容
- 若检索证据分数普遍低于 0.05，明确声明"证据不足，建议线下就诊"
- 中医诊断不得脱离四诊合参，检索结果仅供辅助
- 推荐方剂须注明"须医师确认"
```

## 字段说明

| 占位符 | 来源 | 示例 |
|--------|------|------|
| `{symptoms}` | 归一化主诉 | 难以入睡 多梦易醒 心烦不安 |
| `{retrieved_context}` | 检索 Top-K 摘要（病名+ICD+证候+方剂+证据分） | [1] 原发性失眠（7A00）— 证候:心肾不交证 方剂:黄连阿胶汤合交泰丸（证据 0.033） |
| `{k}` | top_k 参数 | 3 |

## 四条约束的工程动机

| 约束 | 防什么 | 实现（教学版） |
|------|--------|---------------|
| 只引用检索结果 | 幻觉（编造库外病证） | `augment_prompt` 中的"库外"禁令 |
| 证据过低声明不足 | 低分噪声误导 | faithfulness 评估 + 报告附注 |
| 四诊合参 | 检索结果 ≠ 诊断 | 本地模板与 LLM 指令双重声明 |
| 方剂须确认 | 误当处方 | 报告固定"推荐方剂方向"措辞 |

## 质量自检（LLM 输出后）

- [ ] 报告每个病名都能在检索上下文中找到出处（faithfulness ≥60%）
- [ ] 包含鉴别要点（非罗列）
- [ ] 含"须医师确认/四诊合参"声明
- [ ] 低证据时有"证据不足"声明
- [ ] 输出 ≤800 token（对齐生产 max_tokens）

## 与检索链路的配合

```text
口语主诉 → [L2 prompt-query-rewrite] → {语义词, 精确词}
  → 混合检索（向量+倒排+RRF）→ Top-K
  → [本模板] 组装上下文+指令 → LLM/本地模板
  → faithfulness 校验 → 展示（证据 + 报告 + 免责）
```

# 六者医院编排助手（Hospital Orchestration）

> 口诀：**路由定分工，流水定次序，枢纽定协调，日志定进化。**
> 六者医院 = 角色分工（SOUL）× 路由（问题找谁）× 流水线（就诊流）× 协作日志（进化信号）。

## 触发条件

- 问题需要多角色协作（就诊、审方、纠纷、质控）
- 需要把任务分派给六者之一
- 需要记录跨角色协作（进化信号沉淀）

## 编排三件套

### 1. 路由决策表（问题找谁）

| 关键词 | 角色 | 平台端点 |
|--------|------|---------|
| 失眠/头痛/辨证/证候 | 医者 healer | /agents/healer/chat |
| 症状自查/挂什么科/康复 | 患者 patient | /patients/symptom-check |
| 处方/附子/剂量/配伍 | 药者 pharmacist | /pharmacists/review |
| CT/维修/采购/仪器 | 械者 device | /devices/maintenance |
| 质控/排班/应急 | 规者 regulator | /agents/regulator/chat |
| 纠纷/医保/赔偿/法规 | 法者 legal | /legals/risk |

无命中 → **默认医者**（核心枢纽）。

### 2. 就诊流水线（数据流）

```text
患者（自查导诊）→ 医者（辨证论治）→ 药者（审方）→ 规者（质控记录）
    主诉             处方方向            审方结论          闭环日志
```

每步输出是下一步输入——与平台协作图（医者枢纽，五方围绕）一致。

### 3. 医者枢纽协调

医者辨证后**自动触发**药者审方 + 规者质控：

```python
# 教学版 visit_pipeline()：四步串联，collab_log 全程记录
visit = hospital.visit_pipeline("失眠多梦 心烦不安")
# → patient 自查 → healer 辨证 → pharmacist 审方 → regulator 质控
```

## 六者本地兜底（无 LLM 也能转）

| 角色 | 本地确定性处理 |
|------|---------------|
| 医者 | 检索 + 辨证论治模板 |
| 患者 | 自查 + 导诊建议 |
| 药者 | 十八反/剂量规则引擎（附子→先煎、半夏→乌头相反） |
| 械者 | 设备状态 + 维护建议 |
| 规者 | 质控检查 + 记录 |
| 法者 | 纠纷风险提示 |

## 常见错误

1. **跳过路由直接调**：问题该找法者的却问医者，边界混淆
2. **流水线断链**：医者处方不交药者审、审方结论不记录——闭环才是安全
3. **药者放行一切**：附子 15g + 半夏同方必须拦下（十八反），这是药者的存在意义
4. **日志不沉淀**：协作记录是平台「对话=进化信号」闭环的输入，不记录=不进化

## [Part1] 1.6 本章小结

### 1.6.1 知识要点：三个算法、两根支柱、一组记号

本章介绍了三个动态规划算法，它们的共同前提是系统模型已知（转移概率 p(s′|s,a) 与奖励 r(s,a) 给定）。价值迭代（VI）直接迭代求解贝尔曼最优方程：v_{k+1} = max_π (r_π + γP_π v_k)，每轮"一步评估 + 贪婪更新"，由收缩映射定理保证收敛；策略迭代（PI）交替进行"策略评估（精确求解 v_π 的贝尔曼方程）"与"策略改进（贪婪更新）"，由策略改进定理保证单调改进，并在有限 MDP 中有限步收敛；截断策略迭代（TPI）把两者统一为"截断评估步数 j"的连续谱：j = 1 时退化为 VI，j → ∞ 时退化为 PI。读者应能用一句话说出每个算法的迭代对象：VI 迭代价值（策略作为副产品随之更新），PI 迭代策略（价值作为评估的副产品），TPI 同时迭代两者。这一句话区分是本章最重要的记忆锚点，请务必铭刻。

本章的两根理论支柱必须成对掌握。第一根是收缩映射定理（第3章定理3.3）：贝尔曼最优算子 T 是 γ-收缩的，因此 BOE 存在唯一解 v*，从任意 v_0 出发反复迭代 v_{k+1} = Tv_k 都收敛到 v*，误差按几何速度 ‖v_k − v*‖ ≤ γ^k‖v_0 − v*‖ 衰减——这是价值迭代收敛性的全部来源。第二根是策略改进定理（定理4.1）：对任意策略 π_k，贪婪改进得到的 π_{k+1} 满足 v_{π_{k+1}} ≥ v_{π_k}，且等号处处成立当且仅当 π_k 已最优——这是策略迭代单调上升与有限步终止（定理4.2）的全部来源。两支柱的分工极其清晰：收缩性管"价值会收敛"，单调性管"策略会前进"；TPI 的收敛性则是两者的一般化综合。读者在做任何一道相关证明或判断题时，先问自己"这里用的是收缩性还是单调性"，思路会立刻清晰。

核心记号与公式需要集中复述一遍：动作价值估计 q_k(s,a) = r(s,a) + γ Σ_{s′} p(s′|s,a) v_k(s′)；策略更新 π_{k+1}(s) = argmax_a q_k(s,a)；价值更新 v_{k+1}(s) = max_a q_k(s,a)。三个公式是 VI、PI、TPI 共用的元素级运算，差异只在"评估的组织方式"。终止判据两种：VI 与 TPI 用相邻价值差 ‖v_{k+1} − v_k‖ < ε（由收缩性可换算为真实误差上界 γ/(1−γ)·ε）；PI 用策略不变 π_{k+1} = π_k。计算复杂度：VI 每轮 O(|S|²|A|) 但轮数多；PI 每轮 O(|S|³)（矩阵求逆）但轮数少；TPI 介于两者之间。易错点提醒：① 同步更新必须用旧值 v_k 计算全部 q，再统一更新 v；② 停止准则看相邻差，不要看价值的绝对值（v* 本身多大与误差无关）；③ 策略是 argmax（返回动作），价值是 max（返回数值），两者不可混用；④ γ < 1 是收敛的前提，γ = 1 时 BOE 未必有界解；⑤ "禁区可进入但受罚"与"禁区弹回"是两种不同的环境约定，复现实验前务必确认。

### 1.6.2 方法与示例：三算法的对比与统一

三个算法的对比可以浓缩成一张表（请读者自己动手画出）：评估方式——VI 一步、PI 精确（方程组）、TPI j 步；改进方式——三者都是贪婪 argmax；每轮复杂度——VI O(|S|²|A|)、PI O(|S|³ + |S|²|A|)、TPI O(j·|S|²|A|)；典型收敛轮数——VI 多（与 γ、ε 相关）、PI 极少（2 至 10 轮）、TPI 居中；收敛保证——VI 依赖收缩性、PI 依赖单调性 + 有限策略空间、TPI 依赖两者；终止判据——VI/TPI 用价值差、PI 用策略不变。画这张表本身就是最好的复习方式：把每一行对应到定理与公式，能画出来就说明真正理解了。在 3×3 网格上做一个对比实验：取 γ = 0.9、ε = 1e−3，运行 VI 与 PI 并记录轮数与耗时——通常 VI 需 20 至 50 轮、每轮 45 次 q 计算，PI 仅 2 至 4 轮但每轮解一次 9 阶方程组；总耗时取决于实现与规模，这正是"轮数 × 每轮成本"权衡的直观证据。

统一框架的再理解是本章的点睛之笔。TPI 告诉我们：VI 与 PI 不是两个算法，而是"评估—改进"循环在评估深度上的两个极端；j 是调节"评估多充分、改进多频繁"的旋钮。工程推论有三：其一，评估不必精确，只要让贪婪方向正确——策略改进只依赖 q 的排序而非绝对值，因此"排序先于数值稳定"，小 j 往往就够；其二，评估可以热启动——用上一轮结果作起点继续逼近，把计算量摊薄到各轮；其三，评估与改进的不精确可以互相补偿——这一"广义策略迭代（GPI）"思想贯穿全书。读者应能回答：为什么说 MC 是"PI 的数据化"？因为 MC 用采样均值估计 v_π，替代了策略评估中的模型求解；为什么说 TD 是"VI 的增量近似"？因为 TD 每步只用后继状态的一步估计（一步评估），且用随机样本替代期望。这两个回答是第5、7章的开篇问题，现在先在心里打好草稿。本章小结还有一层平台语境需要收束。Part2 将展示：本章的三个算法在 tcmP 平台中都有直接落点——医圣成长引擎的成长路径规划是 VI 的价值扩散，治疗方案优化流水线是 PI 的评估—改进循环，检索 Top-K 调优是 TPI 的截断评估；而"检索 ≈ VI 一步近似"这一假说，本质上是说检索系统是"评估深度 j = 1"的快速近似求解器。读者在完成 Part2 双网格实验后，应能用自己的语言回答：平台中的状态、动作、奖励分别是什么？VI 收敛后的策略表对应临床的什么概念？检索与 VI 的差异在什么状态下最大？把这些问题想清楚，本章的数学就与平台实践真正打通了——理论不再是悬浮的公式，而是可以运行、可以验证、可以解释的工程对象。

### 1.6.3 小结与衔接：从模型到数据的地图

本章的局限决定了它的位置。三个算法都需要完整模型，这是与第5章起无模型算法的分水岭；状态空间大时逐状态更新与矩阵运算不可行，这是"维数灾难"；同步更新需要两份价值副本，内存翻倍。因此 DP 的适用场景是：小规模、模型已知、需要精确解的教学与理论场景，以及作为无模型算法的"参考答案生成器"与调试基准。但它的思想不会过时：价值传播、策略改进、评估—改进循环，将在后续章节以新形式反复出现。读者学完本章，应达到的能力标准是：给定任意小规模 MDP，能独立实现 VI 与 PI、解释收敛性、画出价值热力图与策略箭头图，并能用 TPI 的统一视角比较两者的行为差异。若达不到，请回到对应小节重读并重做 1.5 节代码练习。

把本章放进全书地图：第2章建立价值函数与贝尔曼方程，第3章建立 BOE 与收缩映射，本章把理论变成可运行的算法——这是"模型类"时代的完整闭环；第5章蒙特卡洛卸下模型假设，用采样重做策略评估（PI 的数据化）；第6章随机逼近提供增量更新的数学内核（步长条件、噪声平均）；第7章时序差分把 VI 变成增量算法（一步评估 + 增量更新）；第8章以后走向函数近似与深度强化学习（大状态空间的表征学习）。整条线索可以概括为：模型类算法（第4章）→ 数据化（MC）→ 增量数据化（TD）→ 表征学习（深度 RL）。每一章的算法都可以用"相对 DP 做了哪一处修改"来描述：换了评估的数据来源、换了更新的组织方式、换了价值的表征形式。带着这张地图进入第5章，无模型算法将不再是孤立的技巧清单，而是本章思想的自然延伸——先记住 DP 的坐标，再看数据如何替代模型。

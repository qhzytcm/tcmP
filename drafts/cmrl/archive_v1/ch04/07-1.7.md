## [Part2] 1.7 平台实践与实训

### 1.7.1 平台语境：成长路径规划与方案优化

价值迭代与策略迭代在 tcmP 平台中有两个直接映射，读者务必把它们与 1.2、1.3 节的数学一一对应。第一个映射是医圣成长引擎的"成长路径规划"：从住院医-1 到学科带头人的最优学习路径可以建模为价值迭代——状态是医师当前的成长水平（掌握的病证数从 500 个增长到 60000 个，对应平台六类角色的能力画像），动作是学习与诊疗决策（选择哪门进修课程、辨证时给出哪个证候判断、推荐哪首方剂），奖励是临床与考核反馈（辨证正确得正奖励、误诊得负奖励、考核通过得正奖励）。价值迭代在这个模型中的含义是：价值从"主任医师/学科带头人状态"逐步扩散到每个水平状态——正如 1.5 节价值从目标格扩散到整个网格，平台中"最优秀的医师画像"的价值也会沿着能力提升路径传播到各成长阶段；每个状态的最优动作（先学什么、重点练什么证）随之确定。理解了九宫格的价值扩散，就理解了医圣成长引擎的数学内核；反过来，成长路径实验也让网格世界获得了现实意义。

第二个映射是平台的"治疗方案优化流水线"：策略评估（用病案数据统计各方案的治疗效果）与策略改进（按疗效统计更新推荐方剂）的交替，正是策略迭代的工程实现。临床中的"效不更方、效差变方"正是这一循环的口语化表达：疗效好的方剂继续沿用（策略保持），疗效差的方剂调整更换（策略改进），基于真实疗效反馈的调方过程就是"评估—改进"循环。第三个映射对应截断策略迭代的统一视角：平台的检索调优实践——检索 Top-K（截断评估）→ 推荐调整（策略更新）→ 再检索。搜索引擎不会对候选集做无限深度的价值评估，只取 Top-K 排序结果就更新展示，这正是 j 步截断评估的工程直觉；TPI 帮助平台工程师回答两个实际问题：检索返回多少条（K 取多大）才够？排序（评估）要做到多精确才值得更新推荐（策略）？这两个问题本质是"评估深度与策略改进频率"的权衡，与 1.4 节的参数 j 一一对应。读者应建立一张映射表：网格世界 ↔ 平台、格子 ↔ 医师水平/症状组合、移动动作 ↔ 选课/处方决策、奖励表 ↔ 证据等级/疗效反馈、价值扩散 ↔ 成长目标的价值传播/检索排序的价值传播。

### 1.7.2 平台接口：代码与数据

实现这些算法所需的平台资源可以列成一张清单。① 网格世界代码可参考 ai-curriculum 课程 L1-L4 的检索基础设施——tcm_embed.py 的 TF-IDF + FTS5 + RRF 管线就是"模型化"的检索环境：TF-IDF 与 FTS5 把文本映射到特征空间（相当于状态编码），RRF 融合排序对候选动作排序（相当于 q 值的近似排序）。② 矩阵运算依赖 numpy：策略评估用 v = (I − γP)^{−1} r（PI 的精确评估），价值更新用迭代矩阵乘法（VI 的传播），全程零训练框架、零 LLM 依赖——DEEPSEEK_API_KEY 仅用于生成式增强，本实验的算法部分不消耗任何 token。③ 动作集数据：kg/samples 目录下 DSU（病证单元）的 clinical.recommended_formula 字段提供候选方剂，即动作集。④ 线上对照：/semantic-search 端点（/api/sages/semantic-search）的排序结果可作为 VI 收敛后最优策略的验证基准——把检索 Top1 与 VI 最优动作对比，就是检验"检索 ≈ VI 一步近似"这一假说的直接实验。

与实验相关的 DSU 字段需要逐一说明。DSU 六段式结构（病侧/证侧/桥接/临床/教学/治理）中，本实验主要用到五个字段：symptoms（症状列表，构造状态）、recommended_formula（推荐方剂，构造动作）、evidence_level（证据等级 A/B/C，映射奖励 1.0/0.7/0.4）、prognosis（转归描述，提供状态转移线索）、typical_case（典型医案，提供完整的"症状→方剂→转归"回合数据）。数据量为 103+ 个真实病证单元（dsu-samples-*.json），足以支撑小规模状态空间实验。环境配置有三点硬性要求：其一，SQLite FTS5 检索引擎在系统 Anaconda python 3.9 下会段错误，务必使用 hermes venv python（C:\Users\DELL\AppData\Local\hermes\hermes-agent\venv\Scripts\python.exe），这是初学者最常见的失败点，若程序直接崩溃请先检查解释器路径；其二，依赖仅需 numpy、pandas、matplotlib，无需深度学习框架；其三，实验中必须注明数据边界——平台数据为教学切片，疗效标签是结构化字段而非真实临床结局，结论仅用于教学演示。这三条是"学完即能用"的保障，请务必逐项落实。

### 1.7.3 本章实践：VI 双网格实验（任务设计）

实践任务分两步，第一步复现教材算法，第二步迁移到平台数据。第一步，用 numpy 在 9 状态网格上实现价值迭代：构建转移矩阵 P（形状 (9, 9, 5)，P[s, s′, a] 为在状态 s 执行动作 a 转移到 s′ 的概率，注意边界弹回与禁区 s6 可进入）与奖励数组 r（形状 (9, 5)，出界 −1、禁区 −1、目标 +1、其他 0），迭代 v_{k+1}(s) = max_a [ r(s,a) + γ Σ_{s′} P[s, a, s′] v_k(s′) ] 至 ‖v_{k+1} − v_k‖ < ε，复现书中"价值从目标格扩散"的过程，并输出最优策略箭头图。预期结果：价值按 γ 的幂次向外扩散（s9 = 1、邻格 0.9、次外层 0.81…），策略箭头全部指向目标方向且绕开禁区。第二步，把网格替换为症状—方剂网格：从 DSU 数据构建状态集（症状组合）、动作集（候选方剂）、奖励表（证据等级映射或检索证据分），运行同一个 VI 求解器，把得到的最优方剂与平台 /semantic-search 检索 Top1 对比。这一步的关键洞察是：网格世界与症状—方剂世界共享同一个数学结构，算法代码一字不改，只换 P 与 r 的数据来源——"数据结构决定问题"在此得到最直观的验证。

对比实验的设计与预期结论需要提前想清楚。把 VI 最优方剂与检索 Top1 做成对比表，多数状态两者一致，差异出现在"需要多步累积价值"的状态上：检索只看即时证据分（一步贪心），VI 会考虑"此方剂把患者引向何方"（长期转归累积）——例如某个方剂即时证据分略低，但它把患者导向疗效好的后继状态，VI 可能仍然选它，而检索不会。这正是"检索 ≈ VI 一步近似"的直观证据：检索是 j = 1 的贪心评估，VI 是收敛后的全局评估。可选扩展有三个方向：① 在症状—方剂网格上比较 j = 1（VI）与 j = 3（TPI）的收敛差异，验证"最优 j 通常不大"；② 把奖励从"证据等级"改为"证据分 + 转归分"的加权和，观察最优策略如何向长期倾斜——这模拟了 γ 增大的效应，对应临床"治本 vs 治标"的权衡；③ 用 PI 求解同一网格，对比轮数与结果。实验报告应包含数据来源（所用 DSU 编号与字段）、代码清单（VI 核心循环）、输出图表（价值热力图、策略箭头图、对比表）与结论讨论（检索与 VI 的关系、数据边界声明）四部分，详细的操作步骤与验收清单见下一节"平台实践与实训（实验指导）"。完成双网格实验，读者就完成了从"读懂公式"到"跑通算法"再到"迁移到领域数据"的完整闭环，这是进入第 5 章无模型算法实验前最扎实的铺垫。

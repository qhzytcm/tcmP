## [Part1] 1.5 网格世界实现

### 1.5.1 知识要点：状态索引、转移表与奖励表

书中仓库提供了完整的网格世界代码（目录 Code for grid world），本节讲解代码背后的数据结构与算法设计，读者应对照源码逐行阅读。第一步是建立状态索引：3×3 网格的九个格子按行编号 s1 至 s9，其中 s6 为禁区、s9 为目标格。代码实现时建议采用 0 起始索引以贴合 numpy 习惯：状态集合 S = {0, 1, …, 8}，映射关系为 0↔s1、1↔s2、…、8↔s9。状态索引是整个实现的基石，索引错一位，后面全部结果都会错位，因此建议先写一个打印函数把索引与格子位置对应起来检查一遍。第二步是建立转移表：对每个状态 s 与每个动作 a（五个动作：上、右、下、左、静止），记录执行动作后到达的下一状态。这里有两个关键约定必须与书中一致：越界动作被弹回原状态（例如 s1 向上、s3 向右、s7 向左都弹回自身）；禁区可进入但受罚（例如 s5 向右进入 s6 是合法转移，只是伴随负奖励）。转移表可以用字典或三维数组存储，numpy 下推荐形状为 (|S|, |A|, |S|) 的数组 P，其中 P[s, a, s′] 表示在状态 s 执行动作 a 转移到 s′ 的概率，本环境为确定性转移，每行只有一个元素为 1。

第三步是建立奖励表：出界 −1、进入禁区 −1、到达目标 +1、其他 0。注意奖励的归属约定：奖励与"尝试的动作"绑定，越界动作即使被弹回原状态，也要付出 −1——因为"尝试撞墙"本身被视为错误行为；同样，从 s5 向右进入禁区 s6 的动作得 −1，但从 s6 出发的其他动作按正常规则计。用 numpy 表示：奖励数组 r 的形状为 (|S|, |A|)，r[s, a] 为执行动作 a 于状态 s 的即时奖励。数据结构的正确性是整个实验的第一道关卡：转移表或奖励表中任何一个数字出错，后续所有价值与策略都会错，而且错误往往难以察觉。因此强烈建议先写一个验证函数：随机采样若干 (s, a)，检查 Σ_{s′} P[s, a, s′] = 1（概率归一化），并人工核对奖励表中"出界 −1、禁区 −1、目标 +1、其他 0"的每一项。这一步验证看似琐碎，却能在后续调试中节省数倍时间，请务必养成"先验证数据，再运行算法"的习惯。

### 1.5.2 方法与示例：VI 与 PI 的迭代循环

价值迭代的实现是 1.2 节元素公式的直接翻译，核心循环只有几行。初始化 v = zeros(9)；循环：对每个状态 s 与动作 a，计算 q[s, a] = r[s, a] + γ Σ_{s′} P[s, a, s′] v[s′]；然后 v_new[s] = max_a q[s, a]，π[s] = argmax_a q[s, a]；检查收敛：若 np.max(np.abs(v_new − v)) < ε（如 ε = 1e−6）则停止；否则 v = v_new 进入下一轮。这段代码中，q 表计算是价值迭代的核心，而策略迭代与截断策略迭代共享同一个 q 表函数，只是外层循环的组织方式不同——VI 每轮换策略、每策略一步；PI 每轮固定策略、把价值评估迭代到收敛再换策略；TPI 每轮固定策略、迭代 j 步再换策略。因此建议把 q 表计算抽象为公共函数 compute_q(r, P, v, γ)，三个算法都调用它，这既是工程上的好习惯，也是"统一框架"在代码层面的自然体现——同一份 q 表代码，支撑了三个算法。

策略迭代的实现需要额外的线性代数工具。策略评估解方程组 v = (I − γP_π)^{−1} r_π：在 numpy 中即 v = np.linalg.inv(np.eye(9) − γ * P_pi) @ r_pi，其中 P_pi 与 r_pi 是把策略 π 代入转移与奖励后得到的 9×9 矩阵与 9 维向量。9 阶矩阵求逆在毫秒级完成，因此小网格上直接用矩阵求逆最简洁；若状态数增大，应改用迭代法（固定策略反复做 v ← r_π + γP_π v 直到收敛）。策略改进用 q 表取 argmax：π_new[s] = np.argmax(q[s])。终止判据是策略逐状态相同：np.all(π_new == π)。读者可以对比 VI 与 PI 在同一网格上的收敛轮数：VI 需要几十轮（取决于 ε 与 γ），PI 通常 2 至 4 轮即收敛——但 PI 每轮要解一次方程组，总耗时未必更短；这正是 1.4 节"轮数 × 每轮成本"权衡的活例子，建议读者亲自记录两种算法的轮数与耗时。

手动演算一遍"价值扩散"，是理解动态规划直观图景的最佳方式。设 γ = 0.9，奖励约定同 1.5.1，初始 v_0 = 0。第 1 轮：只有到达目标格的动作产生正奖励，v_1(s9) = 1，其余格子价值为 0。第 2 轮：s9 的邻居"看见"目标——s8 向右 q = 0.9 × v_1(s9) = 0.9，s6 向右同样得 0.9（s6 虽是禁区，但站在禁区里继续向右一步即可到达目标），故 v_2(s8) = v_2(s6) = 0.9，其余格子仍为 0。第 3 轮：s5 向下到 s8，q = 0.9 × 0.9 = 0.81；s3 向左到 s6 或向下到 s8 方向（经 s6 到达），价值取 0.81；于是 v_3(s5) = v_3(s3) = 0.81。第 4 轮：s2 向下到 s5、s4 向右到 s5 或向上到 s1 方向，价值约 0.9 × 0.81 = 0.729，向更外层扩散……读者将清楚看到：价值从目标格出发，像水波一样逐圈扩散到整个网格，每外扩一圈乘以 γ——这正是动态规划中价值传播（value propagation）的直观图景，也是"价值迭代通过反复传播更新价值"这一本质的可视化。

价值扩散的过程也直接决定了策略箭头的形成。随着 v_k 逐轮扩散，每个格子的 argmax 逐渐稳定：s8 始终指向右（目标方向）；s6 指向右（目标方向）；s5 指向下（经 s8 到目标）——注意 s5 不会指向右进入禁区 s6，因为 q 值对比会显示"绕路更优"还是"穿禁区更优"取决于数值：在本设定中，从 s5 向下经 s8 到目标的总回报为 0.9 × 0.9 = 0.81，而从 s5 向右穿禁区再向右到目标为 −1 + 0.9 × 0.9 = −0.19，显然后者差，于是最优策略绕开禁区；但如果把 γ 调大、或者把目标奖励调高、或者把禁区惩罚调小，穿禁区的路径可能反超——这是一个绝佳的数值实验，读者可以修改参数观察最优路径如何翻转。这个例子深刻展示了 DP 的特性：一切权衡（绕路 vs 抄近路、短期代价 vs 长期收益）都被显式地转化为数字比较，而不是停留在直觉层面；中医临床中"效不更方、效差变方"的调方逻辑，与此如出一辙——基于疗效评估（价值）调整方案（策略），这正是 1.3 节策略迭代在临床决策中的朴素版本。

### 1.5.3 小结与衔接

代码实现的要点可以总结为五条。其一，数据结构先行：P、r、v、π 的 numpy 形状要统一，建议 P 用 (9,9,5)（s, s′, a）、r 用 (9,5)、v 用 (9,)、π 用 (9,)，注释标明每个轴的含义。其二，收敛判据用相邻两次迭代的差，ε 控制精度，γ 越接近 1 需要越小的 ε（见 1.2 节的误差上界公式）。其三，q 表计算是 VI/PI/TPI 共享的核心，务必抽象为公共函数。其四，输出要可视化：用 imshow 画价值热力图、用箭头画策略图，一眼就能看出"价值扩散"与"策略指向"，比打印数字直观得多。其五，常见错误要提前规避：忘记边界弹回（转移表错）、把进入禁区的奖励记成 0、argmax 平局处理不当（应约定取最小索引或随机）、同步更新误用了新值（应先算全部 q 再统一更新 v）。修正方法只有一个：先用小网格手算对照程序输出，逐项核对。把这几条内化，本节代码就可以作为模板复用到任何小规模 MDP 上。

本节为 Part2 的"VI 双网格实验"提供了全部代码素材。双网格实验的核心思想是：把九宫格替换为"症状—方剂网格"——状态变为症状组合、动作变为候选方剂、奖励变为证据等级——只需替换 P 与 r 的数据来源，算法代码一字不改。这正是"数据结构决定问题"的生动例证：同一个求解器，喂给它不同的环境描述，它就解决不同的问题。读者在完成本节代码后，应能熟练地：建立状态索引与转移表、填写奖励表、实现 VI 与 PI 的迭代循环、用相邻差判敛、输出价值热力图与策略箭头图。有了这套能力，进入 Part2 的平台实践将水到渠成——把"格子"换成"症状组合"、把"移动"换成"选方剂"、把"奖励表"换成"证据等级表"，网格世界的数学结构原封不动地迁移到中医辨证推荐的场景中。下一节将系统总结本章三个算法的对比，为进入平台实践做好理论收束。

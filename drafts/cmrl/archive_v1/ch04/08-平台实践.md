## [Part2] 平台实践与实训（实验指导）

### 8.1 实验目标与环境准备

本实验的目标有三：其一，用 numpy 实现价值迭代与策略迭代，在九宫格上复现"价值扩散"并输出策略箭头图，与书中手算结果逐项对照；其二，从 DSU 病证数据构建"症状—方剂网格"，把同一个 VI 求解器迁移到中医辨证推荐场景；其三，把 VI 最优方剂与 /semantic-search 检索 Top1 对比，检验"检索 ≈ VI 一步近似"的假说。环境准备按四步完成：① 安装依赖：pip install numpy pandas matplotlib（三者即可，无需训练框架）；② 选择解释器：务必使用 hermes venv python（C:\Users\DELL\AppData\Local\hermes\hermes-agent\venv\Scripts\python.exe），因为 SQLite FTS5 检索引擎在系统 Anaconda python 3.9 下会段错误，直接运行会出现程序崩溃或闪退——这是本实验最常见的失败点，若遇到崩溃请先检查 python 路径再检查依赖；③ 读取数据：从 tcmP/kg/samples/ 读取 dsu-samples-*.json（103+ 个病证单元）；④ 环境自检：运行一个最小用例——import numpy 成功、读入一个 DSU 文件、打印其 symptoms 与 recommended_formula 字段。自检通过后再进入正式实验，把"环境可用"与"代码正确"分开验证，能节省大量排错时间。

### 8.2 实验一：九宫格价值迭代

按四步完成九宫格 VI。第一步，构建转移矩阵 P（形状 (9, 9, 5)）：先写函数 next_state(s, a) 返回执行动作后的下一状态——注意边界弹回（越界动作返回原状态）与禁区 s6 可进入（s5 向右到 s6 合法）；再对每个 (s, a) 把 P[s, next_state(s,a), a] 置 1，其余为 0。第二步，构建奖励数组 r（形状 (9, 5)）：出界 −1（越界动作即使弹回也要罚）、进入禁区 −1、到达目标 +1、其他 0。第三步，价值迭代循环：v = zeros(9)；循环中计算 q[s, a] = r[s, a] + γ * sum(P[s, :, a] * v)，γ 取 0.9；v_new[s] = max(q[s])；π[s] = argmax(q[s])；若 max(|v_new − v|) < 1e−6 停止；否则 v = v_new。第四步，输出可视化：用 plt.imshow 画价值热力图（数值写在格内），用箭头或文字标出 π[s] 的方向。预期结果：价值从 s9 扩散，s9 = 1、邻格（s6、s8）≈ 0.9、次外层 ≈ 0.81；策略箭头全部指向目标方向，s5 指向下（绕开禁区）而非向右。常见错误与修正：转移表漏写弹回（与手算对不上，逐格核对）；argmax 平局处理不一致（约定取最小索引）；γ 误取 1（价值不收敛，检查 γ < 1）；同步更新误用新值（先算全部 q 再统一更新 v）。修正方法是唯一的：随机抽一个状态手算一轮，与程序输出逐项比对。

### 8.3 实验二：症状—方剂网格

把九宫格换成"辨证—处方"场景。第一步，构建状态集：从 DSU 数据挑选 10 个高频症状组合作为 S，例如失眠类——"入睡困难、多梦"、"心悸、乏力、易醒"、"心烦、口苦、难寐"等，每个组合对应一个"格子"。第二步，构建动作集：每个状态对应 5 首左右候选方剂（取自 recommended_formula 字段，不足的用检索 Top-K 补足），如失眠状态下的酸枣仁汤、归脾汤、天王补心丹、龙胆泻肝汤、安神定志丸。第三步，构建转移矩阵：定义"症状组合之间的转移"有两种方案——方案 a（教学用，推荐）：人为规定"趋近核心治愈状态"的转移，例如从"多梦"状态经"用对安神方"转移到"症状缓解"状态；方案 b（数据驱动）：用典型医案的 prognosis（转归）字段估计转移概率，样本少时需加平滑。第四步，构建奖励表：证据等级映射（A = 1.0、B = 0.7、C = 0.4）或直接取 /semantic-search 返回的检索证据分 rrf。然后运行与实验一完全相同的 VI 求解器，输出每个症状组合的最优方剂与价值。这一步的核心体验是：求解器一字未改，只是换了 P 与 r 的数据来源——抽象算法与领域数据在此解耦，这正是"数据结构决定问题"的工程含义。

### 8.4 对比与解读：VI 最优 vs 检索 Top1

把结果整理成对比表，列为五列：症状组合 | VI 最优方剂 | 检索 Top1 | 是否一致 | 解释。预期发现：大多数状态两者一致，差异集中在"需要多步累积价值"的状态——检索只看即时证据分（贪心的一步评估），VI 会累积"方剂把患者引向何方"的长期价值（多步评估）。例如某个状态检索 Top1 是即时证据分最高的方剂，但 VI 发现该方剂把患者导向疗效差的后继状态，转而选择即时分略低但长期更优的方剂——这就是"检索 ≈ VI 一步近似"的最直观证据。若时间允许，做两个扩展：其一，把奖励改为"证据分 + 转归分"的加权和再跑一次 VI，观察最优策略如何向长期倾斜，这模拟了 γ 增大的效果，对应临床"治本 vs 治标"的权衡；其二，取 j = 3 运行 TPI，比较它与 j = 1（VI）的收敛轮数与结果，验证"最优 j 通常不大"。讨论题：在什么情况下"贪心检索"会长期吃亏？请结合中医"急则治标、缓则治本"讨论即时证据与长期转归的冲突——这个讨论没有标准答案，但它是把本章数学与临床思维真正连接起来的思考练习。

### 8.5 实验报告模板与验收清单

实验报告按四部分组织：① 数据来源：所用 DSU 编号、字段、数量，以及数据边界声明（教学切片、非真实临床结局）；② 代码清单：VI 核心循环（建议控制在 20 行以内）与数据构建代码；③ 输出图表：九宫格价值热力图、策略箭头图、症状—方剂对比表；④ 结论讨论：检索与 VI 的关系、差异的解释、局限与改进方向。验收清单逐项自检：□ 实验一价值与手算一致（s9 = 1、邻格 0.9 模式）□ 策略箭头符合直觉（指向目标、绕开禁区）□ 实验二每个症状组合都有明确最优方剂输出 □ 对比表完成且给出不少于 2 条差异解释 □ 报告含数据边界声明。完成本实验后，读者应具备的能力是：把任意"状态—动作—奖励"三元结构（包括未来的真实临床数据）交给 VI/PI 求解，并能解释结果的临床含义——这套"建模 → 实现 → 验证 → 解读"的方法论，比任何单个算法都更具迁移价值，也是第 5 章无模型算法实验的共同起点。若实验一中某些状态的价值与预期不符，请优先检查转移表与奖励表；若实验二检索为空，请检查动作集与 DSU 字段是否匹配；若 FTS5 崩溃，回到环境配置步骤换解释器——按"环境—依赖—数据—算法"的顺序排查，绝大多数问题都能快速定位。

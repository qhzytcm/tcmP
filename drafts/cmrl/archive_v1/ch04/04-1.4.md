## [Part1] 1.4 截断策略迭代：统一框架

### 1.4.1 算法思想：评估深度是一条连续谱

把前两节放在一起对比，一个深刻的结构跃然纸上。价值迭代每轮只做一步价值更新，即"评估一步"；策略迭代每轮把价值评估做到收敛，即"评估到底"。两者看起来是截然不同的算法，但细看它们的骨架——都是"评估 + 改进"的循环，区别仅仅在于策略评估做了多少步。这一观察引出了本章的思想枢纽：截断策略迭代（Truncated Policy Iteration, TPI）。TPI 把"评估深度"抽象为一个参数 j：每一轮先对当前策略做 j 步价值迭代（称为截断的策略评估，truncated policy evaluation），再做一次策略改进。当 j = 1 时，评估只做一步，TPI 退化为价值迭代；当 j → ∞ 时，评估收敛到精确价值，TPI 退化为策略迭代。因此 VI 与 PI 不是两个无关的算法，而是同一个统一框架的两个极端，j 就是连接它们的连续谱上的坐标。书中以图 4.6 直观展示这一关系：横轴是截断步数 j，VI 在最左端，PI 在最右端，TPI 是中间的一切。

为什么需要这个统一视角？有三个动机。第一，理论统一：既然 VI 与 PI 是同一算法的特例，它们的收敛性就不必分别证明，可以在 TPI 框架下给出统一的论证——读者只需理解"截断评估 + 贪婪改进"这一个循环，就同时理解了三个算法。第二，计算权衡：VI 每轮便宜（O(|S|²|A|)）但轮数多，PI 每轮昂贵（解方程组 O(|S|³)）但轮数少，而 TPI 允许在两者之间自由滑动——可以用"略多的轮数"换取"每轮更便宜"，或用"略贵的每轮"换取"更少的轮数"，从而针对具体问题寻找总计算量的最优折中。第三，为无模型算法铺路：第5章起的蒙特卡洛、时序差分等方法，本质上都是 TPI 的某种近似实现——评估用采样数据替代模型计算，改进用近似贪婪替代精确 argmax；理解了 TPI，就拿到了理解后续所有算法的一把通用钥匙。可以说，本节是本章从"三个算法"上升到"一个框架"的关键一跃。

### 1.4.2 实现步骤：j 步截断评估加一次改进

TPI 的算法流程可以这样描述。输入：MDP、折扣率 γ、截断步数 j、精度阈值 ε；初始化：任取 v_0 与 π_0。对每一轮 k = 0, 1, 2, …：第一步，截断策略评估——固定策略 π_k，从当前价值估计出发做 j 步迭代：v_{k,l+1} = r_{π_k} + γP_{π_k} v_{k,l}，l = 0, 1, …, j−1，得到本轮评估结果 v_{k,j}；第二步，策略改进——用 v_{k,j} 计算动作价值 q(s,a) = r(s,a) + γ Σ_{s′} p(s′|s,a) v_{k,j}(s′)，并贪婪更新 π_{k+1}(s) = argmax_a q(s,a)。然后进入下一轮。元素形式的实现与价值迭代几乎相同，唯一的区别是：VI 每轮换一次策略、每个策略只更新一步价值；TPI 每轮固定一个策略、对同一策略连续迭代 j 步价值，再换策略。从代码角度，TPI 只是把 VI 的内层循环多加一层 j 次重复，因此实现成本极低——这也是它作为统一框架的工程便利性。

两个重要的实现细节值得强调。第一，截断评估的起点不必从零开始：v_{k,0} 可以取上一轮评估的结果（热启动，warm start），甚至取任意合理初值，因为贝尔曼算子是收缩的，起点只影响收敛速度不影响极限。热启动使 TPI 在工程上比 PI 灵活得多：PI 每次评估都要从零解一个方程组，TPI 则可以在前一轮估计的基础上继续逼近，计算量被分摊到各轮。第二，截断步数 j 的选取没有万能答案，需要结合问题调整：j 越大，每轮越接近 PI，总轮数越少，但每轮计算量线性增长；实践中常用较小的 j（如 5 至 20），也可以自适应——当相邻两次评估的差异已经小于某个阈值时提前停止本轮评估、直接改进，这等价于把"按步数截断"推广为"按精度截断"。还有一个深刻的观察支撑"小 j 足够"：策略改进只依赖价值估计的相对排序，不依赖绝对数值——价值还没精确，排序可能早已正确，因此评估不必做到收敛，只需做到"贪婪方向正确"。这个现象在 1.5 节实验里可以直观看到，也是理解 VI 高效性的关键。

### 1.4.3 收敛与性质：统一视角的回报

TPI 的收敛性可以统一地表述为：对任意固定的截断步数 j ≥ 1，在有限 MDP 中 TPI 收敛到最优策略。证明的思路与策略迭代一脉相承：截断评估得到的 v_{k,j} 虽然只是 v_{π_k} 的近似，但它是从某个起点做 j 步贝尔曼迭代的结果，与精确值之间的误差受收缩因子控制；由策略改进定理的连续版本可以证明，只要评估误差被控制在某个范围内，贪婪改进仍保证策略价值不降或至少不退化；结合有限策略空间，改进过程必然在有限步内终止于最优策略。严格的误差分析需要引入"评估误差上界"并验证其随轮次收缩，这里不展开全部细节，但读者应抓住本质：TPI 的收敛性来自两个力的平衡——贝尔曼算子的收缩性（保证评估逐步逼近真值）与贪婪改进的单调性（保证策略不倒退）。这两个力在 VI 与 PI 中分别以极端形式出现，在 TPI 中则以一般形式共存，因此统一框架不是把三个证明合并，而是揭示了三个证明共享的同一数学机制。

把三个算法放进统一框架，可以得到一组很有用的对比结论，请读者对照图 4.6 理解。其一，收敛轮数：j 越大，每轮评估越充分，需要的总轮数越少——VI 轮数最多，PI 最少，TPI 居中。其二，每轮成本：j 越大，每轮计算量越大——VI 最省，PI 最贵，TPI 居中。其三，总计算量 = 轮数 × 每轮成本，并不随 j 单调变化，实践中存在一个最优 j，通常不大（这也是"小 j 足够"直觉的量化来源）。其四，实现复杂度：VI 与 TPI 共享几乎相同的代码骨架，PI 需要额外的线性方程组求解器。这四条对比不仅适用于教学理解，也直接指导工程选型：模型已知且状态空间小，可用 PI 求精确解；状态空间稍大，用 TPI（中等 j）；状态空间大但模型仍已知，VI 或小 j 的 TPI 是务实选择；模型未知，则进入第5章的无模型世界，但届时"评估—改进"骨架与"截断"思想仍然适用。

TPI 对后续章节的启示值得单独强调。第5章的蒙特卡洛方法可看作"用采样经验估计 v_π"的截断评估——评估不再是解方程组，而是从数据中取平均，相当于把"模型计算"替换为"数据计算"，策略改进照旧贪婪。第7章的时序差分方法可看作"一步评估 + 增量更新"的特例——每步只用后继状态的一步估计来更新，正是 j = 1 的截断评估，同时用随机样本替代期望运算。更一般地，广义策略迭代（GPI）思想将贯穿全书：评估（部分完成即可）与改进（贪婪或近似贪婪）交替进行、互相促进，任何一方的"不精确"都可以被另一方补偿。读者若能带着这个框架进入后续章节，会发现每一个新算法都在回答同一个问题：在"评估"与"改进"这两个环节上，分别用什么替代了模型？这种提问方式比记忆单个算法更有价值。作为本节收尾，建议读者做一个对比练习：在网格世界上分别取 j = 1、j = 3、j = 100 运行 TPI，记录每种的轮数与总计算量，亲手验证"最优 j 通常不大"这一结论——这个练习将把图 4.6 从抽象图画变成自己的经验。

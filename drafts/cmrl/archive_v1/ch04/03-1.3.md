## [Part1] 1.3 策略迭代算法

### 1.3.1 算法思想：评估与改进交替循环

价值迭代每轮只把价值更新一步，策略迭代（Policy Iteration, PI）则采用另一种更"彻底"的思路：把"评估"与"改进"两个任务拆开，各自做到位，再交替循环。具体地说，PI 维护一个策略序列 π_0, π_1, π_2, …，每轮由两个步骤组成。第一步是策略评估（policy evaluation）：求解当前策略 π_k 的贝尔曼方程，得到其精确的状态价值 v_{π_k}。v_{π_k} 满足线性方程组 v = r_{π_k} + γP_{π_k} v，其中 r_{π_k} 与 P_{π_k} 是策略 π_k 下的即时奖励向量与转移矩阵——注意这是线性方程组，未知量 v 只以一次方出现，可以直接用线性代数求解，不需要迭代逼近。第二步是策略改进（policy improvement）：基于精确的价值 v_{π_k}，对每个状态贪婪地更新策略：π_{k+1}(s) = argmax_a q_{π_k}(s,a)，其中 q_{π_k}(s,a) = r(s,a) + γ Σ_{s′} p(s′|s,a) v_{π_k}(s′)。改进完成后再回到第一步，用新策略重新评估，如此循环，直到策略不再改变。

为什么"先评估精确、再改进"是合理的？关键在于策略改进定理（定理4.1）：对任意策略 π_k，若按贪婪规则构造 π_{k+1}，则 v_{π_{k+1}}(s) ≥ v_{π_k}(s) 对一切状态 s 成立，即改进后的策略价值不降；进一步，若对所有状态都有 v_{π_{k+1}}(s) = v_{π_k}(s)，则 v_{π_k} = v*，π_k 已经是最优策略。定理的直观证明并不难：对任意状态 s，v_{π_k}(s) = Σ_a π_k(a|s) q_{π_k}(s,a)，它是当前策略下各动作价值的加权平均，而加权平均不会超过其中的最大值 max_a q_{π_k}(s,a) = q_{π_k}(s, π_{k+1}(s))——也就是说，贪婪动作的价值不低于当前策略的价值；再用贝尔曼算子的单调性把这个不等式从单步推广到全程，反复代入 v ≤ r_{π_{k+1}} + γP_{π_{k+1}} v，取极限即得 v_{π_k} ≤ v_{π_{k+1}}。等号情形说明 v_{π_k} 满足 BOE，由唯一性即是最优。这个定理是全书最核心的定理之一，读者务必理解每一步：它把"贪婪改进总是无害"这一看似平凡的观察，严格地变成了"策略单调上升、直至最优"的收敛性证明。

### 1.3.2 实现步骤：矩阵形式与元素形式

策略迭代的完整流程可以用伪代码描述。输入：MDP、折扣率 γ；初始化：任取策略 π_0（如全取第一个动作）。循环 k = 0, 1, 2, …：第一步，策略评估，求解 v = r_{π_k} + γP_{π_k} v 得到 v_{π_k}；第二步，策略改进，对每个状态 s 计算 π_{k+1}(s) = argmax_a [ r(s,a) + γ Σ_{s′} p(s′|s,a) v_{π_k}(s′) ]；第三步，检查终止：若 π_{k+1}(s) = π_k(s) 对一切 s 成立，停止，输出 π_k；否则回到第一步。矩阵形式的策略评估写作 v_{π_k} = (I − γP_{π_k})^{−1} r_{π_k}：由于 γ < 1 且 P_{π_k} 是随机矩阵（每行和为 1，谱半径不超过 1），I − γP_{π_k} 必然可逆，因此解存在且唯一。元素形式则把方程组逐状态写出：对确定性策略 π_k(s)，v(s) = r(s, π_k(s)) + γ Σ_{s′} p(s′|s, π_k(s)) v(s′)，对每个 s 一个方程，共 |S| 个方程、|S| 个未知数；对随机策略，r_{π_k}(s) 与 p 的求和还要按 π_k(a|s) 加权。小规模问题用高斯消元或矩阵求逆即可，这是 1.5 节代码中采用的方式。

一个重要的实现细节：策略评估除了"精确求解方程组"，还可以用迭代法——固定策略 π_k，从任意初值出发迭代 v_{j+1} = r_{π_k} + γP_{π_k} v_j 直至收敛，得到的极限同样是 v_{π_k}。这后一种方式正是下一节截断策略迭代的原料：把迭代步数截断为 j 步，就得到 TPI；截断为 1 步、且每轮策略更新，就得到 VI。读者现在可以隐约看到三者之间的联系：PI 的"评估"与 VI 的"更新"都是贝尔曼算子作用，区别只在作用多少步、策略是否随轮更换。从计算复杂度看：策略评估用矩阵求逆为 O(|S|³)，用迭代法则每步 O(|S|²) 但需多步；策略改进对每个状态取 argmax，为 O(|S|²|A|)（每个动作对每个后继求和）。与 VI 对比：VI 每轮 O(|S|²|A|)，但通常需要很多轮；PI 每轮更贵，但轮数通常极少——实践中 3 至 10 轮即可收敛。读者应把"轮数 × 每轮成本"的总量看作评价指标，这正是 1.4 节 TPI 统一框架的工程动机。

### 1.3.3 收敛与性质：有限步收敛与实例演算

策略迭代最漂亮的收敛性质是有限步终止（定理4.2）：在有限 MDP（状态与动作均有限、模型已知）中，策略迭代在有限步内收敛到最优策略。证明只需要两条引理：其一，策略改进定理保证价值序列 v_{π_0}, v_{π_1}, v_{π_2}, … 单调不降，且一旦出现相等就已达最优；其二，有限 MDP 中的确定性策略总数是有限的——至多 |A|^{|S|} 个（随机策略虽然无限多，但贪婪改进总可以取确定性策略，所以只需考虑确定性策略）。价值严格上升的策略序列不可能无限长，因为策略空间是有限的，于是算法必然在有限步内到达一个"无法再改进"的策略，由改进定理的等号条件它即是最优策略。注意这里与价值迭代的差异：VI 在价值空间中迭代，误差按几何速度缩小但理论上需要无限多步；PI 在策略空间中迭代，每一步都严格前进一格，因此在有限策略空间中必然终止。理解这个区别，就能理解为什么实践中 PI 的轮数通常远少于 VI。

在网格世界上演算一遍，可以看清 PI 的全过程。取初始策略 π_0 = "总是向右"（边界弹回）。第 1 轮策略评估：解方程组求 v_{π_0}。以 s8 为例，它向右到 s9（+1），故 v(s8) = 0 + 0.9 × 1 = 0.9；s5 向右进入禁区 s6 得 −1，故 v(s5) = −1 + 0.9 × v(s6)（v(s6) 需与其他方程联立）；逐格列出 9 个方程解出全部价值。第 1 轮策略改进：在 s5 处比较各动作——向下到 s8 的 q 为 0.9 × v(s8) = 0.81，向右进禁区的 q 为 −1 + 0.9 × v(s6)，显然后者更差，于是 π_1(s5) 改为向下；类似地，s2 从"向右"改为"向下"（朝 s5 方向），s4 保持"向右"或改"向上"视价值而定。第 2 轮重新评估 π_1，价值整体上升，再改进……若干轮后策略稳定，得到从每个格子指向目标的最优箭头图。读者将看到 PI 的一个显著特征：每一轮的中间策略都是"合理"的——它总是在上一轮基础上改进，不会出现 VI 早期那种价值还没扩散、策略随意波动的情况。

策略迭代与后续无模型算法的联系值得提前点明。PI 的"评估—改进"循环在无模型时代并未消失，而是以广义策略迭代（generalized policy iteration, GPI）的形式继续存在：评估环节用采样估计替代模型求解，改进环节用近似贪婪替代精确 argmax，评估与改进交替进行、互相促进。第5章的 MC Basic 算法正是这一思想的直接体现：用回合回报的样本均值估计 v_π，再贪婪改进。因此，读者现在对 PI 的"评估必须精确"印象会在第5章被修正——评估可以近似，只要改进方向大致正确，算法依然收敛；这一宽松化正是 TPI 截断思想与 GPI 的共性。学完本节，读者应能独立完成：给定一个小规模 MDP，手算 PI 的前两轮，并解释为什么改进后的策略价值必然不降；同时应能说出 VI 与 PI 在"评估深度"上的差别——这是 1.4 节统一框架的直接入口。

## [Part2] 7.7 平台实践与实训：操作手册

### 7.7.4 实训准备与数据获取

本实训在 Python 3.9+ 环境下完成，核心依赖仅 numpy（Q 表实现），可选 requests（API 实查）。若 API 不可用，可回退到本地 tcm_embed（项目 scripts/tcm_embed.py，bigram 分词 + TF-IDF，零依赖），用症状文本与方剂文本的余弦相似度模拟证据分。开始前请确认三件事：其一，Q 表维度——本任务为 3 类症状（失眠/感冒/头痛）× 2 首候选方剂，故 Q 表为 $3 \times 2$ 矩阵，初始化 np.zeros((3,2))；建议先建立状态 ID 与动作 ID 的映射字典（如 {"失眠": 0, "感冒": 1, "头痛": 2}、{"方剂A": 0, "方剂B": 1}），避免直接用文本当索引。其二，奖励函数——推荐优先走实查路径：POST /semantic-search，请求体为 {"query": 症状文本, "candidates": [方剂A, 方剂B]}，响应中取 rrf 字段；请求失败时回退到本地余弦相似度。其三，审方模拟——若 /pharmacists/review 不可用，可用本地规则模拟：对预置的禁忌组合（如十八反映射表）返回 reject，其余返回 accept。

训练循环骨架如下（伪代码，与 7.5.2 节的 Q-learning 完全一致）：for episode in range(100): 随机选一个症状状态 s；ε = 0.5×(1−episode/100) + 0.05；while 未终止: 若 np.random.rand() < ε 则随机选动作 a，否则 a = argmax(Q[s])；r, s' = env.step(s, a)；Q[s,a] += α×(r + γ×max(Q[s']) − Q[s,a])；s = s'。参数起手：α = 0.1，γ = 0.9；终止条件：推荐被采纳（审方 accept 且模拟转归良好）或达到最大步数（如 5 步）。env.step 的内部逻辑：调用审方接口判 accept/reject，调用检索接口取证据分，合成奖励 r = 证据分 + 审方惩罚项，返回后继状态——后继状态可由真实对话流（用户回复构成下一状态）驱动，也可由预定义转移规则（如"失眠 → 复诊仍是失眠 → 治愈"的三态链）驱动，教学切片建议用后者以保证可复现。每轮记录：本轮平均 Q 值、最终推荐动作、与检索 Top1 的一致性。

### 7.7.5 代码实现要点与常见错误

实现要点有四。第一，ε-贪婪的正确写法：if np.random.rand() < ε 选随机动作，否则选 argmax；ε 的衰减放在 episode 循环外（按轮衰减）而非步循环内，否则每步都在衰减、探索迅速归零。第二，Q-learning 更新中的 max 处理：max(Q[s']) 用 numpy 广播 np.max(Q[s'])；当 s' 为终止状态时，终止行 Q 值全为 0，np.max 自然得 0——但要确保终止状态在 Q 表中有独立的一行（或显式判断后取 0），否则索引越界。第三，更新时注意"先取旧值再赋值"：Q[s,a] += α×(r + γ×np.max(Q[s']) − Q[s,a]) 中，右侧 Q[s,a] 是更新前的旧值，Python 的复合赋值语句天然保证这一点，但若手工写成两步则要小心不要用更新后的值。第四，奖励归一化：rrf 证据分先按批次 min-max 归一化到 [0,1]，再与审方结果合成——否则不同查询的奖励尺度不一致，α 的取值将失去意义。

常见错误与修正对照如下，请务必逐条检查。错误一：Q 表维度错——把方剂名直接当索引、或忘记给终止状态留行，报 IndexError 或静默更新错条目；修正：先建立 ID 映射，初始化前打印 Q.shape 核对。错误二：ε 未衰减或衰减过快——ε 固定 0.5 时收敛慢，ε 从 0.5 一步衰减到 0.05 时探索不足、可能锁死次优动作；修正：按轮线性衰减，并把 ε 曲线与收敛曲线一起绘制验证。错误三：α 过大导致震荡——α > 0.5 时 Q 值在两个极值间振荡不收敛；修正：降到 0.1 再试，观察曲线进入 ±0.05 带内是否震荡。错误四：奖励未归一化或负奖励权重不足——reject 只扣 0.1 时，负信号被证据分噪声淹没，Q 表无法学会回避禁忌方；修正：reject 取 −1、accept 取 +0.2，或直接硬约束（reject 后该条目 Q 值置 −∞ 量级）。错误五：回合边界处理——把"一轮对话"当成"一个回合"会导致回合过短、长期价值学不出来；修正：明确回合定义（首诊 → 复诊 → 转归）与终止条件，保证每个回合至少 2 步以上。排查顺序建议：先跑通单轮（打印每一步的 r、s'、更新前后 Q 值），再跑完整 100 轮，最后做对比实验——单步调试能暴露绝大多数上述问题。

### 7.7.6 实验设计与结果分析

实验设计建议包含两组对比与一项分析。对比一：探索策略——ε 固定 0.1、ε 固定 0.5、ε 从 0.5 衰减到 0.05 三组，每组独立运行 5 次取平均，绘制 Q 值收敛曲线与"最终推荐与检索 Top1 一致率"柱状图；预期结论：ε 衰减组一致率最高（前期充分探索、后期稳定利用），ε 固定 0.1 组可能因探索不足而错失更优方剂，ε 固定 0.5 组收敛最慢。对比二：学习率 α——取 0.05、0.1、0.3 三组，观察收敛速度与震荡幅度；预期结论：α 越小越稳但收敛慢，α 越大震荡越明显，0.1 附近是合理起点。结果分析的三项指标：其一，收敛性——每条 (s, a) 的 Q 值曲线是否进入 ±0.05 带内震荡；其二，一致性——3 类症状各自 argmax_a Q[s,a] 与检索 Top1 的命中情况，汇总为 3 行命中表；其三，负奖励效果——被审方 reject 的动作 Q 值是否显著低于被 accept 的动作。

验收标准：提交一份实验报告，包含环境封装说明（PlatformEnv 的关键代码）、三组 ε 对比的收敛曲线与一致率柱状图、α 敏感性表、每类症状的命中表，以及不少于 300 字的分析——重点回答三个问题：为什么 ε 衰减优于固定 ε？Q-learning 收敛到检索 Top1 说明什么？若收敛结果与检索 Top1 不一致，可能的原因是什么（提示：奖励合成权重、探索不足、检索分与长期疗效的偏差）？延伸任务（选做）：把状态扩展到 5 类症状、动作扩展到 5 首方剂，观察 Q 表规模扩大后收敛所需轮数的变化；或按 7.6.2 节的批量 TD 思想，离线重放 200 条真实问答日志，对比批量 TD 与在线 Q-learning 的收敛曲线——这将是平台 CI/CD 进化闭环的算法原型，也是本章"对话日志 = 训练数据"理念的最终验证。

## [Part2] 6.7 平台实践与实训

### 6.7.1 平台语境：在线学习的数学内核

随机逼近是 tcmP 平台"对话 = 进化信号"闭环的数学内核。平台的设计理念可以概括为一句话：每次问诊、每次检索、每次对话都是一条新样本，价值估计就地更新（w_{k+1} = w_k + α·误差）——不需要全量重训。这与本章 6.2 节增量均值估计的哲学完全一致：非增量方式要求攒齐全部数据再重新训练模型，在平台场景下意味着每次病证库更新都要重跑一遍训练管线、重新部署模型，延迟以小时计；增量方式每来一条对话日志就微调一次估计，延迟以毫秒计。平台之所以选择"对话 = 进化信号"而非"定期重训"，正是增量思想在工程上的胜利。具体而言，六者 Agent（医者、师者、学者、规者、侍者、志者）的行为参数可视为 w——例如医者 Agent 的推荐阈值、师者 Agent 的出题难度、志者 Agent 的学习路径排序权重；平台的对话日志就是样本序列 {x_k}——每次 /consult 问诊、每次 /semantic-search 检索、每次课程完成记录都是一条样本。SA 公式 w_{k+1} = w_k + a_k(x_k − w_k) 在平台上读作：新的行为参数 = 旧参数 + 步长 ×（新日志信号 − 旧参数）。

把本章数学逐一映射到平台组件，可以得到一张完整的对应表。增量均值估计 w_{k+1} = w_k + (1/k)(x_k − w_k) ↔ 平台对"某方剂对某证候的平均疗效"的在线估计：x_k 是第 k 条疗效反馈（来自复诊转归或证据等级），w_k 是当前疗效均值估计。RM 求根 g(w) = 0 ↔ 平台求解"推荐参数 w 使期望用户满意度为零误差"的问题：g̃ 是带噪声的满意度观测。Dvoretzky 格式 w_{k+1} = w_k − a_k(w_k − x_k) ↔ 平台对病证单元（DSU）检索得分的在线校准：x_k 是单次检索的证据分。SGD 优化 ↔ 平台六者 Agent 行为参数的在线调优：J(w) 是对话质量目标（如辨证准确率、用户留存），∇f(w_k, x_k) 是单条对话日志给出的梯度近似。平台上的"对话 → 日志 → 图谱 → Agent 调优 → 自动上线"CI/CD 闭环，本质是一个持续运行的 SA 过程：每个样本都被立即用于改进估计，估计改进后又影响后续样本的生成——这与本章"增量迭代 + 步长条件"的数学结构一一对应。理解了这个闭环，就理解了平台"越用越准"的设计原理：不是靠某一次大规模训练，而是靠每一次对话的增量修正。

### 6.7.2 平台接口：日志流与增量实现

把 SA 落到平台实现，需要四个接口要素。要素①日志数据流：平台每次 /consult（问诊接口）、/semantic-search（语义检索接口）调用都是一条样本，日志以结构化格式落盘（包含时间戳、会话 ID、查询内容、返回结果、用户行为），可导出分析；要素②增量实现：增量均值估计在 python 中是一行代码 w += (1/k)*(x - w)，零外部依赖、任何环境可跑，不需要数据库、不需要训练框架，这是 SA 方法在工程上的最大优势；要素③样本值来源：DSU 证据等级（evidence_level：A/B/C）映射为数值信号 1.0/0.7/0.4，或取 /semantic-search 返回的检索证据分（如 Top1 的融合得分），作为样本 x_k；要素④LLM 角色：DEEPSEEK_API_KEY 仅用于生成式增强（如生成辨证解释、润色推荐文案），增量学习本身零 token 消耗——这一点对平台成本控制至关重要：在线学习不该依赖昂贵的生成式推理，SA 的增量更新是纯数值计算。

步长设计是平台工程落地 SA 的关键决策，必须与本章收敛条件对应起来。平台上线初期，估计与真值可能相差很远，且系统需要快速适应新领域，此时可用较大步长（如常数 α = 0.1 或 0.2）快速逼近；进入稳定期后，应衰减步长（如 α = 1/k 或 α = 1/k^0.8），对应 SA 收敛条件"步长平方和收敛"——否则估计会在真值附近持续抖动，表现为平台推荐的"漂移"与不稳定。工程上常用的折中是"分段步长"：先以常数步长快速收敛，达到预设轮数后切换为衰减步长；或用"渐近常数步长"α_k = α_0/(1 + k/τ)，兼顾前期速度与后期稳定。读者应能指出：常数步长对应"收敛到邻域、不收敛到精确值"（SA 理论断言），衰减步长对应"以概率 1 收敛到精确值"——平台选择哪种，取决于业务上更需要"快速响应"还是"精确稳定"。另一个工程细节：日志数据可能含异常值（恶意请求、异常会话），增量更新对异常值敏感，实践中应加截断或权重（如对 |x_k − w_k| 过大的样本降权），这是 SA 理论中"噪声有界"假设的工程化保障。

### 6.7.3 本章实践：在线均值估计实验（任务设计）

实践任务：实现增量均值估计并观察收敛，用平台真实检索数据复现教材 6.2–6.4 节的全部核心思想。实验分四步。第一步，数据采集：对"失眠"系列症状（如"入睡困难""多梦易醒""心悸健忘""潮热盗汗"等 4–6 个查询）反复调用 /semantic-search 接口（或本地 tcm_embed 脚本），每次记录 Top1 结果的证据分，得到样本序列 {x_k}；建议每查询重复 10–20 次，获得 40–120 条样本。第二步，增量估计：用 SA 公式 w_{k+1} = w_k + (1/k)(x_k − w_k) 在线更新均值估计 w_k，记录每一步的 w_k 值；同时计算非增量全量均值 (1/n)Σ_{i=1}^{n} x_i 作为对照。第三步，绘制收敛曲线：横轴为样本序号 k，纵轴为 w_k，画出增量估计轨迹与全量均值水平线的对比图，观察增量估计是否快速逼近全量均值并最终重合——这正是 6.2 节等价性定理的可视化验证。第四步，步长策略对比：分别用常数步长（α = 0.5、α = 0.1）与 1/k 步长运行同一数据，对比三条收敛曲线——常数步长的估计在均值附近持续抖动、抖动幅度与 α 成正比，1/k 步长的估计收敛后基本静止——直观验证 RM 定理的两个条件：步长不衰减则噪声无法被平均掉（平方和条件失效），步长衰减过快则前期无法跟上（和条件失效）。

实验的预期结论与延伸方向要提前想清楚。预期结论有三条：① 增量均值与全量均值在样本数足够时重合，验证等价性；② 1/k 步长收敛后波动远小于常数步长，验证步长平方和条件的必要性；③ 常数步长下估计围绕均值波动而非精确停在均值上，验证"常数步长只收敛到邻域"。延伸方向有三个：其一，把"单条检索证据分"换成"多条检索得分的指数加权平均"，观察加权参数对收敛曲线的影响；其二，把样本换成"辨证正确与否的反馈"（1/0），估计"辨证准确率"的在线变化，这对应平台医者 Agent 的质量监控；其三，模拟"真值漂移"场景——人为让证据分在第 30 条样本后系统性升高，观察 1/k 步长与常数步长谁更快跟上漂移（答案：常数步长更快，但代价是稳定期波动更大——这正是"探索 vs 利用"在步长设计上的体现）。完成本实验，读者就完成了从"读懂 SA 公式"到"用平台数据验证 SA 定理"的闭环，详细的操作步骤与验收清单见下一节"平台实践与实训（实验指导）"。

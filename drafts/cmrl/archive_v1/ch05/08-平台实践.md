## [Part2] 平台实践与实训（实验指导）

### 8.1 实验目标与环境准备

本实验的目标有三：其一，从 teaching.typical_case 抽取 30 条"症状→方剂→疗效"episode，完成医案数据到回合样本的转换；其二，实现 MC 价值估计，按方剂分组计算疗效均值，并用增量更新形式验证等价，同时比较首次访问与每次访问两种统计口径；其三，把 MC 估计与病证库 recommended_formula、/semantic-search 检索分三方对比，检验"历史疗效统计"与"语义检索推荐"的一致程度。环境准备按四步完成：① 安装依赖：pip install numpy pandas matplotlib（三者即可，无需训练框架）；② 选择解释器：务必使用 hermes venv python（C:\Users\DELL\AppData\Local\hermes\hermes-agent\venv\Scripts\python.exe），因为 SQLite FTS5 检索引擎在系统 Anaconda python 3.9 下会段错误，程序直接崩溃或闪退——这是本实验最常见的失败点，若遇到崩溃先检查解释器路径，再检查依赖；③ 读取数据：从 tcmP/kg/samples/ 读取 dsu-samples-*.json（103+ 个病证单元），聚焦 clinical.prognosis 与 teaching.typical_case 字段；④ 环境自检：运行最小用例——import numpy/pandas 成功、读入一个 DSU 文件、打印其 typical_case 字段。自检通过后再进入正式实验，把"环境可用"与"代码正确"分开验证，能节省大量排错时间。

### 8.2 实验一：医案回合抽取与回报计算

按四步完成数据准备。第一步，解析：遍历 103 个 DSU 文件，从 teaching.typical_case 提取完整医案（症状列表、辨证、方剂、转归），从 evidence_level 提取证据等级，从 clinical.prognosis 提取转归描述；把每条医案组织成结构化样本 (症状组合, 方剂, 疗效, 证据等级)。第二步，回报量化：定义映射函数——疗效标签痊愈 = 1.0、好转 = 0.7、无效 = 0.3，或证据等级 A = 1.0、B = 0.7、C = 0.4；两种口径都实现，报告中注明采用哪一种，不得混用。第三步，分组：按 (症状组合, 方剂) 键分组，统计每组样本数 n；样本数 n < 2 的组在后续分析中标注"样本不足"。第四步，输出：打印分组统计表（症状组合 | 方剂 | 样本数 | 疗效均值 | 标准误），其中标准误用 5.2 节公式估算：若疗效是 0–1 之间的值，σ 保守取 0.5，标准误 ≈ 0.5/√n。常见错误与修正：字段名拼写不一致（读文件前先打印 keys 核对）、typical_case 是嵌套结构（先展平再解析）、症状列表含重复项（去重后再组合）——修正方法统一为"先打印一条样本，人工核对无误后再批量处理"。

### 8.3 实验二：疗效均值估计（MC 价值估计）

在分组数据上实现 MC 估计，分三步。第一步，批均值：对每组 (症状组合, 方剂)，直接计算 v̂ = (1/N)Σ G_i，得到疗效均值估计表——这就是 5.3 节 MC Basic 的平台版本，估计对象是 q(症状组合, 方剂)。第二步，增量验证：对同一组数据用增量式 q ← q + (G − q)/N 逐样本更新，比较两种计算的结果（应当完全一致），体会 5.4 节增量均值"旧估计 + 修正量"的含义——这一步是第6章随机逼近的伏笔，务必亲手跑一遍。第三步，口径对比：对同一证候在一条医案中出现多次的样本（如复诊记录），分别按首次访问（只取首访回报）与每次访问（全部回报纳入）统计，输出两张估计表，比较均值与方差差异；若数据中无重复访问，可在报告中说明"本数据集未触发口径差异，理论差异见 5.5 节"。输出后，用 5.2 节的公式做诊断：30 条样本分散到若干 (症状, 方剂) 组后，多数组 n 只有 1–5，标准误 0.22–0.5——直观回答"30 条样本的估计波动有多大"，并列出波动最小的前 3 组与波动最大的前 3 组。

### 8.4 对比与解读：MC 估计 vs 检索先验 vs 推荐方剂

把结果整理成三方对比表，列：症状组合 | MC 估计最优方剂 | 病证库推荐方剂 | 检索 Top1 | 是否一致 | 解释。检索分通过 /api/sages/semantic-search 对症状组合查询获得（或本地 tcm_embed.py 的 TF-IDF+FTS5+RRF 管线复现），记下 Top1 方剂及其分数。预期发现：多数症状组合三方一致——说明"语义匹配"与"疗效证据"在该组合上指向同一方剂，平台推荐可信；差异出现在两类情况：其一，样本不足的组合，MC 估计被少量样本左右，与推荐不一致是统计噪声所致，应归因于"数据不足"而非"推荐错误"；其二，语义相近但疗效证据不同的组合，如症状文本与某方剂高度匹配（检索分高）但历史病案显示疗效一般（MC 估计低）——这正是 off-policy 视角的临床版：检索分是"语义先验"，MC 是"疗效证据"，两者冲突时，数据边界与证据等级是裁决依据。讨论题：检索分与疗效估计各有什么局限？什么时候该信检索、什么时候该信疗效统计？在报告结论部分，把"MC 估计 ≈ 历史疗效的统计共识，检索分 ≈ 语义相似度先验"写成一句话，即完成本实验的核心解读。

### 8.5 实验报告模板与验收清单

实验报告按四部分组织：① 数据来源：所用 DSU 编号、字段、数量，以及数据边界声明——平台数据为教学切片，疗效标签为结构化字段而非真实临床结局，结论仅用于教学演示；② 代码清单：MC 价值估计核心循环（建议控制在 20 行以内）与数据解析代码；③ 输出图表：分组统计表、疗效均值估计表（批均值与增量各一张）、首次/每次访问对比表、三方对比表；④ 结论讨论：检索与疗效统计的关系、差异的解释、局限与改进方向（更多样本、重要性采样修正 off-policy 偏差、引入先验）。验收清单逐项自检：□ 30 条 episode 抽取完成且样本数与来源可追溯 □ 批均值与增量更新结果一致 □ 首次/每次访问两口径已比较（或已说明不适用）□ 三方对比表完成且给出不少于 2 条差异解释 □ 报告含数据边界声明。排查顺序固定为"环境—依赖—数据—算法"：环境问题查解释器与 FTS5，依赖问题查 pip 安装，数据问题打印字段核对，算法问题抽查一个分组手算。完成本实验后，读者应具备的能力是：把任意"症状—方剂—疗效"数据交给 MC 估计流程，得到带误差尺度的疗效排序，并解释它与检索推荐的关系——这套"建模 → 实现 → 验证 → 解读"的方法论，与 5.2 至 5.4 节的数学一一对应，是进入第6章增量学习与第7章时序差分实验的共同起点。

## [Part2] 5.7 平台实践与实训

### 5.7.1 平台语境：病案数据的统计学习

MC 方法与 tcmP 平台的病案统计学习几乎逐条对应，读者务必把 5.2 至 5.4 节的数学与下面的平台概念一一挂钩。平台中的 episode 是一次完整诊疗过程：就诊（症状采集）→ 辨证 → 处方 → 复诊转归。一次诊疗从症状采集开始，到复诊时看到转归结束，正是一条"有起点、有终点"的回合：状态是患者的症状组合（四诊信息），动作是辨证结论与所选方剂，奖励是疗效反馈（证据等级、转归好坏），状态转移是证候随治疗的变化。于是，从大量历史病案中估计"某方剂对某证候的疗效均值"，就是 MC 价值估计：v̂(症状组合, 方剂) = 该 (症状, 方剂) 组合下所有病案疗效回报的平均。这与 5.3 节 q̂_π(s,a) = (1/N)Σ G_i 逐字对应——平台不过把 (s,a) 换成了 (症状组合, 方剂)，把回报换成了疗效标签。平台的"数据驱动"方法论与 MC 的"无模型就用数据"哲学完全一致：平台不假设每种证候的转移概率已知，而是从病案统计中估计疗效；病案越多，估计越准——这正是 5.2 节大数定律在平台上的日常形态。医圣成长引擎的"经验积累"也由此获得数学含义：医圣画像的价值随病案样本的积累而收敛，正如 MC 估计随 N 增大而逼近真值。

平台数据中处处是 MC 概念的具体化。证据等级（evidence_level：A/B/C）正是历史样本的质量标签：A 级（大样本随机对照或多中心研究支撑）相当于高质量样本，B 级（非随机对照）与 C 级（专家经验、个案）相当于低质量样本——如果把证据等级映射为奖励（A = 1.0、B = 0.7、C = 0.4），疗效估计就是对这些带质量的回报取平均；而 teaching.typical_case 字段包含完整医案（症状→方剂→转归），是天然的 episode 数据源——30 余条典型医案就是 30 余条现成的回合，无需任何改造即可进入 MC 估计流程。病证库中 103 个病证单元（DSU）的临床字段（clinical.prognosis）提供转归描述，是构建回报与状态转移线索的原料。首次访问与每次访问（5.5 节）在临床也有自然的对应：同一证候在一份病案中可能多次出现（如复诊记录里"心悸"反复出现），统计疗效时按首次还是每次处理，就对应 first-visit 与 every-visit 的口径选择——同一份数据，两种口径可能给出不同的疗效估计，这正是 5.5 节讨论的现实版本。

### 5.7.2 平台接口：医案数据与采样

实现 MC 疗效估计所需的平台资源可以列成一张清单。① 数据读取：kg/samples 目录下 DSU（病证单元）的 clinical.prognosis（转归）与 teaching.typical_case（典型医案）字段，提供 30+ 条完整医案；DSU 采用六段式结构（病侧/证侧/桥接/临床/教学/治理），本实验主要用到临床段与教学段。② 采样工具：python random + pandas，从 103 个 DSU 构建 episode 集——把每条 typical_case 解析为"症状子集 → 方剂 → 疗效标签"的三元组，即一条回合；疗效标签是 DSU 中结构化字段（如转归痊愈/好转/无效），量化规则在 5.7.3 给出。③ 先验注入：/semantic-search 端点（/api/sages/semantic-search）的检索分数可作为 MC 估计的初值——检索给出"即时证据分"，MC 给出"长期疗效估计"，两者互补；把检索分作为贝叶斯先验、再被样本均值修正，正是"先验 + 数据"的经典结合（第6章增量更新里会再次见到这个思想）。④ 依赖：numpy/pandas 即可，无需训练框架；DEEPSEEK_API_KEY 仅用于生成式增强，本实验的算法部分零 token 消耗。

三条硬性提醒，请务必落实。其一，数据边界：平台数据为教学切片，疗效标签是结构化字段而非真实临床结局——实验报告必须注明"结论仅用于教学演示"，不得外推为真实疗效声明；这是医学数据处理的基本伦理，也是 5.7.3 验收清单的必查项。其二，环境选择：SQLite FTS5 检索引擎在系统 Anaconda python 3.9 下会段错误，务必使用 hermes venv python（C:\Users\DELL\AppData\Local\hermes\hermes-agent\venv\Scripts\python.exe）；若程序直接崩溃，先检查解释器路径再检查依赖——这是初学者最常见的失败点。其三，样本意识：103 个 DSU、30+ 条医案是小样本，估计的方差会很明显，这正是实验要观察的对象，而不是缺陷——用 5.2 节的 σ/√n 公式预先估算波动范围，是实验设计的必要一步。

### 5.7.3 本章实践：疗效均值估计（任务设计）

实践任务分三步，完整复现教材 5.2 至 5.4 节的思想，但数据来自平台真实病证库。第一步，抽取数据：从 teaching.typical_case 抽取 30 条"症状→方剂→疗效"episode，解析为结构化样本（症状组合、方剂、疗效标签、证据等级）。第二步，MC 价值估计：按方剂分组，对每组用回合回报均值估计 v(症状组合, 方剂)——疗效标签量化为回报（痊愈 = 1.0、好转 = 0.7、无效 = 0.3，或直接取证据等级 A/B/C → 1.0/0.7/0.4），同一 (症状, 方剂) 组合下多条病案取平均，即 v̂ = (1/N)Σ G_i；若一条病案中同一证候出现多次（复诊记录），可分别按首次访问与每次访问各算一遍，比较两种口径的差异。第三步，对比与解读：按估计值对方剂排序，与病证库 clinical.recommended_formula 字段（平台推荐方剂）逐一对比，解释一致与不一致的原因；再用 5.2 节的公式讨论样本量对方差的影响——30 条样本的均值估计波动有多大，增加样本或引入检索先验后如何改进。

实验设计的三个细节值得提前想清楚。其一，回报的量化口径要与平台字段对齐：疗效标签取 clinical.prognosis 的结构化字段，证据等级取 evidence_level，两者映射的奖励尺度要写进报告，不能混用。其二，on-policy 与 off-policy 的直觉对照：用"病案库现有数据"估计"推荐方剂的价值"，本质是 off-policy——数据由历史策略（医生习惯）生成，目标是推荐策略；若数据充足，可直接按 5.5 节引入重要性权重，若样本稀缺则先承认偏差、在报告中注明。其三，MC 估计与 /semantic-search 检索分的对比是实验的精华：检索分是"即时语义匹配"（相当于一步先验），MC 估计是"历史疗效统计"（相当于多步经验），两者的一致程度衡量"语义相似推荐"与"疗效证据推荐"的重合度——这是平台"检索 + 统计"双通道决策的实证基础。完成三步后，读者应能回答四个问题：一条医案如何变成一条样本？30 条样本的估计波动有多大？首次访问与每次访问的结果差多少？MC 疗效估计与检索分谁更可信、为什么？详细的操作步骤与验收清单见下一节"平台实践与实训（实验指导）"。

## [Part2] 9.8 中医药语境与职业应用

### 9.8.1 中医辨证的场景化理解

把本章概念放到中医临床场景中重新读一遍。辨证论治的过程天然是一个马尔可夫决策过程：望闻问切收集的四诊信息（舌象、脉象、症状、体征）构成状态 s；辨证结论与随之的方剂选择构成动作 a；患者的转归、复诊反馈、证候改善程度构成奖励 r。策略 π(a|s,θ) 在临床上正是"证-法-方"的映射：面对一组症状，经验丰富的医家并非只记一个答案，而是对不同治法分配不同的倾向——如同一组"入睡困难、多梦"的症状，肝郁化火者倾向龙胆泻肝汤，心脾两虚者倾向归脾汤，阴虚火旺者倾向天王补心丹。这种"同病异治"恰恰是策略分布的表达：状态相同（症状组合相近），动作不同（方剂各异），概率不同（由证型判断决定）。策略梯度理论给这个临床现象一个精确的数学注脚：最优策略未必是确定性的"症状→唯一方剂"，而可以是带概率的"症状→方剂分布"；当四诊信息不完整、证型判断存在歧义时，概率性推荐（Top-K 候选）比唯一答案更接近临床真实——这正是 9.2 节"随机策略可以是最优的"的中医版本。反过来，"异病同治"对应同一动作服务多个状态：参数化策略中，相近症状特征 φ(s) 经同一组参数映射到相近的方剂概率，泛化能力自动产生"方证相应"的迁移——见过"心悸失眠"的医者 Agent 面对"虚烦不得眠"时，无需重新学习就能给出合理推荐。

证据等级在 tcmP 平台中充当奖励信号：DSU 记载的证据等级越高（如权威医案、随机对照试验证据），对应推荐的奖励权重越大；证据等级低（如个人经验、单案报道）则奖励权重小。于是"辨证准确"被量化为"推荐方剂与高证据等级方剂的接近程度"，策略优化的目标 J(θ) 变成"长期推荐质量"——这与"最大化长期疗效指标"完全一致。tcmP 平台已有 60000+ 病证单元与 103+ DSU 教学切片，是典型的大状态空间：不可能为每个症状组合维护一个表格条目（表格策略的局限），必须用参数化策略（函数策略）——未入库的"新症状组合"通过 TF-IDF 向量映射到已有证型空间，策略自动给出合理推荐，这正是 9.1 节"函数策略泛化"的平台落地。医圣成长路径在算法语言下非常清晰：张仲景 SOUL 的六经辨证规则是策略先验（初始 θ 与可行域），/consult 对话日志是训练轨迹，药者审方与证据检索是奖励信号，策略梯度上升驱动"从规则复述到辨证风格"的进化——从表格（硬编码规则）到函数（参数化策略），从跟随到内化。

### 9.8.2 tcmP 平台映射与实训闭环

tcmP 平台为本章提供了完整的实训闭环。状态侧：症状组合由 tcm_embed 的 bigram 分词 + TF-IDF 向量表征（零依赖纯 numpy 实现），或使用平台预留的 BGE 中文模型接口获得语义 embedding——特征质量直接影响策略泛化，这正是 9.1 节 φ(s,a) 特征设计的工程对应。动作侧：方剂库中的每首方剂是一个离散动作；若未来扩展到剂量、疗程等连续变量，9.7 节的高斯策略便直接可用——方剂剂量的微调本质是连续动作，高斯均值给出推荐剂量、方差给出调整幅度，这在"药者-医者"联动中尤其有价值。奖励侧：/semantic-search 的 rrf 证据分提供连续奖励（推荐与循证依据的契合度），/pharmacists/review 的 accept/reject 提供离散奖励（安全合规性），二者合成多目标奖励——医者 Agent 必须在"疗效证据"与"用药安全"两个目标间平衡，这与现实医疗决策的约束结构一致。实训任务（9.7.3 的 REINFORCE mini 版）把三者串成闭环：抽样 DSU 案例→医者策略采样方剂→检索与审方打分→梯度更新→下一案例；200 回合后比较策略熵、J(θ)、与检索 Top1 的一致性，学员可以直观看到"策略从均匀探索到明确偏好"的收敛过程，也能亲手验证"基线降低方差"的理论结论。

职业应用方面，AI 工程岗位的 RL 应用场景集中在平台算法研发、模型训练与部署、检索与 Agent 工程三块。算法研发：策略梯度是方剂推荐排序的优化引擎——把"检索结果重排序"建模为策略，用点击/采纳反馈做奖励，训练排序策略；模型训练与部署：softmax 策略网络（或线性策略）在 numpy/torch 上训练后，导出为 ONNX 或平台内嵌模型，随 Agent 一起上线，注意部署时策略熵的监控（熵过低=过拟合单一行为，需回滚）。检索与 Agent 工程：策略与 /semantic-search 的混合架构是平台的主流模式——检索负责"召回证据"，策略负责"综合决策"，策略的输出分布可以作为检索结果的加权权重，实现"检索增强+策略学习"。方法与工具链：numpy/sklearn（线性 softmax 策略）、torch（深度策略网络）、gymnasium（把平台 API 封装为自定义环境）、W&B（训练曲线监控）。趋势适应：PPO 类信任域算法（9.5 节路径三）正成为 Agent 行为对齐的标准工具，离线策略评估（off-policy evaluation）解决"医疗数据难以在线采集"的约束，值得持续跟进。

药企研发岗位的 RL 应用场景以"六者·药者视角"展开。方剂优化：以疗效证据为奖励函数，在候选方剂/剂量组合空间上做策略搜索——策略梯度天然适合"组合爆炸"的配伍空间（数百味药、多种剂量），比穷举试错高效得多；疗效统计：奖励信号设计是核心工程——用真实世界证据（RWE）与临床试验数据构造奖励，把"有效率、复发率、不良反应率"折算为多目标奖励，注意折扣因子 γ 的选择反映"长期疗效 vs 短期症状缓解"的权衡。用药安全策略：十八反、十九畏、妊娠禁忌等构成策略的硬约束（可行域），药者 Agent 的策略在约束内优化——任何违反配伍禁忌的动作概率被置零（类似基线/信任域对更新的限制），这在数学上等价于"受限策略优化"（constrained policy optimization）。方法与工具链：临床试验历史数据构造离线训练集、模拟环境（virtual patient）做在线探索、策略评估报告（含方差与置信区间，呼应 9.4 节的方差分析）支撑审评决策。趋势适应：人机协同审方（AI 策略建议+药师复核）要求策略可解释——softmax 偏好分数天然可审计（每个方剂的概率贡献可追溯到特征），"策略概率可解释"正是策略梯度方法相比黑箱价值网络的职业优势。最后强调职业素养：医疗场景的策略学习必须守住安全边界（先验约束不可被梯度更新突破）、数据合规（患者数据脱敏）、以及"AI 建议不等于处方"的伦理底线——这与 9.2 节"策略梯度不是万能药"的冷静判断一脉相承。

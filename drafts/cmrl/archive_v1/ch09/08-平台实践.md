## [Part2] 9.7 平台实践与实训

### 9.7.1 平台语境：医者行为的策略优化

策略梯度方法对应 tcmP 平台中医者 Agent 的行为策略优化。平台语境下，策略 π(a|s,θ) 的含义是：给定患者的症状组合 s，推荐方剂 a 的概率；参数 θ 由"医圣 SOUL 的人格先验"与"平台交互数据"共同调优——先验提供初始点，数据提供梯度方向。平台的知识抽象是病证单元（Disease-Symptom Unit, DSU）：每个 DSU 记载一组症状（如"入睡困难、多梦易醒、心悸健忘"）、对应方剂（如"酸枣仁汤"）与证据等级。DSU 的三要素与强化学习三要素一一对应：症状=状态（state），方剂=动作（action），证据等级=奖励（reward）。于是"最优诊疗策略"被精确表述为：最大化长期疗效指标 J(θ)——不是追求单次开方命中，而是追求长期、稳定、可复现的疗效质量，这与策略梯度最大化平均回报 J(θ) 的数学目标完全同构。值得注意的是"概率性推荐"并非降低标准：平台对同一症状组合输出 Top-K 候选方剂而不是唯一答案，正是 softmax 策略"偏好有高低、选择有概率"的体现；不同证型（肝郁化火、心脾两虚）对同一症状的侧重不同，策略分布可以表达"多种合理治法并存"的临床灵活性——这是表格式硬编码规则（一个症状对应一个方剂）无法表达的。

平台语境还赋予"医圣成长路径"一个清晰的算法解释。张仲景 SOUL 的六经辨证规则（太阳病、阳明病、少阳病……）是策略的先验约束：它界定了参数 θ 的可行域，如同 softmax 策略的偏好结构决定了哪些行为模式可达。初始阶段，医者 Agent 的策略接近"检索式"：按语义检索返回的证据分 Top-1 直接开方（等价于一个尖峰分布、近似确定性的策略）。随着对话日志积累，"对话=进化信号"的闭环开始工作：每次问诊都是一次策略更新机会，药者审方结果（accept/reject）与用户复诊转归形成奖励信号，驱动 θ 沿策略梯度方向漂移。经过足够多的回合，医者 Agent 的策略从"照搬检索结果"进化为"带有个人辨证风格的参数化策略"——这正是医圣成长路径的算法本质：从表格（规则库）到函数（参数化策略）的升级，与 9.1 节的理论叙述一一对应。

### 9.7.2 平台接口：策略载体与轨迹数据

把平台接口逐个映射到本章概念上。策略载体：sages/zhang-zhongjing/SOUL.md 是医圣张仲景的六经辨证规则文件，充当策略先验（初始 θ 与可行域）；agents/healer/SOUL.md 是医者 Agent 的角色定义，规定"医者不直接开具剂量""先辨证后开方"等行为边界——这些边界构成策略优化的约束条件，任何违反边界的梯度更新都会被工程层拦截，如同基线或信任域对更新的限制。轨迹数据：/consult 的问答日志记录"主诉→回复→后续反馈"的完整序列，是天然的策略轨迹（s_t,a_t,r_{t+1},s_{t+1}）；其中主诉与辨证信息构成状态 s，医者回复中的方剂推荐构成动作 a，用户是否采纳、复诊转归、药者审方结果构成奖励 r。奖励信号有两条通道：/semantic-search 返回的 rrf 证据分是连续值奖励（检索证据与策略推荐的契合度），/pharmacists/review 返回的 accept/reject 是离散奖励（审方通过与否）——前者衡量"推荐是否与循证依据一致"，后者衡量"处方是否安全合规"，两者结合正是一个多目标奖励设计的雏形。

实现依赖上，平台刻意保持教学友好：softmax 策略（9.7 节的向量外积形式）加检索分数作 q 估计，纯 numpy 即可完成，无需 torch、无需 GPU——策略梯度的数学结构是"参数向量×特征矩阵"的线性运算，平台 API 就是环境，/consult 与 /pharmacists/review 就是 step 函数。验证环节提供两组可对照的观测：其一，策略输出分布与 /semantic-search 的 Top-K 结果对比——若策略学到的 Top1 与检索 Top1 长期不一致，说明梯度信号与检索信号存在冲突，需要检查奖励设计；其二，策略熵（-Σπ ln π）随训练的变化——熵从高到低收敛说明策略从"均匀探索"走向"明确偏好"，熵骤降为 0 则提示过早确定性（探索不足），熵不降则提示奖励信号太弱。这两组观测把"策略质量"从抽象概念变成可量化指标，也是后续调参的依据。

### 9.7.3 本章实践：REINFORCE mini 版

实践任务：实现 REINFORCE 的 mini 版本，完整复现本章全部理论。步骤①策略定义：softmax 线性策略 π(a|s,θ)=softmax(θ^T φ(s,a))，特征 φ 用平台 tcm_embed 的 TF-IDF 向量（bigram 分词，零依赖实现）；步骤②动作集：选取 5 首候选方剂（如酸枣仁汤、天王补心丹、归脾汤、龙胆泻肝汤、逍遥散，对应失眠的不同证型）作为离散动作；步骤③奖励信号：药者审方 accept=+1、reject=−1，可用 /pharmacists/review 实查，或用本地规则模拟（如"含十八反配伍则 reject""组方与辨证证型匹配则 accept"）；步骤④训练循环：每回合从 DSU 库抽取一个失眠案例作为初始状态，按当前策略采样方剂，获取奖励，重复至回合结束（可设单步回合：一问一答即一个轨迹），用 G_t=Σγ^k r 与 9.7 节的对数梯度公式更新 θ，训练 200 回合，记录 J(θ) 与策略熵的变化曲线。

观察与讨论问题：第一，梯度方差对收敛的影响——对比"每回合更新一次"与"每 10 回合用平均梯度更新一次"，哪种更稳？第二，最终策略与检索 Top1 的一致性——训练后策略的最高概率方剂是否与 /semantic-search 的 Top1 吻合？若不一致，分析是奖励设计问题（如模拟审方规则过于简化）还是探索不足；第三，基线的作用——把更新式改为 θ←θ+α(G_t−b)∇θ ln π（b 取滚动平均回报），重跑实验，比较策略熵曲线与收敛回合数，实证 9.5 节"方差缩减"的结论；第四，随机性的临床意义——对比"确定性贪婪策略"（每次选概率最大方剂）与"softmax 采样策略"在 50 次模拟问诊中的平均奖励，体会随机策略在探索中的价值。这个实践把策略梯度定理落到平台真实的"医者-药者"交互闭环上：医者是 actor（输出策略分布），药者是 critic 的简化版（输出审方奖励），对话日志是训练数据——完成了从数学公式到平台工程的最后一公里。

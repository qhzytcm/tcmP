## [Part2] 平台实践与实训

在 tcmP 中医医院 AI 网络教育平台中，网格世界的思想被映射为"医圣成长路径"。状态不再是格子，而是医师当前的成长水平：从住院医-1 到学科带头人，对应平台中六类角色的能力画像——掌握的病证数从 500 个增长到 60000 个。动作是医师的学习与诊疗决策：选择哪门进修课程、在辨证时给出哪个证候判断、推荐哪首方剂。奖励来自临床反馈：辨证正确得正奖励，误诊得负奖励，考核通过得正奖励。平台的终极目标，是帮助每位医师找到从当前水平到最优水平的成长策略——这与智能体在网格世界中寻找最优路径的目标完全同构：都是在未知环境里靠试错学习出覆盖所有状态的策略。读者不妨把"医圣成长路径"当作网格世界的放大版：状态更多、动作更丰富、奖励更真实，但数学结构完全一致——理解了九宫格，就理解了成长路径的骨架；反过来，理解了成长路径，也就理解了网格世界的现实意义。平台实验中，成长水平与病证数正是可直接观测的状态变量，实验前请先明确观测对象。

平台用结构化数据承载状态空间。病证单元（Disease-Syndrome Unit, DSU）的六段式结构（病侧/证侧/桥接/临床）定义了状态空间——症状组合即状态。一个状态可以写成 {"symptoms": ["恶寒重", "发热轻", "无汗"]} 这样的症状组合：医师在临床上遇到的每个症状组合，对应网格世界中的一个格子。平台知识库中这样的病证单元超过 60000 个，正是"医圣成长路径"要遍历的"格子"；住院医只熟悉其中约 500 个，而学科带头人几乎覆盖全部。读者可以对照 1.2 节：状态空间 S 在平台中就是症状组合的集合；状态设计（症状如何选取、如何组合、粒度粗细）直接决定后续学习的可行性——症状选得太多组合爆炸，选得太少又丢失辨证必需的信息，需要在表达力与可行性之间取得平衡，正如 1.2 节所说“状态是决策所需信息的浓缩”。建议从 10 个高频症状组合起步，规模虽小，已足以演示状态空间的结构。若时间允许，再扩展到 20 个组合，对比两套状态集的实验差异。

方剂与证据等级则对应动作与奖励。方剂字段（formula）定义了动作空间——推荐哪首方剂，相当于网格世界中的"移动一步"；证据等级（evidence_level）映射为奖励：A 级 = 1.0，B 级 = 0.7，C 级 = 0.4。数据来源是 tcmP/kg/samples/ 下的 dsu-samples-*.json（103+ 个真实病证单元）。平台的数据接口即环境的"物理规则"：语义检索端点 /api/sages/semantic-search 返回的证据分 rrf，可以作为奖励信号的真实来源。这与 1.5 节的奖励表一一对应：证据等级表就是平台版奖励表，检索分数就是平台版即时奖励。读者在做实验时，应当把自己想象成"环境设计者"：你如何写奖励表，平台就如何引导医师学习——奖励表的每一格，都是你与学习者之间的一次"对话"；这正呼应 1.5 节“奖励是人机接口”的核心思想。若证据分缺失，可先以证据等级映射兜底，再逐步替换为真实检索分。

进行平台对接实验前，需要完成环境配置：① 安装依赖：pip install numpy pandas matplotlib（基础）；如需标准 RL 环境可安装 gymnasium。② 配置 LLM：设置环境变量 DEEPSEEK_API_KEY 激活平台的 DeepSeek 对话能力；注意密钥不写入代码或文档，以免泄露。③ 准备数据：从 tcmP/kg/samples/ 读取真实病证单元。④ 注意运行环境：平台检索引擎（SQLite FTS5）在系统 Anaconda python 3.9 下会段错误，务必使用 hermes venv python（C:\Users\DELL\AppData\Local\hermes\hermes-agent\venv\Scripts\python.exe）。这一步配置是初学者最常见的失败点：如果直接运行报"段错误"或崩溃，先检查 python 环境是否切换正确，再检查依赖是否安装齐全，最后确认数据路径无误——按"环境—依赖—数据"的顺序排查，绝大多数问题都能快速定位。配置完成后，建议先运行一个最小检索用例验证环境可用，再进入正式实验；把"环境可用"与"代码正确"分开验证，能节省大量排错时间。

本章实践任务：把"辨证→方剂"建模为一个网格世界。① 用真实 DSU 数据构造状态集：选取 10 个高频症状组合作为 S。② 构造动作集：选取 5 首候选方剂作为 A。③ 奖励表由 /semantic-search 的检索证据分填充：对每个症状组合查询 Top-K 方剂，把证据分 rrf 写入奖励表。④ 对照书中 1.3 节的转移表与 1.5 节的奖励表，用 Python 字典构建 S、A、r 三个数据结构。⑤ 编写一个简单的随机策略模拟器：以 0.2 均匀概率从 5 个动作中随机选择，输出若干条轨迹与回报，验证 1.6 节"回报评价策略"的思想——你会发现，随机策略的回报往往低于任何有目的的策略，这正是"策略"价值的直观证据。通过这个实践，体会原文"奖励是人机接口"的思想在平台中的具体含义：奖励设计 = 对平台行为的引导——你如何映射证据等级，决定了平台会引导医师学会什么样的辨证策略。完成随机策略模拟后，再按 1.4 节构造一张简单策略表并比较回报，体会“策略越有目的，回报越高”的规律。

实验输出与验收标准如下，读者可按此自检。① 模拟器应输出若干条完整轨迹：每条轨迹包含状态序列、动作序列、奖励序列与最终回报，格式与 1.6 节轨迹示例一致。② 正确性检验：随机抽取一条轨迹手算回报，与程序输出对照；核对转移表与奖励表的每一项，保证字典与书中表 1-1、表 1-2 的约定一致。③ 边界情形：轨迹应始终停留在状态集内（对应 1.3 节"状态空间封闭"），不应出现未定义的状态。④ 常见问题排查：奖励表缺失项会导致回报异常，动作空间与 DSU 不匹配会导致检索为空，FTS5 崩溃则回到环境配置步骤。⑤ 拓展方向：把随机策略换成 1.4 节给出的确定性策略表，比较两者的平均回报；再换用 1.6 节的不同 γ 值，观察回报如何变化——这一步会让本章的概念在数据中"活"起来，也是进入第 2 章状态价值学习的自然衔接。请把每次实验的输出与回报记录成表，作为本章实践报告的一部分提交。报告应包含数据来源、代码清单与结论讨论三部分，缺一不可。

## [Part2] 10.7 平台实践与实训：操作手册

### 10.7.4 实训准备与数据获取

本实训在 Python 3.9+ 环境下完成，核心依赖仅 numpy（softmax 策略 + 线性 critic），可选 requests（平台 API 实查）。若 API 不可用，回退到本地 tcm_embed（scripts/tcm_embed.py，bigram 分词 + TF-IDF，零依赖），用症状文本与方剂文本的余弦相似度模拟证据分，用预置禁忌表（十八反、十九畏映射）模拟审方。开始前确认四件事。其一，状态与动作映射：本任务为 3 类症状组合（失眠：入睡困难、多梦、心悸；感冒：恶寒发热、头身痛、脉浮；头痛：头痛、项强、脉弦）各配 3~5 首候选方剂，建立状态 ID 与动作 ID 字典，避免用文本当索引。其二，环境封装：定义 PlatformACEnv 类，step(s, a) 内部依次调用语义检索（证据分，min-max 归一化到 [0,1]）与审方规则（禁忌 → reject），合成奖励 $r = \text{证据分} - \beta \times \mathbb{1}_{\text{reject}} + \text{转归}$，并返回后继状态——后继状态由预定义转归链驱动（首诊 → 复诊 → 好转/未愈 → 终止），保证实验可复现；学习器只与 env 交互，平台 API 细节藏在环境内部，保持"算法与平台解耦"。其三，参数起手：$\gamma = 0.9$，$\alpha_w = 0.1$，$\alpha_\theta = 0.01$——两时间尺度是 AC 的命门，$\alpha_w$ 要比 $\alpha_\theta$ 大 5~10 倍。其四，数据记录：每轮记录平均规者评分、合规率、策略熵、最终推荐与检索 Top1 的一致性。

训练循环骨架（伪代码，与 10.3 节 A2C 完全一致）：初始化 $\theta, w$；for episode in range(200)：随机选一个症状状态 $s$；while 未终止：由 softmax 策略采样 $a$（或 $\varepsilon$-贪婪，$\varepsilon$ 从 0.3 衰减到 0.05）；(r, s') = env.step(s, a)；$\delta = r + \gamma\hat{v}(s',w) - \hat{v}(s,w)$；$w \leftarrow w + \alpha_w \delta \nabla_w \hat{v}(s,w)$；$\theta \leftarrow \theta + \alpha_\theta \delta \nabla_\theta \ln \pi(a|s,\theta)$；$s = s'$。终止条件：转归链到达"好转"或"未愈"终态，或达到最大步数（如 5 步）。每个 episode 记录上述四项指标，训练结束后绘制全部曲线。

### 10.7.5 代码实现要点与常见错误

实现要点有五。第一，两时间尺度：$\alpha_w$ 与 $\alpha_\theta$ 必须分开设置并保持 $\alpha_w \gg \alpha_\theta$；把两者设成同一个值是最常见的"看起来能跑、实际上不收敛"的错误。第二，softmax 梯度的正确实现：$\nabla_\theta \ln \pi(a|s,\theta) = e_a - \pi(\cdot|s,\theta)$（one-hot 向量减概率向量），用 numpy 的向量操作一次完成，不要手工逐分量推导——10.1.3 节已经演示了手工推导极易出错。第三，优势信号：本任务用单步 TD 误差即可；若想体会 A3C 的 n 步优势，把 $\delta$ 换成 $\hat{A}_t = \sum_{k=0}^{n-1}\gamma^k r_{t+k+1} + \gamma^n\hat{v}(s_{t+n}) - \hat{v}(s_t)$，$n = 3$ 起步，观察偏差-方差权衡。第四，硬约束：审方 reject 时把 $\delta$ 直接置 $-M$（如 $-10$）或屏蔽该动作的 actor 更新——药者红线不可被梯度"谈判"；同时把该 (s, a) 加入禁忌记录，后续采样直接排除。第五，奖励归一化：证据分按批次 min-max 到 [0,1]，reject 惩罚 $\beta$ 取 1.0 以上，否则负信号被证据分噪声淹没。

常见错误与修正对照如下，请逐条检查。错误一：单学习率 → 策略参数震荡发散；修正：分开设置 $\alpha_w = 0.1$、$\alpha_\theta = 0.01$，并同时绘制 $w$ 与 $\theta$ 曲线核对"价值先稳、策略后动"的两层节奏。错误二：softmax 梯度符号或归一化错误 → 策略朝错误方向漂移；修正：用 $e_a - \pi$ 向量形式，单步打印核对 $\Delta\theta$ 的符号是否符合"高价值动作概率上升"。错误三：用 $\hat{q}$ 加权代替优势（未减基线）→ 高价值状态的全体动作都被推高，策略随机漂移（10.3.3 节自环对照）；修正：一律使用 $\delta$。错误四：证据分未归一化或尺度不一致 → 学习率失效；修正：批次 min-max 归一化并打印奖励分布核对。错误五：reject 惩罚太轻 → 策略学会"擦边"处方；修正：$\beta \ge 1$ 或硬屏蔽。错误六：回合边界混乱 → 长期价值学不出来；修正：明确定义转归链与终止条件，保证每轮至少 2 步。排查顺序：先跑单轮并打印每一步的 $(s, a, r, s', \delta, \Delta w, \Delta\theta)$，再跑完整训练，最后做对比实验——单步调试能暴露绝大多数上述问题。

### 10.7.6 实验设计与结果分析

实验设计建议包含三组对比与一项进阶。对比一（评价信号）：无 critic（REINFORCE 式，用完整转归回报 $G_t$）vs QAC 式（$\hat{q}$ 加权）vs A2C 式（$\delta$ 加权）三组，每组独立运行 5 次取平均；预期结论：A2C 组收敛最快最稳、平均评分最高，REINFORCE 组方差大、需更多轮，QAC 组在状态价值差异大的症状组合间出现波动。对比二（两时间尺度）：$(\alpha_w, \alpha_\theta)$ 取 $(0.1, 0.1)$、$(0.1, 0.01)$、$(0.1, 0.001)$ 三组，观察 $\alpha_w = \alpha_\theta$ 组是否震荡、$\alpha_\theta$ 过小组是否收敛过慢。对比三（双 critic）：单规者 critic vs 规者 + 药者双 critic，观察合规率曲线与"擦边处方"出现频次。进阶实验：状态扩展到 5 类症状、动作扩展到 5 首方剂，观察参数规模扩大后收敛所需轮数的变化；或把 $n$ 步优势（$n=3$）与单步对比；或离线重放 200 条真实 /consult 日志做批量更新（异策略 + 重要性采样），验证"日志 = 训练数据"的平台进化理念。

验收标准：提交实验报告，包含环境封装关键代码（PlatformACEnv.step）、三组评价信号对比的收敛曲线与平均评分柱状图、两时间尺度敏感性表、双 critic 合规率对比、每类症状的"最终推荐 vs 检索 Top1"命中表，以及不少于 300 字的分析——重点回答三个问题：为什么两时间尺度是 AC 的必要条件？A2C 的优势信号相对 QAC 的 $\hat{q}$ 加权到底改进了什么？双 critic 如何同时约束疗效与安全？延伸思考（选做）：若规者评分只奖励床位周转率，医者策略可能学到什么"奖励黑客"行为？应如何设计奖励与约束加以防范？——这个问题直接通向 10.8.5 节的医院管理应用，也是本章"评价机制决定学习行为"结论的最深刻注脚。

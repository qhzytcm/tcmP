## [Part2] 10.7 平台实践与实训：tcmP 平台的六者 AC 闭环

### 10.7.1 平台语境：医者 actor 与规者 critic

本章是全书中与 tcmP 中医药智能平台贴合度最高的一章：actor-critic 的双模块结构几乎是平台六者架构的算法画像。在平台中，actor 由医者 Agent（agents/healer）承担——它是辨证与方剂推荐的决策主体，是六者协同的核心枢纽；critic 则由两个 Agent 共同承担——规者 Agent（agents/regulator）负责质控评估，药者 Agent（agents/pharmacist）负责处方审核。这一分工不是工程巧合，而是医疗质量管理"决策与评价分离"的制度设计在软件中的投影：开方者与审方者分离、医生与质控者分离，防止"既当运动员又当裁判员"。病证单元（DSU）为状态、动作与奖励提供了知识载体：症状组合即状态 $s$，候选方剂即动作 $a$，证据等级映射分即奖励 $r$——平台病证库中 60000+ 病证单元（教学切片 103+）的每一个，都内含"症状→方剂→证据等级"三元组，这正是 AC 学习所需的 (s, a, r) 数据源。医圣成长路径则对应 AC 的"先验初始化 + 在线进化"：医圣 Agent（sage-zhang-zhongjing）的 SOUL 人格（六经辨证规则）作为策略先验构成 actor 的 $\theta_0$ 与可行域，病证库证据分作为 critic 的 $w_0$，随后由真实对话驱动在线调优。

平台"对话 = 进化信号 → Agent 调优 → 质控验证 → 自动上线"的 CI/CD 闭环，正是 AC 的工程实现。每次患者与医者 Agent 的对话都是一次策略更新机会：状态 = 患者症状 + 上下文（主诉、既往史、user_level），动作 = 推荐的辨证结论与方剂，奖励 = 用户反馈（采纳、复诊转归、审方结果）。医者推荐方剂后，药者审核、规者质控、患者转归依次发生，于是产生 TD 误差 $\delta = r + \gamma\hat{v}(s') - \hat{v}(s)$：$\delta > 0$ 说明本次辨证开方优于当前策略的平均水平，actor 调高该方剂的概率；$\delta < 0$ 则调低。日复一日，无数对话的 $\delta$ 汇聚成策略的持续进化，而质控指标（处方合规率、床位周转率、复诊依从性）与基线对比，正是"优势 = 优于平均"的平台化表达——规者给出的是相对评价而非绝对分数。药者的十八反拦截则构成 critic 的硬约束：一旦触犯配伍禁忌，该 (s, a) 的优势直接置为极小值或屏蔽，无论证据分多高——这条"不可越界的价值评估"对应 AC 中基线之外的不可谈判规则，也是平台安全边界的算法化。

### 10.7.2 平台接口：actor/critic 载体与数据

把理论落到工程，需要熟悉平台的四组接口。其一，actor 载体：agents/healer 的辨证与方剂推荐逻辑，其 SOUL 人格边界（如"医者不直接开具剂量""推荐须附证据等级")是策略可行域的先验约束——对应 AC 中"参数只允许在可行域内更新"。其二，critic 载体：agents/regulator 的质控评估端点 /agents/regulator/quality（返回处方合规、质控指标得分）与 agents/pharmacist 的审方端点 /pharmacists/review（返回 reject/accept），前者是连续值的疗效/质量信号，后者是离散的安全信号。其三，观测数据：/consult 问答对（主诉 → 回复内容，字段含 user_level）构成 (s, a) 序列，质控指标值与复诊转归构成奖励序列；语义检索 /semantic-search 返回 rrf 证据分，可归一化到 [0,1] 作为连续奖励。其四，实现依赖：numpy 即可完成（softmax 策略 + Sarsa/TD critic 都是向量与矩阵运算），无需 GPU 与强化学习库——平台 API 本身就是环境。

奖励合成与硬约束是平台实践的关键工程决策。多信号合成公式可取 $r = w_1 \times \text{证据分} + w_2 \times \text{审方结果} + w_3 \times \text{转归}$，权重体现目标导向：若实验目标是"复现检索最优"，证据分权重占主导；若目标是"安全优先"，审方结果应设为硬约束（reject 时直接屏蔽动作或把 $\delta$ 置为 $-M$）。语义检索 /semantic-search 在此承担双重角色：对 actor，检索 Top1 可作为初始策略的贪婪动作——"按检索 Top1 开方"的规则策略正是 10.7.3 节 actor 的初值；对 critic，检索证据分为价值估计提供先验奖励。医圣 SOUL 的六经辨证规则（sages/zhang-zhongjing）则把名医经验编码进 $\theta_0$ 与可行域——这正是"初始化为先验知识、在线更新为经验学习"的强化学习范式在中医药场景中的落地。数据规模说明：当前为教学切片（103+ DSU），60000+ 全量图谱在云端，但算法结构不变——这正是函数近似（第8章）相对表格法的意义所在。

### 10.7.3 本章实践：六者 AC 闭环模拟（设计）

本节实践的目标是模拟六者平台的 AC 闭环，把本章全部理论落到平台架构上，完成从理论到平台的"最后一公里"。任务设计如下。第一，actor：初始为规则策略——按语义检索 Top1 开方；用 softmax 参数化 $\pi(a|s,\theta) = \text{softmax}(\theta \cdot \phi(s))_a$，其中 $\phi(s)$ 为症状文本的 TF-IDF 特征（本地 tcm_embed 或平台接口），$\theta_0$ 设置为使检索 Top1 对应动作概率最高的值（可用 one-hot 初始化后加小噪声）。第二，critic：规者评分函数——基于处方合规与质控指标构造 $\hat{v}(s,w)$，线性近似即可，$w_0$ 用病证库证据等级分初始化。第三，每轮门诊：状态 $s$（症状组合）→ actor 推荐方剂 $a$ → 规者评分 $r$ → 转归 $s'$（预定义转归链：首诊 → 复诊 → 好转/未愈 → 终止）→ 计算 $\delta = r + \gamma\hat{v}(s',w) - \hat{v}(s,w)$ → 更新 critic $w$（TD）与 actor $\theta$（优势加权）。第四，观察目标："质控反馈 → 医者策略改进"的收敛过程——绘制平均质控评分、处方合规率与策略熵曲线，验证 $\delta$ 是否驱动策略向高评分方向演化，这就是平台 CI/CD 进化闭环的算法原型。

进阶任务加入药者 critic，构成双 critic 结构。药者审方结果（reject/accept）作为硬奖励：accept 正常参与奖励合成，reject 时 $\delta$ 直接置 $-M$ 或跳过 actor 更新。对比实验设计为"单 critic（只有规者）vs 双 critic（规者 + 药者）"：观察单 critic 下策略是否出现"合规但低效"或"高效但擦边"（如频繁推荐证据分高但配伍违规的方剂）的行为，双 critic 下合规率是否显著上升。双 critic 的工程意义正是 10.6.2 节风险清单的落地：效率与安全分别由不同评价器约束，任何单一指标被过度优化的风险都得到对冲。评价指标建议三个：平均规者评分（收敛目标）、处方合规率（安全约束）、最终推荐与检索 Top1 的一致率（先验保持度）。具体的数据准备、代码骨架、常见错误与实验报告要求，见 10.7.4 至 10.7.6 节。

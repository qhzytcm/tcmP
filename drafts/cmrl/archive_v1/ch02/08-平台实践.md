## [Part2] 2.7 平台实践与实训

### 2.7.1 平台语境：状态价值即临床价值

把第2章的数学概念映射到 tcmP 中医医院 AI 网络教育平台，首先要找到状态、动作、奖励三个要素的平台对应物。在平台中，状态是病证单元（Disease-Syndrome Unit, DSU）的症状组合：一个 DSU 用六段式结构建模（病侧、证侧、桥接、临床），其中"症状组合"相当于 MDP 的状态，平台的病证库承载 60000+ 个这样的病证单元；动作是医师的诊疗决策，在 DSU 中对应方剂字段（formula）——辨证之后选择哪首方剂，就像网格世界中在某个格子选择向哪个方向移动；奖励来自临床反馈，平台用证据等级（evidence_level）映射为数值奖励：A 级 = 1.0，B 级 = 0.7，C 级 = 0.4。有了这三个对应，第2章的核心结论就全部获得了临床含义：状态价值 vπ(症状组合) 表示按诊疗路径 π 处理该症状组合时能够获得的期望疗效回报——它回答"这个症状组合在当前的诊疗路径下有多好"；贝尔曼方程的自举结构揭示了辨证的递归本质：当前症状组合的期望转归 = 当下处理的效果 + γ × 后继状态（转归、并发症）的价值。辨证不是一次性的静态判断，而是沿着病程递归展开的动态评估。这正是平台设计"医圣成长路径"的理论依据：医师从住院医到学科带头人的每一次决策，都在改写自己路径上各状态的价值。

### 2.7.2 数据与检索实现：tcm_embed.py 的角色

平台用什么工具"计算"这些价值？答案不是直接求解矩阵方程，而是用语义检索做价值近似。tcmP/scripts/tcm_embed.py 实现了病证检索流水线：bigram 分词 → TF-IDF 向量化（权重 log((N+1)/(f+1)) + 1）→ 余弦相似度排序 → FTS5 全文召回 → RRF（Reciprocal Rank Fusion）融合排序。这条流水线扮演"价值近似的计算器"：给定一个症状状态，检索返回的 Top-K 病证及其证据分，就是该状态价值的初步估计——高证据分意味着"按库中已有路径处理，期望疗效高"，低证据分意味着"库中缺乏支持，疗效不确定"。配置接口有三步。第一步，读取数据：用 Python 加载 kg/samples/dsu-samples-001.json，该文件包含真实的病证单元样例（103+ 个，含失眠、感冒、头痛等常见病证）。第二步，运行引擎：务必使用 hermes venv 的 python（C:\Users\DELL\AppData\Local\hermes\hermes-agent\venv\Scripts\python.exe）执行 tcm_embed.py——平台检索引擎依赖 SQLite FTS5，而系统 Anaconda python 3.9 下 FTS5 会段错误（segfault），这是已知的环境坑，务必避开。第三步，线上验证：调用平台的语义检索端点 curl "http://localhost/api/sages/semantic-search?q=失眠&top_k=1"，观察返回的病证、方剂与证据分。经过这三步，读者就拥有了"状态 → 价值估计"的完整链路。

### 2.7.3 本章实践：贝尔曼方程的平台小实验

实践任务：用真实 DSU 数据构造小规模 MDP，求解贝尔曼方程，把教材 2.4 节的矩阵求解在平台数据上复现。实验设计如下：① 状态：选取 10 个高频症状组合（如"失眠+多梦+心悸"、"恶寒重+发热轻+无汗"、"头痛+项强+恶风"等），构成状态集 S；② 动作：每个状态配 5 首候选方剂（如失眠对应酸枣仁汤、天王补心丹、归脾汤等），构成动作集 A；③ 转移概率 P(s′|s,a)：从病证-方剂共现统计估计——统计库中"用方剂 a 处理症状组合 s 后，病程转归到症状组合 s′"的频率，归一化得到概率；④ 奖励：按证据等级映射 A=1.0、B=0.7、C=0.4。构造完成后，用 numpy 求解 v = (I − γP)⁻¹r（γ 建议取 0.9），得到每个症状组合的临床价值向量。最后做一步对照实验：把求解结果与 /semantic-search 检索得到的 Top-K 证据分放在同一张表里对比，讨论"检索分数 ≈ 价值近似"的合理性——检索分高的症状组合是否对应求解价值高的状态？偏差出现在哪里（特征表示、奖励设计、候选集大小）？这个讨论没有标准答案，但它是把第2章的数学与平台的工程连接起来的关键一步。完成实验后，请在实训报告中回答三个问题：其一，γ 取 0.9 与 0.5 时，价值排序是否变化？为什么？其二，如果证据等级映射改为 A=1.0、B=0.9、C=0.8，哪些状态的价值变化最大？其三，检索分数与求解价值的排序一致性，在哪些病种上最好、哪些病种上最差？把回答连同求解代码、结果表格一并提交。

### 实验代码骨架

为方便读者上手，给出 2.7.3 节实验的求解代码骨架（完整代码见实训包）。第一步，读取数据：用 json 加载 kg/samples/dsu-samples-001.json，从每个病证单元的六段式字段中提取症状组合（状态）与方剂（动作），构造状态索引字典 state2id 与动作列表。第二步，构造转移矩阵：遍历病证-方剂共现记录，统计"在症状组合 s 下使用方剂 a 后转归到 s′"的次数，按行归一化得到 P，形状为 n×n；同时按证据等级映射（A=1.0、B=0.7、C=0.4）构造奖励向量 r。第三步，求解：直接法 p = np.linalg.inv(np.eye(n) − gamma * P) @ r，或迭代法 v = r.copy() 后循环 v = r + gamma * P @ v 直到 ‖v_new − v‖ < 1e−8。第四步，对照：对每个症状组合调用检索引擎取 Top-K 证据分，与求解价值并列成表。再次强调：运行检索引擎时必须使用 hermes venv 的 python，系统 Anaconda python 3.9 下 SQLite FTS5 会段错误；求解部分则与 python 环境无关，可用任一 python 3.8+ 环境。

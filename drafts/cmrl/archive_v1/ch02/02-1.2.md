# 2.2 状态价值的定义（Definition of State Value）

## [Part1] 2.2 状态价值的定义

### 2.2.1 回报的局限：随机性带来的麻烦

2.1 节已经表明，回报可以评价策略，且数值大小与直觉一致。但我们同时注意到一个隐患：一旦策略或环境的转移具有随机性，从同一状态出发就可能得到不同的回报。设想机器人按某个随机策略在状态 s1 出发一百次：这一百次运行可能穿过不同的格子、拿到不同的奖励序列，因而回报各不相同。此时如果我们说"该策略在 s1 的回报是 0.7"，这句话是不严谨的——0.7 只是某一次运行的结果，下一次可能是 0.2，再下一次可能是 1.1。回报是一个随机变量（random variable），它由随机变量序列 Rt+1, Rt+2, … 加权求和得到，而每个 Rt 都依赖于随机采取的动作与随机的转移。随机变量不能直接用来排序和比较策略：一次实验的高分不能证明策略好，一次实验的低分也不能证明策略差，样本与规律之间存在噪声。要摆脱这种噪声，数学上最标准的做法是把随机变量平均掉，即考察它的期望。这一节我们就来定义这个期望，并把它命名为状态价值（state value）。

### 2.2.2 定义与记号

考虑时间序列 t = 0, 1, 2, …。在时刻 t，智能体处于状态 St，按策略 π 采取动作 At，环境转移到下一状态 St+1，并给出即时奖励 Rt+1。折扣回报定义为 Gt = Rt+1 + γRt+2 + γ²Rt+3 + … = Σk=0∞ γ^k Rt+k+1。如前所述，Gt 是一个随机变量。现在定义状态价值函数（state value function）vπ(s)：从状态 s 出发、遵循策略 π 所能获得的期望折扣回报，即 vπ(s) = E[Gt | St = s]。这个定义值得用三种方式反复咀嚼。第一，从文字上读：状态价值是"给定当前处于状态 s，按策略 π 行动，未来折扣回报的期望"。第二，从记号上读：vπ 中的下标 π 提醒我们价值依赖策略，括号中的 s 提醒我们价值依赖状态；E[· | St = s] 是条件期望，条件就是"当前状态为 s"。第三，从直觉上读：状态价值度量的是"状态 s 在策略 π 下有多好"——数值越大，说明从这个状态出发越有希望获得高回报。如果读者觉得这个定义抽象，不妨把它理解为对 2.1 节 return3 的正式化：当时我们对随机策略的回报取了平均，现在这个"平均"被严格地写成了条件期望。

### 2.2.3 三点注解

对定义 vπ(s) = E[Gt | St = s]，赵世钰老师在课堂上特别强调三点注解，这里逐一说明。第一，vπ(s) 依赖于状态 s，因为它是条件期望：条件不同，期望一般不同。在网格世界中，靠近目标的格子价值通常高于远离目标的格子——这是"位置决定前景"的数学表述。第二，vπ(s) 依赖于策略 π，因为轨迹由策略生成：同一状态在不同策略下，未来走向不同，期望回报自然不同。回到 2.1 节的例子，状态 s1 在"避开禁区的策略"下价值高，在"进入禁区的策略"下价值低。第三，vπ(s) 不依赖于时刻 t。这个性质初看令人意外：条件期望 E[Gt | St = s] 的表达式里明明写着 t，为什么结果与 t 无关？原因在于马尔可夫性质与平稳性：从状态 s 出发的未来演化只由 s 与策略 π 决定，与"现在是什么时刻"无关；折扣回报只是把同一段随机过程重新加权求和，加权的起点不影响期望值本身。正因为 vπ(s) 与 t 无关，我们才可以放心地写 vπ(s) 而不写 vπ(s, t)，也才可以把它当成"状态的属性"来研究。这三点注解构成了后续一切推导的语义基础：状态价值是"状态与策略的函数"，而不是"时间的函数"。

### 2.2.4 特例：确定性系统的回报等于状态价值

为了看清定义的几何，我们考察两个特例。第一个特例：策略与转移都是确定性的。此时从状态 s 出发只有唯一一条轨迹 s, a, s′, a′, s″, …，每个时刻的奖励都被唯一确定，回报 Gt 退化成一个确定的数，不再是随机变量；期望作用于常数等于常数本身，因此 vπ(s) = Gt。换言之，在确定性系统中，状态价值就是那条唯一轨迹的折扣回报。2.1 节中前两个策略（第一个策略与第二个策略）都是确定性的，所以当时计算的 return1 与 return2 正是它们在状态 s1 的状态价值。第二个特例：随机性存在但不影响期望。假设某个状态 s 的两条后继轨迹回报分别为 1 与 −1、各以 0.5 概率出现，则 vπ(s) = 0.5×1 + 0.5×(−1) = 0。这个 0 并不意味着"从 s 出发什么都得不到"——单次运行要么得 1 要么得 −1，从不真的得 0；它只说明"多次重复的平均是 0"。这两个特例提醒我们：期望会抹平随机性，而实际运行永远只经历随机性的一个实现。状态价值回答的是"平均意义上好不好"，这正是策略比较所需要的确定性指标。

### 2.2.5 状态价值是评价策略的形式化指标

现在我们可以把 2.1 节的结论升级为一般原则：策略 π 的好坏，用它在各状态的状态价值来衡量；如果对一切 s ∈ S 都有 vπ₁(s) ≥ vπ₂(s)，我们就说策略 π₁ 不劣于 π₂。为什么选择"期望"而不是其他统计量（如中位数、最坏情形）？这是强化学习的基本约定：期望对应着"长期平均收益最大化"，它把风险平均化处理，数学上最方便（期望是线性算子，可进入求和号），也最容易与概率论既有理论衔接。当然，期望不是唯一选择——风险规避的场合可以引入条件风险价值（CVaR）等指标，那是扩展方向；本书如无特别说明，一律采用期望准则。至此，评价策略的问题从"直觉"落到了"可计算的数字"上：给定策略 π 与模型 (P, R, γ)，我们要计算 vπ 在每一个状态上的取值。2.1 节的三个策略计算靠的是手工枚举轨迹，这在状态多、轨迹长时完全不可行——我们需要一种不枚举轨迹、直接由状态之间的"关系"求解价值的数学工具。这种工具就是下一节的贝尔曼方程。

### 2.2.6 例题：网格世界的状态价值

例2.1 在 2.1 节的网格世界中，设 γ = 0.9。求"第一个策略"（避开禁区）在状态 s1 的状态价值，并与"第二个策略"（进入禁区）比较。解：第一个策略从 s1 出发的轨迹唯一：s1 → s3 → s4 → s4 → …，回报为 0 + 0.9×1 + 0.9²×1 + … = 0.9/(1−0.9) = 9，故 vπ₁(s1) = 9。第二个策略的轨迹为 s1 → s2 → s4 → s4 → …，回报为 −1 + 9 = 8，故 vπ₂(s1) = 8。因此 vπ₁(s1) = 9 > vπ₂(s1) = 8，与 2.1 节 return1 > return2 的结论一致。这个例题虽然简单，却揭示了一个重要现象：两个策略的差距在价值上被"放大"了——直觉上只差一步的决策，在价值上差出 1 个单位的期望回报；如果 γ 更接近 1，后续停留在目标态的奖励越多，这个差距还会进一步扩大。原因在于状态价值累积了整条轨迹的后续回报：一步之差，影响的是此后每一个时刻。这也解释了为什么强化学习如此看重"第一步"的选择——在折扣回报的视角下，任何一步的失误都会沿着时间轴向后传播。例2.1 的数值将在 2.3 节由贝尔曼方程重新得到，届时读者可以对比两种算法的结果。

### 状态价值与回报的记号辨析

初学者常在记号上混淆两个对象：vπ(s) 与 Gt。Gt 是随机变量，描述"这一次运行实际拿到的折扣回报"；vπ(s) = E[Gt | St = s] 是一个确定性的数，描述"从状态 s 出发按策略 π 行动，平均意义下的折扣回报"。两者在数值上通常不同——单次运行可能运气好、可能运气差，而期望抹平了运气的波动。写代码时这种区别会变得非常具体：Gt 对应一次环境交互的采样返回值，vπ(s) 对应大量采样后的平均；强化学习算法中的"价值估计"，本质上就是让一个可学习的估计量逐步逼近 vπ(s) 的过程。本书第5章以后的时序差分方法，正是利用"单次采样 Gt 是 vπ(s) 的无偏噪声估计"这一事实来设计更新规则的——到那时，请回想本节这个看似琐碎的辨析，它是连接"采样"与"期望"的桥梁。

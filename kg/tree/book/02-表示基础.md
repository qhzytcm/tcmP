# 第二章 中医药知识的表示基础

## 2.1 知识表示方法概览（框架/语义网络/本体/属性图）

知识表示的历史是一部「从规则到结构、从结构到向量」的演进史。**框架表示**用槽—值结构描述对象；**语义网络**用节点—弧表达概念关系；**本体**（Ontology）在语义网络之上加形式化公理，使之可推理；**属性图**（LPG）则以「节点带属性、边带属性」的工程形态落地。

中医药知识树并不发明新表示法，而是**组合**它们：树骨架借自本体（is-a / part-of 层级），经脉边借自属性图（带权、带类型的边），叶节点则预留向量表示接口。

## 2.2 RDF/OWL 与属性图（LPG）

RDF 用三元组 `(主语, 谓语, 宾语)` 表述事实，OWL 在此基础上定义类、属性与基数约束。其优点是标准化与可推理，缺点是查询与工程实现较重。属性图以 Neo4j 为代表，节点与边都可挂属性，查询语言（Cypher）直观。

tcmP 采用**双轨**：对外以 OWL 承载中医领域本体（Protégé 建模），对内以 JSON 属性图承载构建与查询。二者的桥接由 `kg/tree/schema.json` 定义。

## 2.3 树结构与图结构的数学基础

树是连通无环图，具有唯一路径、$n$ 节点恰有 $n-1$ 条树边、任意两节点间距离等于深度差等性质。这些性质让树天然适合做**导航与从属**：`path(叶)` 必唯一，`subtree(枝)` 必封闭。

图则可含环、可多路径，适合做**推理与传播**。知识树 = 生成树（树边承担层级） + 附加边集（非树边承担关系）。于是「找一条学习路径」用树算法，「找一条推理链」用图算法。

| 任务 | 结构 | 算法 |
| --- | --- | --- |
| 定位知识来源 | 树 | 祖先链（唯一路径） |
| 展开某域全部学科 | 树 | 子树遍历 |
| 由病索证／由证溯病 | 图 | 邻接遍历 / 路径搜索 |
| 学先用例排序 | 图（DAG） | 拓扑排序（前置依赖） |

## 2.4 中医药领域本体设计（七步法）

斯坦福七步法在中医领域落地为：① 确定领域与范围（如「证候—方剂」子领域）；② 复用现有本体（ICD-11 传统医学章、TCM 术语标准）；③ 列举重要术语；④ 定义类与层级；⑤ 定义属性与关系；⑥ 定义约束（如「一证至少一主症」）；⑦ 实例化与评估。

知识树的第一、二级（须、根）即为领域本体的顶层类，第三至五级（干、枝、叶）为其下实例化结果。

## 2.5 知识图谱嵌入（TransE/RotatE）与树的向量表示

# 第八章 构建管线与工程实现

## 8.1 单一事实源与生成器模式

知识树的可信度来自**单一构建点**。全树由 `scripts/build_knowledge_tree.py` 一次生成，任何人不得手工编辑生成物。这带来三个好处：一致性可证（索引与技能同源，不可能漂移）、规模可扩展（学科从 120 增到 200 只需重跑）、可自动校验（CI 能判定生成物是否已提交）。

```bash
python scripts/build_knowledge_tree.py     # 构建
python scripts/verify_knowledge_tree.py    # 24 项自检
```

## 8.2 多源异构数据的容错解析

知识树的输入跨越四类异构源：学科目录 JSON、领域规范 Markdown、病证单元 JSON、技能目录 JSON。其中领域规范最难，因为它同时存在编号列表、表格、`<br>` 拼接单元格与代码围栏四种排版。构建器采用**多策略抽取 + 章节归属追踪**：

```python
def _extract_chapters(blob):
    blob = blob.replace("<br>", "\n")           # 归一化 <br> 拼接
    for raw in blob.splitlines():
        if raw.startswith("|"):                  # 表格：取「第N章 | 章名」行
            m = CHP_ROW.match(raw); ...
        if re.match(r"^\d{1,2}[\.、]", raw): ...  # 编号列表
        if re.match(r"^第[0-9一二三四五六七八九十百]+章", raw): ...  # 纯章行
```

## 8.3 知识树的 Schema 设计与校验

`schema.json` 用 JSON Schema（draft-07）固化节点与边的结构：节点必须有 `id/level/level_index/name/kind`，边的 `type` 限定在 14 种枚举值内。任何越界在构建阶段即被拦截。

## 8.4 构建的自检与质量门禁

自检脚本把「结构完整性、树导航、图邻接、检索、API 路由」五类断言固化：

| 类别 | 断言示例 |
| --- | --- |
| 结构完整性 | 8 域 · 120 学科 · 章节覆盖 120/120 · id 无重复 |
| 树导航 | `path(D07-S04) == [D07, D07-S04]` |
| 图邻接 | 五行相生自洽（木 出→火、入←水） |
| 检索 | 「桂枝」有结果；「知识图谱」命中 D07-S04 |
| API 路由 | `/tree/stats`、`/tree/path/{id}` 等函数级可用 |

## 8.5 与 Embedding 引擎的双向绑定

知识树给**结构**，Embedding 引擎给**语义**，二者双向绑定：树的叶文本喂入向量库，语义检索的命中回挂到叶上。

平台引擎（`scripts/tcm_embed.py` + `/diag`、`/bianzheng`、`/semantic-search`、`/rag`）技术栈为 **TF-IDF 字符 n-gram + SQLite FTS5 + RRF 融合**，内网零 token：

```python
# 1) TF-IDF 字符 n-gram 向量（零依赖起步）
from sklearn.feature_extraction.text import TfidfVectorizer
vec = TfidfVectorizer(analyzer="char_wb", ngram_range=(1, 3))
X = vec.fit_transform([d["text"] for d in docs])       # 每片叶一行

# 2) SQLite FTS5 全文索引（BM25 排序）
con.execute("CREATE VIRTUAL TABLE fts USING fts5(id, text, tokenize='unicode61')")
con.executemany("INSERT INTO fts VALUES (?,?)", [(d["id"], d["text"]) for d in docs])

# 3) RRF 融合（倒数排序，k=60）把「向量 Top-K」与「FTS5 Top-K」合并
def rrf(rank_lists, k=60):
    score = {}
    for rl in rank_lists:
        for i, doc in enumerate(rl):
            score[doc] = score.get(doc, 0) + 1.0 / (k + i + 1)
    return sorted(score, key=score.get, reverse=True)
```

**上下文工程（context engineering）** 则是把树图检索的结果精确装配进 LLM 上下文：只送 Top-5 叶（约 1.5K token），而非全库（31K/次），token 下降约 95%。装配规则由知识树的路径决定——先取 `path(叶)` 给出学科坐标，再取 `neighbors(叶)` 给出关系证据，最后按证据等级排序，形成「结构化、有出处、可复核」的提示上下文。

> 实测（2026-10）：`/semantic-search?q=失眠` → DSU-00035，证「心脾两虚证」，方「归脾汤」，ICD-11「MC81」，融合分 0.1601（向量 0.160 + FTS 0）。

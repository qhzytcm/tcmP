# 第九章 关联规则挖掘

## 9.1 三个核心量：support / confidence / lift

关联规则写作 A → B。它由三个量刻画：

| 量 | 定义 | 含义 |
| --- | --- | --- |
| support | P(A,B) = n(A,B)/N | A 与 B 同时出现的比例 |
| confidence | P(B\|A) = n(A,B)/n(A) | 出现 A 时也出现 B 的条件概率 |
| lift | confidence / P(B) | 相对“随机”的倍数；>1 为正相关 |

## 9.2 Apriori 与频繁项集

Apriori 利用“频繁项集的子集必频繁”逐层剪枝。教材层面先掌握**两两共现**，再理解剪枝即可。

```python
pair = Counter()
for tx in transactions:            # tx = 一条记录的项集
    for x in tx:
        for y in tx:
            if x != y:
                pair[(x, y)] += 1
```

## 9.3 平台实例：症状 → 证候、证候 → 方剂

在 103 条病证单元上挖掘，得到 45 条规则。例如：

| 规则 | support | confidence | lift |
| --- | :-: | :-: | :-: |
| PSA升高 → 肾虚瘀毒证(癃闭/积证) | 0.0097 | 1.0 | 103.0 |
| 一侧腰臀至下肢后外侧放射性疼痛 → 寒湿阻络、气滞血瘀证 | 0.0097 | 1.0 | 103.0 |

## 9.4 ⚠️ 虚假高提升度：本课程最重要的一课

上表 lift=103 看起来极强，其实是 `1/(1/103)` 的必然：**小语料里每个症状只出现一次**，support 低到 0.0097。任何“只出现一次”的 A 都会得到 confidence=1.0 与 lift=N。

**结论**：必须先设 **support 阈值**过滤低频项，再谈 lift。否则会被“虚假高提升度”严重误导——这是信息挖掘最经典的陷阱，也是本课程考核重点。

```python
if k / N < MIN_SUPPORT:      # 先过 support 门槛
    continue
lift = (k / n_a) / (n_b / N)
```

## 9.5 从规则到知识：人工复核不可省

数据挖出的规则只是**假设**，需经中医专家复核才能成为知识。平台的“证据等级（A–F）”正是为这种复核结果提供标尺。

> 实训：把 MIN_SUPPORT 从 1 提到 2、3，观察规则数量与 lift 分布的变化，说明其含义。

# 第十七章 中医药数据库技术

## 17.1 数据库在中医信息学中的位置

数据库解决“数据放哪、怎么查得快”。中医药数据的特点是**多表关联**（病—证—方—药—穴）与**文本为主**，因此既要关系库的严谨，也要全文索引的速度。

## 17.2 关系模型与 SQL

关系模型用表表达实体、用外键表达关系。一个简化的病证库：

```sql
CREATE TABLE dsu (id TEXT PRIMARY KEY, disease TEXT, syndrome TEXT, formula TEXT);
CREATE TABLE symptom (dsu_id TEXT, name TEXT, FOREIGN KEY(dsu_id) REFERENCES dsu(id));
SELECT s.name, COUNT(*) FROM symptom s GROUP BY s.name ORDER BY 2 DESC LIMIT 10;   -- 高频症状
```

## 17.3 SQLite 与轻量落地

平台选择 SQLite：单文件、零运维、便于分发。ICD-11 本地库 `data/icd11_mms.db` 即以 SQLite 存储 31,838 条实体。

```python
con = sqlite3.connect("data/icd11_mms.db")
con.execute("SELECT id, code, title FROM entities WHERE id=?", (fid,)).fetchone()
```

> ⚠️ **工程陷阱**：部分环境的 sqlite3 DLL 与库文件不兼容会导致进程级崩溃。平台约定：读写关键库统一用 Hermes 自带 Python（3.11），并在客户端做“连接即测”。

## 17.4 全文索引：FTS5

文本检索要靠 **FTS5 虚拟表**（倒排索引 + BM25）：

```sql
CREATE VIRTUAL TABLE dsu_fts USING fts5(id UNINDEXED, text, tokenize='unicode61');
INSERT INTO dsu_fts VALUES ('DSU-00001','疾病：普通感冒 … 证候：风寒束表证 …');
SELECT id FROM dsu_fts WHERE dsu_fts MATCH '失眠' LIMIT 5;
```

## 17.5 图数据库与知识图谱存储

病—证—方—药的多跳关系更适合图库（Neo4j，Cypher 查询）。平台以属性图 JSON 承载构建、以 OWL 承载本体，二者通过 Schema 桥接（详见 `/tree` 知识树）。

## 17.6 数据质量控制

入库前必须清洗：值域校验、去重、缺失处理。平台用**枚举一致性校验**（见第十八章 M5）自动发现“I级→E级”这类录入错误。

> 实训：用 SQLite 建立 103 条 DSU 的最小库，跑出“高频症状 Top10”。

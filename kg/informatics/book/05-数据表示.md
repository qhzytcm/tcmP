# 第五章 中医药数据表示与数据元

## 5.1 从文本到数据：表示的三个层次

同一句“恶寒重、发热轻、无汗”，可以有三种表示：**字符串**（原文）、**结构化**（症状列表）、**向量**（数值）。信息学的任务就是在这三层之间自由转换。

## 5.2 病证单元：平台的最小数据单元

平台把中医药知识表示为「病证单元（DSU）」——同时包含病侧与证侧，不可拆分：

| 段 | 字段 |
| --- | --- |
| 病侧 | 病名、ICD 编码、分类、分子靶点、基因通路、生物标志物 |
| 证侧 | 证名、证型、脏腑、六经、八纲、主症、舌脉、证候场论、经典依据 |
| 桥接 | 对应类型、生物学基础、证据等级 |
| 临床 | 主方、加减、针灸、食疗、预后 |
| 教学 | 难度、阶段、医圣引用、典型医案 |

## 5.3 结构化表示：JSON Schema 与枚举

`kg/schema/schema.json` 用 JSON Schema 固化结构与值域。它既是**文档**（人读），也是**校验器**（机读）。

```json
"evidence_level": {
  "type": "string",
  "enum": ["A级-多中心RCT","B级-单中心RCT","C级-队列研究",
           "D级-病例对照","E级-专家共识","F级-经典理论"]
}
```

## 5.4 向量表示：字符 n-gram 起步

把文本变数字的最快方式不是大模型，而是 **TF-IDF 字符 n-gram**：中文没有空格，用字符 bigram（如“失眠”→“失眠/眠多/多梦”）就能获得稳健表示，且零依赖、零 token。

```python
for seg in re.findall(r"[\u4e00-\u9fff]+", text):
    toks += [seg] if len(seg) == 1 else [seg[i:i+2] for i in range(len(seg)-1)]
```

## 5.5 数据元设计原则

- **单一职责**：一个数据元只表达一件事；
- **值域显式**：枚举优于自由文本；
- **可追溯**：每个数据元标注来源与版本；
- **可降级**：平台不可达时要能回退（如 ICD-11 公网降级英文检索）。

> 实训：为一个新症状（如“夜间盗汗”）设计数据元，写出名称/定义/类型/值域/示例。

## 5.6 中医药信息特征框架（补充 · 对标词条）

学科**率先提出中医药信息特征框架**，为“怎么表示”提供理论依据。结合平台落地，可归纳为“四性”与“四策”：

| 信息特征 | 表现 | 表示策略（平台落地） |
| --- | --- | --- |
| 双轨性 | 病 × 证 | DSU 双段 + bridge 桥接 |
| 模糊性 | 舌脉等定性描述 | 枚举 + 程度分级 |
| 关联性 | 病—证—方—药—穴 | 图/边表示（`neighbors`） |
| 经验性 | 医案隐性知识 | 文本挖掘 + 证据等级 |

数据元设计（5.5）正是这一框架在字段层面的实现。

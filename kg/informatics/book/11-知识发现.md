# 第十一章 知识发现与智能应用

## 9.1 从数据到知识：KDD 流程

知识发现（KDD）是一条流水线：**数据 → 清洗 → 集成 → 选择 → 变换 → 挖掘 → 评估 → 知识**。教材反复强调：前六步占 80% 工作量，挖掘算法只占 20%。

## 9.2 中医药知识图谱

知识图谱用“实体—关系—实体”表达知识。平台的病证单元是**节点**，`bridge`/`manifests_as`/`disease_is`/`icd11_map` 是**边**；血证单元之上再叠“知识树”提供层次坐标（见 `/tree`）。

## 9.3 智能问答与辨证辅助

把“检索 + 图谱 + 上下文工程”串起来，就得到一个可解释的中医问答/辨证辅助系统：

```
用户症状 → 向量+FTS5 召回 Top-K 病证单元 → 取 path 给学科坐标 → 取 neighbors 给证据 → 装上下文 → LLM 生成带出处的回答
```

## 9.4 大模型与中医药信息学

大模型解决“自然语言的入口/出口”，但**不能取代**编码、检索与挖掘：它需要结构化知识作为“锚”，否则易幻觉。信息学为 LLM 提供**可信的外部知识**与**可追溯的出处**。

## 9.5 数据质量即知识质量

平台数据质量门禁发现 36 项问题（29 项编码缺失、6 项六经越界、1 项证据等级错别字）。这提示一个朴素真理：**垃圾进、垃圾出**——没有数据质量，就没有知识发现。

## 9.6 伦理、安全与治理

医疗数据涉隐私；智能辅助不能越权诊断；结论必须可追溯。平台的合规姿态是：所有技能均为**辅助性**能力，不替代医师判断与签字。

## 11.7 古籍数字化与智能计算平台（补充 · 对标词条）

知识发现在中医药场景的典型载体是**古籍数字化**：中国中医科学院信息所主导构建**国家中医药古籍数字图书馆**，完成《中华医藏》等古籍的数字化整理；2025 年上线**中医药智能计算平台**，集成自然语言处理模块，实现古籍文本**自动标引**。

这三步——**数字化 → 结构化 → 自动标引**——正是本课程“文本→数据→知识”主链在古籍领域的实例：先用 OCR/阅读序重建把扫描件变成文本，再用数据元/标注把文本变成结构，最后用 NLP 做自动标引与知识抽取。

# 第三十一章 中医临床信息数据的整合

> 对应《中医临床信息学》第十五章。

## 31.1 整合的目的与原则

**目的**：让分散在各业务系统的数据**可关联、可分析**——同一患者在门诊、住院、检验、影像中的数据必须能拼成一条时间线。

**原则**：以患者主索引为锚；术语与编码先行统一；保留原始来源可追溯；增量整合、不打断业务。

## 31.2 基于数据仓库技术的整合

抽取（ETL）→ 清洗 → 转换 → 装载，形成面向主题（病种/证候）的分析库。优点是分析性能好；代价是时效与治理成本。

## 31.3 基于 HL7 标准的整合

以 **HL7** 等医疗信息交换标准实现系统间互操作：定义消息与资源模型，用标准接口替代点对点集成。这也是**国际标准化建设**（本教材第二十六章）在医院侧的落点。

## 31.4 平台对照

| 整合路径 | 平台实现 |
| --- | --- |
| 编码统一 | ICD-11 双通道（`/icd/*` + 本地库） |
| 模型统一 | DSU Schema（病·证·桥·临床·教学·元） |
| 多源桥接 | DSU `bridge` 段（直接/间接/阶段/机制对应） |

> 思考题：为什么“术语与编码先行”是数据整合铁律？举一个编码不统一导致整合失败的例子。

# 中医中药系列教材编写平台 — 项目需求分析 v2.0

> **项目代号：** TCM-KT（Knowledge Tree）  
> **核心隐喻：** 四层 Agent 协作构建「一干八枝」病证单位知识树  
> **内容范式：** 病证同存 — 病（西医分子靶点）+ 证（中医证候场论顺应）  
> **版本：** v2.1 | 2025-07-04（中医智能学院 + 浪潮服务器 192.168.1.11 + 落地路线图）

---

## 一、项目概述

### 1.1 项目名称

中医中药「病证单位」系列教材四层 Agent 协作编写平台（知识树系统）

### 1.2 一句话描述

以**病证单位**（病·西医分子靶点 ↔ 证·中医证候场论顺应）为内容核心，四层 AI Agent 协作构建 120 门学科教材的知识树，实现病证同存知识体系的精准生产与智能检索。

### 1.3 项目背景

- 高等中医药院校规划 **120 门独立学科教材**，每门均以「病证单位」为编写原子
- 传统教材将"病"与"证"分离编写，无法体现**分子靶点与证候场论的动态顺应**关系
- 教材使用阶段需支持"以病索证"和"以证溯病"的双向检索
- 中医药大学按八类院系组织教学，其中**枝6 由「中西医结合」升级为「中医智能学院」**，标志中医与 AI 深度融合
- 八域平均各有 **15 门学科教材**（8 × 15 = 120），实现均衡化学科布局

### 1.4 核心创新

```
传统模式：人 → 写教材（病证分离）→ 学生分别学"西医病"和"中医证"
本系统：  Agent 树 → 以病证单位为原子 → 病证同存双向检索
           └─ 病（分子靶点基因通路）
           └─ 证（证候场论顺应调控）
           └─ 智能介入（中医智能学院提供 AI 桥接）
```

### 1.5 「病证单位」范式定义

```
┌──────────────────────────────────────────────────────────────┐
│                    病证单位 = 病 + 证                         │
│                                                              │
│   病（Disease）                 证（Syndrome）               │
│   ┌─────────────────┐          ┌─────────────────┐          │
│   │ 西医分子靶点     │          │ 中医证候场论     │          │
│   │ · 基因通路       │  顺应    │ · 阴阳盛衰       │          │
│   │ · 蛋白靶标       │ ←────→  │ · 气血津液       │          │
│   │ · 代谢网络       │  动态    │ · 脏腑经络       │          │
│   │ · 信号转导       │          │ · 六淫七情       │          │
│   └─────────────────┘          └─────────────────┘          │
│                                                              │
│   每个知识节点同时包含：                                     │
│   · 病侧：分子机制 + 靶点图谱 + 生物标志物                   │
│   · 证侧：证候特征 + 场论解释 + 顺应调控法则                 │
│   · 桥接：中医智能学院提供的 AI 分析模型                     │
└──────────────────────────────────────────────────────────────┘
```

## 二、四层 Agent 体系定义

### 2.1 Agent 层级结构

```
L1 行业主编 (1个根节点)
  └─ L2 领域主编 (8个主干节点，即八枝)
       └─ L3 学科主编 (120个分支节点，每学科1个，每域15门)
            └─ L4 章节作者 (N个叶子节点，每章对应N个病证单位)
```

### 2.2 各层 Agent 需求规格

| 层级 | 名称 | 实例数 | 覆盖范围 | 核心职责 | 关键能力 | 默认后端 |
|:--:|------|:--:|------|------|------|:--:|
| **L1** | 行业主编 | 1 | 全部 120 种教材 | 终审仲裁、病证范式合规、全局标准 | 跨域病证一致性裁决、四层级衔接审查 | `managed_modal` |
| **L2** | 领域主编 | 8 | 每个领域 15 种教材 | 域内病证协调、分子-证候场论一致性 | 域术语统一、病证桥接审核、AI 介入调度 | 按域分派（见下表） |
| **L3** | 学科主编 | 120 | 单种教材全部章节 | 病证单位审核、分子靶点准确性、证候场论完整性 | 病证双向审核、认知递进设计、教学目标制定 | `daytona` |
| **L4** | 章节作者 | ~2,400+ | 单一章节（约 20 个病证单位） | 编写病证单位、标注分子靶点与证候顺应 | 病证同存内容创作、分子靶点标注、场论阐述 | `浪潮服务器` |

### 2.5 基础设施：浪潮服务器

| 属性 | 值 |
|------|------|
| **IP 地址** | `192.168.1.11` |
| **已部署 Agent** | CursorAgent（编码与生成）+ HermesAgent（多 Agent 编排） |
| **版本管理** | GitHub（已启动，仓库就绪） |
| **承担角色** | L4 章节作者主力执行环境 + 枝8 领域主编 + 本地开发调试 |
| **并发容量** | 支持同时运行 ~50 个 Agent 实例 |

### 2.3 八领域（八枝）定义 —— 病证单位视角下的三层映射

```
枝1 基础医学院   → 知识域：病证基础理论/分子中医学/证候场论/中医思维 → 岗位：高校教师、科研人员
枝2 中药学院     → 知识域：靶点中药学/中药场论药理学/分子炮制学 → 岗位：分子药师、靶点药企研发
枝3 针灸推拿     → 知识域：神经-经络场论/靶点针灸学/分子推拿学 → 岗位：针灸师、神经调控治疗师
枝4 临床一系     → 知识域：病证内科/分子妇科/靶点儿科/场论温病 → 岗位：病证内科/妇科/儿科临床医师
枝5 临床二系     → 知识域：病证外科/分子骨伤/靶点皮肤/场论眼科 → 岗位：病证外科/骨伤科临床医师
枝6 中医智能学院 → 知识域：AI辨证/分子-证候知识图谱/中医大模型/智能诊断 → 岗位：中医AI工程师、智能诊疗系统架构师
枝7 护理学院     → 知识域：病证护理/分子老年护理/靶点社区护理 → 岗位：病证护师、智能护理管理
枝8 管理人文     → 知识域：中医智能管理/卫生经济AI/医古文NLP → 岗位：智能医院管理、中医药AI传播
```

## 三、功能需求

### 3.1 知识树构建与管理

| 编号 | 功能 | 描述 | 优先级 |
|:--:|------|------|:--:|
| F-01 | 树节点 CRUD | 创建/读取/更新/删除知识树节点（根/主干/分支/叶子） | P0 |
| F-02 | 节点编码系统 | 自动生成唯一编码（如 `3.1.3.1.2` = 枝3→学科1→章3→节1→病证单位2） | P0 |
| F-03 | 树可视化 | D3.js/React Flow 渲染完整知识树，支持缩放、折叠、搜索 | P1 |
| F-04 | 节点关联 | 节点间建立「病→证」顺应关系和「证→病」溯源关系 | P0 |
| F-05 | 批量导入 | 从 Excel/CSV 批量导入 120 学科清单和病证单位目录 | P1 |

### 3.2 Agent 管理与编排

| 编号 | 功能 | 描述 | 优先级 |
|:--:|------|------|:--:|
| F-06 | Agent 注册 | 注册 L1~L4 四类 Agent 实例，绑定知识节点 | P0 |
| F-07 | Agent Profile 生成 | 根据 Agent 类型自动生成 Hermes Profile（config.yaml + SOUL.md） | P0 |
| F-08 | Agent 状态监控 | 实时显示各 Agent 在线/离线/忙碌状态 | P1 |
| F-09 | Agent 任务分发 | 通过 Kanban 看板向 Agent 分发病证单位编写/审核任务 | P0 |
| F-10 | Agent 通信协议 | L4→L3→L2→L1 的审核上报和 L1→L2→L3→L4 的指令下发 | P0 |

### 3.3 六阶段工作流引擎

| 编号 | 功能 | 描述 | 优先级 |
|:--:|------|------|:--:|
| F-11 | 阶段管理 | 支持六个阶段的启动/流转/暂停/完成 | P0 |
| F-12 | 交互方向控制 | 阶段一（Top-Down）、阶段四（Bottom-Up）等不同方向自动切换 | P1 |
| F-13 | 阶段模板 | 每个阶段的标准化任务模板，自动生成待办清单 | P1 |
| F-14 | 进度仪表盘 | 六阶段总体进度 + 八域各自进度 + 瓶颈预警 | P2 |

### 3.4 教材编写与审核（病证单位范式）

| 编号 | 功能 | 描述 | 优先级 |
|:--:|------|------|:--:|
| F-15 | 病证单位编辑器 | 双栏编辑器：左栏「病（分子靶点）」↔ 右栏「证（证候场论）」，实时同步 | P0 |
| F-16 | 版本管理 | 病证单位的版本历史 + 病/证双侧 Diff 对比 | P1 |
| F-17 | 审核工作台 | 分层审核（L3病证审/L2域审/L1终审），含病证合规检查 | P0 |
| F-18 | 驳回与升级 | 病侧或证侧不通过时的驳回→修改→重新提交，超限自动升级 | P1 |

### 3.5 病证双向检索与路由（核心目标）

| 编号 | 功能 | 描述 | 优先级 |
|:--:|------|------|:--:|
| F-19 | 以病索证 | 输入分子靶点/基因通路 → 检索对应证候场论描述 | P0 |
| F-20 | 以证溯病 | 输入证候特征 → 检索对应分子机制与靶点 | P0 |
| F-21 | Agent 路由 | 根据病证匹配，路由到最合适的 Agent（L4精确→L3→L2→L1降级） | P0 |
| F-22 | 路由日志 | 记录每次路由的查询→病证节点→Agent→响应时间 | P2 |

### 3.6 认知觉醒适配（病证单位视角）

| 编号 | 功能 | 描述 | 优先级 |
|:--:|------|------|:--:|
| F-23 | 认知层级标注 | 每个病证单位标注认知层级（识记分子靶点→理解场论→应用病证顺应） | P2 |
| F-24 | 分层内容呈现 | 同一病证单位在不同认知阶段展示不同深度 | P2 |

### 3.7 七类终端后端管理

| F-26 | Agent-后端绑定 | 为每个 Agent 指定默认后端 + 阶段级覆盖规则 | P0 |
| F-27 | 后端切换 | 阶段切换或故障降级时自动迁移后端 | P1 |
| F-28 | 后端健康检查 | 实时监控各后端状态，异常告警 | P1 |
| F-29 | 后端成本统计 | 按后端统计资源消耗与费用 | P2 |

### 3.8 中医智能学院特需功能

| 编号 | 功能 | 描述 | 优先级 |
|:--:|------|------|:--:|
| F-30 | AI 模型注册 | 注册中医大模型/辨证模型/知识图谱模型 | P0 |
| F-31 | 病证桥接引擎 | 枝6 Agent 提供分子靶点→证候场论的 AI 桥接推理 | P0 |
| F-32 | 模型评估面板 | 中医 AI 模型的准确率/召回率/辨证一致性评估 | P1 |

## 四、非功能需求

| 编号 | 类别 | 需求 |
|:--:|------|------|
| NF-01 | 性能 | 病证双向检索响应时间 < 500ms |
| NF-02 | 可用性 | 系统可用性 ≥ 99.5% |
| NF-03 | 扩展性 | 支持新学科加入时自动扩展知识树节点（目标 120→未来可扩展） |

| NF-05 | 数据 | 支持 Markdown/PDF/Word/LaTeX 多格式导入导出 |
| NF-06 | 兼容 | 支持 Hermes Agent 框架的 Profile 体系 |
| NF-07 | 后端兼容 | 支持七类终端后端 |
| NF-08 | 后端切换 | 单 Agent 可在六阶段中动态切换后端，切换延迟 < 30s |
| NF-09 | 病证范式 | 所有教材内容必须以「病证单位」为最小编写原子，禁止病证分离 |
| NF-10 | 智能介入 | 枝6 Agent 具有跨域 AI 桥接能力，可为其他七域提供模型推理服务 |

## 五、用户角色

| 角色 | 对应 Agent | 核心场景 |
|------|:--:|------|
| 行业主编 | L1 | 审阅全局仪表盘 → 签批病证范式标准 → 仲裁跨域病证争议 |
| 领域主编 | L2 | 管理本域 15 种教材 → 审核病证桥接一致性 → 调度枝6 AI 介入 |

| 学生/年轻医生 | — | 以病索证 / 以证溯病 → 获取专家级病证解释 |
| AI 工程师 | 枝6 L2/L3 | 开发部署中医 AI 模型 → 桥接其他七域的病证推理 |

## 六、技术栈建议

| 层 | 技术选型 |
|------|------|
| **前端** | Next.js 14 + TypeScript + Tailwind CSS + React Flow（树可视化）+ 双栏编辑器 |

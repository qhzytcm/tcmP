## 一、四层 Agent × 7 类后端 映射矩阵

> 原则：L4 就近（local）→ L3 共享（ssh/daytona）→ L2 算力（singularity/modal）→ L1 安全（managed_modal）

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│   L1 行业主编 ────────────────────── managed_modal (生产级托管)      │
│   │  备选: modal (大规模推理时)                                      │
│   │                                                                 │
│   ├── L2 领域主编·基础 ──────────────── singularity (HPC科研计算)    │
│   ├── L2 领域主编·中药 ──────────────── singularity                  │
│   ├── L2 领域主编·针灸 ──────────────── docker (批量一致性)          │
│   ├── L2 领域主编·内科 ──────────────── ssh (团队共享服务器)         │
│   ├── L2 领域主编·外科 ──────────────── ssh                          │
│   ├── L2 领域主编·结合 ──────────────── daytona (标准化环境)         │
│   ├── L2 领域主编·护理 ──────────────── docker                       │
│   ├── L2 领域主编·管理 ──────────────── local (轻量)                 │
│   │                                                                 │
│   ├── L3 学科主编(×120) ───────────── daytona (标准化)×80           │
│   │                              └──── ssh (共享)×40                │
│   │                                                                 │
│   └── L4 章节作者(×2000+) ────────── local (个人本机)×1500          │
│                                    └─ docker (批量生成)×500         │
│                                    └─ daytona (统一环境)×200        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 映射详解

| Agent 层 | 主后端 | 理由 | 备选后端 | 切换条件 |
|:--:|------|------|------|------|
| **L1** | `managed_modal` | 终审操作需要最高安全等级 + 生产级可用性 | `modal` | 需要进行大规模跨域语义分析时切换 |
| **L2·基础/中药** | `singularity` | 基础域和中药域涉及大量文献分析，需 HPC 算力 | `ssh` | 非科研计算类任务时切换 |
| **L2·针灸/护理/管理** | `docker` | 轻量域，容器化保证配置一致性 | `local` | 个人开发调试时切换 |
| **L2·内科/外科** | `ssh` | 临床域需要团队共享审核，SSH 远程协作 | `daytona` | 需要标准环境时切换 |
| **L2·结合** | `daytona` | 中西医结合域需要严格标准化环境 | `docker` | 批量任务时切换 |
| **L3** | `daytona` + `ssh` | ~80个用 daytona 保证标准环境，~40个用 ssh 灵活协作 | `docker` | 学科审需要大量计算时切换 |
| **L4** | `local` | ~1500 个章节作者在个人本机编写 | `docker` | CI/CD 批量生成草稿时切换 |

## 二、六阶段 × 7 类后端 动态调度

```
阶段一（需求分析）
  L1: managed_modal  ← 签批总纲（最高安全）
  L2: ssh            ← 岗位调研（远程协作沟通）
  L3: daytona        ← 知识点清单（标准环境）
  L4: local          ← 读者调研（个人工作）

阶段二（体系设计）
  L1: managed_modal  ← 签发规范
  L2: docker         ← 域架构图（可复现）
  L3: daytona        ← 章节结构设计
  L4: local          ← 教学详案

阶段三（内容编写）★ 高峰期
  L1: managed_modal  ← 半休眠（仅跨域仲裁，低频）
  L2: ssh            ← 跨科协调（实时沟通）
  L3: daytona        ← 实时指导 L4
  L4: local(80%) + docker(20%)  ← 主力编写！
       └─ local: 逐章精写
       └─ docker: CI/CD 批量生成初稿

阶段四（审核评阅）★ 计算密集
  L1: modal          ← 全局术语审计（需大模型推理）
  L2: singularity    ← 域内跨学科一致性计算
  L3: daytona        ← 科学性审核
  L4: local          ← 自审自查

阶段五（教学应用）
  L1: managed_modal  ← 审阅全局反馈报告
  L2: ssh            ← 收集域反馈
  L3: local/docker   ← 汇总学科反馈
  L4: local          ← 接收反馈

阶段六（修订迭代）
  L1: managed_modal  ← 签发修订令
  L2: singularity    ← 修订影响分析（计算密集）
  L3: daytona        ← 分配修改任务
  L4: local          ← 执笔修改
```

## 四、后端切换策略

### 4.1 同一 Agent 跨阶段切换

```
L2-领域主编-中药 的典型切换路径：

阶段一(需求)                         阶段四(审核)
  ssh ───────────────────────────── singularity
  ↑                                  ↑
  远程协作调研                         HPC计算跨学科一致性
  │                                  │
  └── 阶段三(编写) ── docker ────────┘
                        ↑
                        批量校验工具容器化执行
```

### 4.2 切换触发条件

| 触发条件 | 从 | 到 | 示例 |
|------|:--:|:--:|------|
| 任务从「交互协作」变为「批量计算」 | `ssh` | `singularity`/`docker` | L2 域审时切换到 HPC |
| 任务从「低安全」变为「高安全」 | `local`/`ssh` | `managed_modal` | L1 终审签名环节 |
| 任务从「个人」变为「团队共享」 | `local` | `ssh`/`daytona` | L3 学科审进入共享阶段 |
| 任务从「开发调试」变为「生产运行」 | `daytona` | `managed_modal` | L1 从调试环境切到生产 |

### Agent Profile 中的后端声明

```yaml
# profiles/L2-branch-02-herb/config.yaml

model:
  default: deepseek-v4-pro

terminal:
  backend: ssh                          # 默认后端
  ssh:
    host: herb-review-server.internal
    user: agent-l2-herb
    cwd: /data/textbook/branch-02/

agent:
  max_turns: 120

# 阶段级后端覆盖
backend_overrides:
  phase-1: ssh                          # 需求分析：远程协作
  phase-2: docker                       # 体系设计：容器可复现
  phase-3: ssh                          # 编写阶段：远程指导
  phase-4: singularity                  # 审核阶段：HPC计算
  phase-5: ssh                          # 应用阶段：远程协作
  phase-6: singularity                  # 修订阶段：影响分析计算
```

### 看板卡片新增字段

```yaml
# 原卡片基础上新增
backend: singularity          # 本任务指定的执行后端
backend_fallback: ssh         # 后端不可用时的降级方案
phase: 4                     # 当前阶段（用于后端自动切换）
```

---

> **设计原则：**  
> L4 就近（local）→ 低延迟个人创作  
> L3 标准（daytona）→ 一致化的审核环境  
> L2 算力（singularity/docker）→ 批量计算 + 跨学科分析  
> L1 安全（managed_modal）→ 最高安全等级的终审服务  
> 每个 Agent 可根据六阶段动态切换后端，实现「正确的工作在正确的环境运行」

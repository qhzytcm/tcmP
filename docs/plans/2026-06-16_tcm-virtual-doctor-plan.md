# 中医虚拟医生系统 — 架构与实施规划

> **本规划面向**: 从零搭建一个具备"四诊合参 + 辨证论治 + 处方推荐"能力的中医 AI 虚拟医生系统

**目标**: 构建一个以 LLM + RAG 为核心、融合中医知识图谱和多模态输入的虚拟医生助手，实现症状采集 → 辨证分型 → 治则治法 → 方药/针灸推荐的完整诊疗闭环。

**架构风格**: 模块化微服务 (FastAPI)，核心推理层用 LangChain/LlamaIndex 编排，知识层用向量库 + 图数据库双引擎。

**技术栈建议**: Python 3.11+ / FastAPI / LangChain / Neo4j (知识图谱) / Milvus (向量库) / PostgreSQL (业务数据) / Whisper (语音输入) / YOLO+ViT (舌诊图像分析)

## 二、核心功能模块

### 模块 1：四诊信息采集 (Four Diagnostic Methods)

| 诊法 | 实现方式 | 技术选型 |
|------|---------|---------|
| **望诊** (观察) | 舌象图片分析、面色分析、形体姿态 | YOLOv8 舌体分割 + ViT 舌象分类 (舌色/苔色/舌形/苔质) |
| **闻诊** (听嗅) | 语音语调分析 (目前难实现气味) | Whisper 转录 + 声学特征提取 (音色/语速/气息) |
| **问诊** (询问) | 结构化问卷 + 自由对话，按十问歌流程 | LLM 驱动的对话式信息采集 |
| **切诊** (触诊) | 脉搏传感器 (硬件) 或用户自述 (软件) | IoT 设备对接 (远期) / 问卷降级 |

### 模块 2：症状规范化

- NLP 将口语化症状映射到**中医症状标准术语** (参考 GB/T 16751 或 SNOMED-CT TCM 扩展)
- 症状属性结构化: 部位/性质/程度/持续时间/加重缓解因素

### 模块 3：辨证论治引擎 (核心)

**3.1 八纲辨证** — 表里/寒热/虚实/阴阳

**3.2 脏腑辨证** — 心/肝/脾/肺/肾定位

**3.3 六经/卫气营血/三焦辨证** — 外感病路径

**3.4 推理策略**:
```
症状集合 → 知识图谱检索候选证型 → LLM+RAG 证型排序与鉴别 → 确定主证+兼证
```

### 模块 4：治疗方案生成

- **方剂推荐**: 基于证型 → 经典方 + 加减化裁建议
- **中药配伍**: 君臣佐使结构，剂量建议，禁忌检查
- **针灸方案**: 主穴+配穴，补泻手法建议
- **食疗/养生**: 体质调养方案

### 模块 5：安全与合规

- ⚠️ **免责声明机制**: 始终标注"本系统仅供辅助参考，不替代执业医师诊断"
- 用药禁忌检查: 十八反/十九畏 / 妊娠禁忌 / 剂量上限
- 高风险症状自动分诊: 急重症 → 建议立即就医

## 三、知识库建设

### 3.1 需要构建的数据集

| 知识类型 | 数据来源 | 存储方式 | 预估规模 |
|---------|---------|---------|---------|
| 中医经典文献 | 黄帝内经/伤寒论/金匮要略/温病条辨等 | 向量库 (RAG) | 10万+ 段落 |
| 中药数据库 | 中国药典 2020 | 图数据库 + 结构化表 | 600+ 味 |
| 方剂数据库 | 中医方剂大辞典 | 图数据库 + 向量库 | 10万+ 首 |
| 证型数据库 | 国家标准 + 教材 | 图数据库 | 300+ 证型 |
| 症状-证型映射 | 教材 + 临床路径 | 图数据库关系 | 5000+ 映射 |
| 医案数据库 | 名老中医医案 | 向量库 | 1万+ 案 |
| 针灸穴位 | 经络腧穴学 | 结构化 + 图 | 361 经穴 |

### 3.2 知识图谱 Schema (核心)

```
(症状)-[:BELONGS_TO]->(证型)
(证型)-[:TREATED_BY]->(方剂)
(方剂)-[:CONTAINS]->(中药)
(中药)-[:HAS_PROPERTY]->(性味归经)
(中药)-[:CONTRAINDICATED_WITH]->(中药)   // 十八反十九畏
(证型)-[:DIFFERENTIATE_FROM]->(证型)     // 鉴别诊断
(穴位)-[:BELONGS_TO]->(经络)
(证型)-[:ACUPOINTS]->(穴位)
```

## 五、关键技术决策

### 5.1 LLM 选型策略

| 场景 | 推荐模型 | 原因 |
|------|---------|------|
| 问诊对话 | Claude / GPT-4 / DeepSeek | 需要长上下文、温和表达、追问能力 |
| 辨证推理 | DeepSeek / Qwen | 中文中医语料丰富，推理能力强 |
| 处方生成 | 微调后的专用模型 | 需要严格遵循配伍规则 |
| 舌象分类 | ViT / ConvNeXt 微调 | 视觉任务专用 |

### 5.2 RAG vs 微调

- **RAG 优先**: 知识可更新、可追溯来源、幻觉可检测
- **微调补充**: 对辨证推理链路做 SFT 微调，提升辨证准确率
- **关键**: 处方生成环节必须可溯源到经典方剂原文

### 5.3 评估指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 辨证准确率 | 与专家标注一致的比例 | > 85% |
| 方剂推荐合理率 | 中医专家盲审合理比例 | > 80% |
| 禁忌检出率 | 十八反/十九畏/剂量超标召回率 | > 99% |
| 用户满意度 | NPS 评分 | > 60 |

## 六、风险与应对

| 风险 | 等级 | 应对策略 |
|------|------|---------|
| LLM 幻觉导致错误处方 | 🔴 高 | 处方生成必须走检索+验证双轨，所有方药需在药典中可查 |
| 中医知识标准化困难 | 🟡 中 | 以教材 + 药典为权威来源，争议内容加注 |
| 舌象图像质量差异大 | 🟡 中 | 采集前给予标准化指引，模型做光照/角度增强 |
| 医疗合规与监管 | 🔴 高 | 始终定位"辅助工具"，标注免责声明，咨询法律顾问 |
| 数据版权与隐私 | 🟡 中 | 用户数据加密存储，古籍数据注意版本版权 |

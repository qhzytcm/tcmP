# 技能体系整合方案（草案 · 2026-09-05）

> 目的：压缩每次会话的 context 加载量、消除重复技能、沉淀平台运维知识。
> 现状：全局技能 ~130 个，其中**看板类 5 个高度重叠、视频课程类 8 个分散重叠**。

## 一、看板类技能（5 → 1 伞技能 + 1 巡检变体）

| 技能 | 位置 | 大小 | 处置 |
|---|---|---|---|
| kanban-board-operations | devops/ | 5.5KB | 🔀 并入伞技能 |
| kanban-board-ops | devops/ | 7.1KB | 🔀 并入伞技能 |
| kanban-board-triage | devops/ | 6.0KB | 🔀 并入伞技能 |
| hermes-kanban-operations | software-development/ | 7.4KB | 📌 **保留为伞技能**（描述最全） |
| kanban-cron-inspection | devops/ | 22.2KB | ✂️ 拆：cron 巡检专节并入伞技能 references；本体删 |

**合并理由**：四者语义完全重叠（blocked 三态判定、review-required 断点、kanban show 事件流优先、跨 profile 技能补装、PowerShell 坑），每次会话若加载多个将浪费 context。

## 三、textbook 系列（120 门教材主线，部分重叠）

现有 20+ 个 textbook-* 技能（textbook-workflow 62.9KB 为伞）。待架构快照完成后二次评估，原则：
- 功能型技能（审核/质量标准/图表管线）保留但瘦身，详细内容 references 化
- 同一流水线多代技能（textbook-*-pipeline 系）按「目录驱动→正文→图表→三审→出版」收拢

## 四、执行步骤（待用户拍板后）

1. `skill_manage(action='create')` 建伞技能（hermes-kanban-operations 扩充吸收三兄弟内容）
2. `skill_manage(action='delete', absorbed_into='hermes-kanban-operations')` 删除被并技能
3. 视频类同理
4. 验收：`skills_list` 复核；触发场景回归（模拟 blocked 卡诊断）

## 五、预期收益

- kanban 场景技能加载：5 → 1（-80%）
- 视频课程场景：6 → 2（-67%）
- 每次会话 skills 注入量显著下降 → context 占用降低

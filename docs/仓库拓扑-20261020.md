# 仓库拓扑与推送约定（2026-10-20 定案 · 方案 A）

> 结论：**一个 GitHub 仓 `qhzytcm/tcmP`，两条互不相干的历史分支**——
> 代码走 `master`，教材内容走 `textbook`。两套历史无共同祖先，**不做合并**（避免 subtree 重写）。

## 一、拓扑

```
                        GitHub  qhzytcm/tcmP
                        ├── master      ← 平台代码（本仓 ~/tcmP）
                        └── textbook    ← 教材内容（~/textbook-project）
                                   ↑↓ 同步
                    华为云镜像  114.115.211.254:/root/tcmP-mirror.git
                    （同时收 master 与 textbook 两条分支）
```

| 工作区 | 本机路径 | 对应分支 | 内容 |
|---|---|---|---|
| 代码仓 | `C:\Users\DELL\tcmP` | `master` | `kg/`（知识树/信息学/语义张量/器械）、`api/`、`constitution/`、`tests/`(122 项)、`scripts/`、`docs/`、`skills/`、`agents/` |
| 内容仓 | `C:\Users\DELL\textbook-project` | `textbook` | `domain-specs/`（DOMAIN_SPEC_D01~D08）、`subject-outlines/`、`drafts/`、`reviews/`、`feedback/`、`archive/`、`chapter-templates/` |

## 二、远端配置

**代码仓 `~/tcmP`**
```
origin  git@github.com:qhzytcm/tcmP.git            (fetch/push)
huawei  root@114.115.211.254:/root/tcmP-mirror.git
```

**内容仓 `~/textbook-project`**（2026-10-20 新增；本地分支名为 `master`，远端分支名为 `textbook`）
```
github  git@github.com:qhzytcm/tcmP.git            (fetch/push)
huawei  root@114.115.211.254:/root/tcmP-mirror.git
push refspec（已写入 local config，故无需每次写 master:textbook）:
  remote.github.push = refs/heads/master:refs/heads/textbook
  remote.huawei.push = refs/heads/master:refs/heads/textbook
```

> 为什么本地叫 `master`、远端叫 `textbook`：内容仓既有历史在 `master` 上，改名会牵动全部工具与脚本；用 refspec 映射即可，零侵入。

## 三、固定推送动作

```powershell
# 代码（master）
cd C:\Users\DELL\tcmP
git push origin master
git push huawei master

# 教材内容（本地 master → 远端 textbook）
cd C:\Users\DELL\textbook-project
git push github
git push huawei
```

拉取：
```powershell
cd C:\Users\DELL\tcmP;             git pull origin master
cd C:\Users\DELL\textbook-project;  git pull github master    # 首拉需显式写远端分支
```
新机器克隆内容分支：`git clone -b textbook git@github.com:qhzytcm/tcmP.git textbook-project`

## 五、决策记录

| 日期 | 决策 | 备选与否决理由 |
|---|---|---|
| 2026-10-20 | 采用 **方案 A：同仓双分支**（代码 `master` / 内容 `textbook`） | B（subtree 并入 master）：需重写目录结构、双仓同步改走 subtree push；C（独立仓）：多仓维护成本高。A 保留两套历史边界，内容可 clone/浏览/开 PR，改动成本最低 |

## 六、已知注意点

- **不要在内容仓直接 `git push github master`**：会把内容历史推到同名 `master` 分支并与代码历史冲突。永远走 `git push github`（refspec 已固定）。
- **不要在代码仓 `git merge textbook`**：两套历史无共同祖先，合并会产生大体积无关提交。
- 大体积媒体（mp4/wheel 等）两侧都用 `.gitignore` 拦截：内容仓忽略 `docs/视频/*.mp4` 等；代码仓忽略 `deps/ov/`（7.4 MB wheel）与含明文凭据的探针脚本。
- 凭据一律不入库；仓库内**已存在**的明文口令（`scripts/batch_suwen.py` 等）属历史遗留，待单独清理。
